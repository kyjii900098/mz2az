# 작업 로그·스프린트 문서 작성

## 1. 누구의 폴더인지부터 정한다

이 스킬은 팀원 셋 모두가 쓴다. **자기 폴더에만 쓰고 남의 폴더는 건드리지 않는다.**

1. `mcp__atlassian__atlassianUserInfo` 로 지금 로그인한 사람을 확인한다. 각자 자기
   계정으로 MCP 인증돼 있으므로 이것이 곧 호출자다.
2. `01_Raw/README.md` 의 "지라 계정 ↔ 폴더" 표로 폴더 이름을 찾는다. 지라 표시 이름과
   폴더 이름이 달라서 이 표를 거쳐야 한다.
3. MCP 인증이 끊겨 있으면 사용자에게 **누구인지 직접 묻는다.** 추측하지 않는다 —
   엉뚱한 사람 폴더에 쓰면 되돌리기 번거롭다.

## 2. 규칙을 읽는다

두 파일을 읽는다. 이 스킬 파일에는 규칙을 중복해 적지 않는다.

| 파일 | 무엇 |
| --- | --- |
| `01_Raw/README.md` | 공용 규칙 — 두 갈래, 이름 규칙, 로그 골격, 정정 방법, 글쓰기 |
| `01_Raw/{이름}/README.md` | 그 사람 폴더 배치와 예외 |

**개인 README 가 없으면 먼저 만든다.** `01_Raw/README.md` 의 "개인 README 를 처음
만들 때" 절에 템플릿이 있다. 폴더를 실제로 훑어보고 지금 있는 것을 적은 뒤, 공용 규칙과
다르게 두고 있는 것이 있으면 예외 칸에 이유와 함께 적는다. 사용자에게 확인받고 만든다.

볼트 루트 `CLAUDE.md` 의 "Writing for the reader" 도 적용된다.

## 3. 어디에 쓸지 정한다

사용자가 "로그 써줘" 라고만 해도, 실제로는 **셋 다 손봐야 하는 경우가 많다.**

| 성격 | 자리 |
| --- | --- |
| 오늘 한 일·막힌 것·배운 것 | `logs/NN_YYYY-MM-DD_제목.md` **새로 만든다** |
| 그 결과로 확정된 결론·스펙 | 주차 폴더의 해당 문서를 **고친다** |
| 이전 로그의 판단이 뒤집힘 | 그 로그에 **정정 콜아웃을 덧붙인다** (원문은 두고) |

새 로그를 쓰기 전에 `logs/` 를 훑어 **마지막 번호** 를 확인한다. 번호를 건너뛰거나
겹치지 않게 한다.

## 4. 쓰기 전에 확인한다

로그는 사실 기록이다. **추측을 사실처럼 쓰지 않는다.**

1. **커밋 해시·PR 번호·파일 경로·버전은 실제로 확인한다.** `git log`, `gh pr view`,
   파일 읽기로 검증한 값만 적는다.
2. **에러 메시지는 그대로 붙인다.** 요약하지 않는다 — 나중에 검색으로 찾는 것이 목적이다.
3. **남의 작업은 근거를 직접 읽고 쓴다.** 커밋 메시지·계약서·티켓 본문을 확인한다.
   전해 들은 것은 "…라고 들었다" 로 적고 확인 여부를 밝힌다.
4. **계약서·명세를 볼 때는 이름 목록만 훑지 않는다.** 파라미터가 무엇에 걸리는지
   설명문까지 읽는다. 목록만 보고 판단해 틀린 적이 있다.
5. 근거를 못 찾으면 **지어내지 말고** 사용자에게 묻는다.

## 5. 새 주차 폴더를 만들 때

1. 그 주 스프린트 회의록(`00_기록/Sprint(권호작성)/`)을 읽어 **그 주의 주제** 를 확인한다.
2. `N주차_주제/` 를 만든다. 주제는 회의에서 정해진 말을 쓴다.
3. 이전 주차 폴더에서 **아직 유효한 결론** 이 있으면 위키링크로 잇는다. 복사하지 않는다.

## 다른 스킬·저장소와의 관계

- 완료된 티켓의 산출물 정리는 `jiradocs` 스킬의 몫이다. **로그는 경위, JiraDocs 는
  결과물** 이다. 같은 작업이라도 문서가 다르다.
- 팀 회의록은 `meeting-notes` 스킬과 `00_기록/` 담당이다. 개인 폴더에 회의록을 만들지
  않는다.
- 지라 티켓 본문을 고치는 일은 사용자의 지시에 따른다. 로그에는 **무엇을 왜 고쳤는지** 를
  남긴다.
- 모노레포(`~/workspace/SceneTrip`)의 계획서·ADR 을 참조할 때는 파일 경로와 커밋 해시를
  함께 적는다. 저장소가 바뀌면 로그의 링크가 낡기 때문이다.
