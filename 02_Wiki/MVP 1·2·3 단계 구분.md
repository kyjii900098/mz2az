> [!summary] Data 축과 기능 축을 나눠 3단계로 쪼갠 것. MVP1은 드라마 데이터 + 마이코스까지.

### 상세 내용

박재범의 접근법(요약본):
> MVP 계획을 수립해서 전체적으로 프로젝트 마무리할 때 어느 마일스톤으로 갈 건지, 거기 들어가는 기능들은 뭐가 있는데 **뭘 MVP 1까지 하고 2까지 할 건지, 그다음에 데이터는 어떻게 할 건지 — 이 세 가지로 접근해서 갈래를 쳐야 함.**

**태블릿 스케치의 표**(IMG_0845, 판독 가능한 부분만)

| | MVP #1 | MVP #2 | MVP #3 ? |
| --- | --- | --- | --- |
| **Data** | 드라마 | 드라마 + POP | **?** |
| **기능** | … / **My Course** | … / **개인화 추천** | … |

MVP #3 열의 Data 칸은 물음표만 적혀 있다 — 이 시점에 정하지 않았다.

**정승길이 정리한 MVP1 범위**(`46_2026-07-24 로드맵`):
> **MVP1 범위**(박재범 로드맵 기준): 데이터 = 드라마만·자동생성 콘텐츠만 / 기능 = **앱 메인 + 장면 탐색 + 마이코스.**
> 커뮤니티·루트마켓·선호도 개인화·경로 최적화는 MVP2~3. LLM 플래너 어시스턴트는 차별화 포인트지만 MVP1 스트레치로.

**MVP1까지는 데이터를 우리가 직접 만든다**(현장 메모):
> 처음 MVP1까진 우리가 만들어놓는다. 일단은 OTT로 하고 넷플릭스, 웨이브라든지 몇 개 채널로 인기 있던 20개를 만든다. 그걸 에이전트로 이용해서 만들어서 올린다.
> 그게 완성됐을 때 서비스 참여 유도를 해야 하는데 — **크라우드소싱 비용을 걸고.**

즉 콜드스타트를 팀이 직접 돌파하고, 그 뒤에 크라우드소싱으로 넘긴다는 순서다. 정문창이 피봇팅 의견서에서 요구한 보완 2번과 같은 처방이다.
