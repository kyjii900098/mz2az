> [!summary] 8/3 스프린트 플래닝에서 실개발 착수를 결정했으나, 8/4 프론트 프레임워크가 다시 논의 테이블에 올랐다.

### 상세 내용

**8/3 회의(정승길·김태환·정권호 3인)에서 팀은 1주차의 기획·수집 단계를 끝내고 실제 개발에 들어가기로 확정했다.** 이번 주 목표는 목업 기반 프론트 + 검색·조회 API + 필터링 완료 데이터이며, 우선순위는 "일단은 프론트가 제일 중요하니까"라는 발언대로 프론트다.

**확정된 것** 은 다음과 같다. 데이터는 추가 수집 없이 현재 V4/V5를 필터링만 해서 V6로 확정한다. 프론트는 **Flutter(Dart)** 로 iOS·Android 양쪽을 대응하고, 지도는 **네이버 지도 SDK** 의 Flutter 포팅 패키지를 쓴다. 개발 환경은 **Docker + Docker Compose** 로 팀 전원을 통일하고, 나중에 쿠버네티스로 옮길 것을 감안해 지금부터 컨테이너로 시작한다. 이미지는 최종적으로 Amazon S3에 저장하되 앱은 **링크 방식** 으로 받아 표시하며, 이 흐름은 로컬 개발 단계부터 그대로 적용한다. **Kafka는 쓰지 않는다** — 대용량 실시간 스트림이 필요한 서비스가 아니기 때문이다. 검색 자동완성은 입력 언어를 영어로 하고, DB 조회는 단순 단어 매칭으로 처리한다(RAG는 이후 AI 기능 단계에서 도입). 역할 분담은 정승길이 프론트, 정권호가 백엔드(DB 구축·API 명세·Docker 구성), 김태환이 데이터·AI 사전 조사(수집 방식 다변화, 챗봇 조사, 자막 기반 장면 위치 추출 가능성 조사)를 맡는다.

**그런데 8/4 팀회의 기록에는 다른 내용이 나온다.** 김태환의 기록에 따르면 이날 "플루터를 버리는 것에 대한 논의"가 있었다 — Bazel(멘토가 제공한 저장소 뼈대에 포함된 빌드 도구)을 통해 Flutter를 쓰는 것이 번거롭다는 의견이 나왔고, "IOS 어플을 우선적으로 개발하자고 의견이 좁혀짐"이라고 적혀 있다.

> [!question] 확인 필요 — 8/3에 Flutter(Dart)로 확정했던 프론트 프레임워크가 8/4에 다시 논의되어 iOS 우선으로 의견이 모였다는 기록만 있고, 이것이 팀의 최종 결론인지는 이 시점 기록만으로 확인되지 않는다. 실제로 정승길의 같은 날짜(8/3~8/4 새벽 세션) 작업 로그에는 Flutter 프로젝트를 생성하고 iOS 시뮬레이터로 검색 탭까지 구현한 기록이 남아 있어([[MVP1 프론트 테크 스펙]] 참조), 8/4 재논의가 실제 작업 방향을 바꿨는지는 후속 기록으로 확인이 필요하다.

미결로 남은 항목도 있다. 하네스(harness, 개발 과정을 표준화·자동화하는 도구/프레임워크)를 도입하기로 했으나 어떤 것을 쓸지는 미정이고, 지도가 한국 밖으로 벗어났을 때의 처리 방식도 8/3 회의에서 결정하지 못했다.
