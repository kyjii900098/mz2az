> [!summary] 김태환이 정리한 도커→쿠버네티스→kind→Helm→SigNoz 학습 경로와 8/4 설치 완료 기록.

### 상세 내용

김태환이 SceneTrip 로컬 개발환경 설치 가이드(`docs/installs/`)가 "어떻게 하는가"만 알려주고 "그게 뭔가"는 설명하지 않는다는 문제의식에서, 인프라 개념 6편을 순서대로 작성했다. 각 도구가 **앞 도구가 만든 새 문제를 푸는** 구조로 이어진다 — 환경이 사람마다 달라 안 돌아가는 문제는 컨테이너(Docker)가, 컨테이너가 여러 개라 관리가 안 되는 문제는 쿠버네티스가, 쿠버네티스를 맥에 띄우는 문제는 kind(Kubernetes in Docker, 쿠버네티스 노드를 도커 컨테이너로 흉내 내는 도구)가, 설치가 복잡한 문제는 Helm(쿠버네티스의 패키지 매니저)이, 장애 원인을 모르는 문제는 SigNoz(로그·메트릭·트레이스를 모아 보여주는 관측성 도구)가 푼다.

**SceneTrip은 클러스터 이름 "scenetrip" 안에 네임스페이스(클러스터를 논리적으로 나누는 구획) 2개를 둔다** — 우리 서비스가 도는 `scenetrip`과 관측성 도구가 도는 `signoz`다. 설치는 `just cluster-up` 한 번으로 끝나며, 이 명령은 **멱등**(몇 번을 실행해도 결과가 같음)이라 이미 있으면 건너뛴다.

**`kind load` 누락이 가장 흔한 실수이자 가장 위험한 실수다.** kind 노드는 맥의 Docker 이미지 저장소와 별도의 저장소를 쓰기 때문에, `docker build`만 하고 `kind load`를 빼먹으면 노드가 옛 이미지를 그대로 쓴다. 문제는 이미지가 아예 없으면 오류(`ErrImageNeverPull`)가 나서 금방 알아채지만, **한 번 적재한 뒤 코드만 고쳐 다시 빌드하면 오류 없이 조용히 옛 코드가 계속 도는 무음 실패(silent failure)** 가 된다는 점이다. SceneTrip은 이 위험을 `just image`·`just update` 레시피로 감싸 손으로 하지 않게 했다.

**Apple Silicon(arm64) 빌드가 EKS(amd64)에서 죽는 함정도 있다.** 맥북(arm64 아키텍처)에서 빌드하면 arm64 이미지가 나오는데, AWS EKS(운영 환경) 노드가 amd64면 로컬에서는 되는데 EKS에서만 죽는다. `--platform` 옵션을 지정해 빌드해야 한다.

**8/4에 로컬 개발환경 설치를 완료했다.** 설치 기록에 따르면 Docker Desktop 4.85.0, kind 0.32.0, kubectl 1.36.3, Helm 4.2.3, k9s 0.51.0, AWS CLI 2.36.15, just 1.58.0, SigNoz 차트 0.135.1(localhost:8080)을 깔았다. 같은 날 팀회의에서는 쿠버네티스 환경 설정과 함께 AIDLC 같은 하네스(harness, 개발 과정을 표준화·자동화하는 도구) 적용도 논의됐다.
