> [!summary] "지도만 뜨면 사용자가 뭘 해야 할지 모른다" — 첫 화면이 지도에서 콘텐츠 목록으로 뒤집혔다.

### 상세 내용

정승길이 `46_2026-07-24 로드맵` 에 정리한 전환 근거:

> **IA(정보구조)가 뒤집힘**: 기존 목업은 **지도-first**(첫 화면 = 지도 + 핀). 박재범 멘토님 지적은 **"지도만 뜨면 사용자가 뭘 해야 할지 모른다"** → **콘텐츠-first** 로 재설계 필요:
>
> `카테고리(드라마) → 작품 목록 → 장면 리스트 → 장면 상세(담기) → 마이코스 편집 = 나만의 코스`
>
> (선호도 조사는 MVP1에서 부차적 → 후순위. **탐색과 플랜은 별개 단계.**)

**같은 고민이 이미 07-06에 있었다.** 팀 내부 메모(`37_(07.06)`):
> 첫 화면에 지도가 바로 뜬다? 검색창.
> 콘텐츠 첫 화면 → 케데헌 선택 → 간단한 설명(콘텐츠), 장소 목록 → 더보기 눌릴 시 → **지도와 함께 핀들이 뜨고**, 핀 클릭 시 해당 이미지·정보도 같이 나온다.
> 그냥 지도만 봤을 때, 해당 핀 클릭 시 관련 콘텐츠 다 표시.

즉 팀은 이미 두 방향을 저울질하고 있었고, 박재범의 지적이 **콘텐츠-first 쪽으로 결론을 내려준 셈** 이다.

**함의가 크다.** 지도가 "핵심 기능"([[지도는 누가 만드느냐가 품질을 가른다]])에서 **"콘텐츠 탐색의 결과를 보여주는 뷰"** 로 위상이 바뀐다. 최종 목업의 하단 탭 순서가 `작품검색 · 지도 · 지금 근처 · 커뮤니티` 로 작품검색이 첫 번째인 것이 이 결정의 반영이다.

같은 로드맵에 함께 적힌 다른 전환들:
- **스택 불일치** — 기존 산출물은 React 웹(`SceneTrip Standalone.html`, 7/7)인데 확정 스택은 Flutter. "Standalone.html은 화면 레퍼런스로만 쓰고 실제 개발은 Flutter로 새로 시작"
- **다국어는 처음부터** — "나중에 붙이면 대공사". 로케일(EN 우선) 코드가 데이터 모델·화면 메시지에 처음부터
