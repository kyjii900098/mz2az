> [!summary] 목업 화면 하나하나에 번호를 달고 그 뒤에 돌아야 할 AI 모듈을 매핑한 것. 김태환의 담당 범위 전체.

### 상세 내용

| 코드 | 모듈 |
| --- | --- |
| **M1** | 데이터 수집·추출 |
| **M2** | RAG·검색 |
| **M3** | 실시간 Agent |
| **M4** | 추천 |
| **M5** | 경로 생성 |
| **M6** | 다국어 |
| **권한** | 티어·운영 |

**화면별 매핑 (요지)**

- **작품검색 탭** — 지도 핀(M1 수집·지오코딩 + PostGIS 지리검색) / 검색창(**M2 임베딩 기반 시맨틱 검색** — "재벌 드라마", 배우명, 오타까지) / 인기 리스트(M4 랭킹) / 작품 요약(M6 다국어 + M2 RAG) / 성지 리스트 씬 태그(M1 추출)
- **경로여정 탭** — 경로 동선(**M5 Itinerary Planning, TSP 근사** + Route API 실측) / 경로마켓(M4) / 여정 빌더(M5 검증) / **AI 가이드 챗봇(M3 Location-aware Agent** — `search_spots`·`get_route`·`rag_lookup` 도구 호출) / 무료 질문 카운터(권한 게이팅) / **근거 카드(M2 RAG citation)** / 퀵리플라이(M3)
- **커뮤니티 탭** — 게시글 자동 태깅(경량 LLM) + **팬 글에서 새 성지 후보 발굴해 M1으로 환류** / 후기 속 경로 파싱(M5) / 시맨틱 검색(M2)
- **마이페이지 탭** — 패스권(권한 → 차등 RAG) / 판매 경로 통계(M4 분석) / **언어 설정이 M6 파이프라인의 스위치**

**커뮤니티에 대한 관점이 특이하다**
> 커뮤니티는 AI가 **소비만 하는 게 아니라 데이터를 공급받는** 곳 — 팬들이 올린 새 촬영지·후기가 M1 수집 파이프라인의 신선한 소스가 됩니다.

즉 크라우드소싱이 별도 기능이 아니라 **M1의 입력 채널** 로 설계돼 있다.

**화면 흐름 상의 위치**(`플로우차트_화면흐름`) — 하단 4개 탭이 4개 진입점이고, **모든 여정이 ⑤ AI 가이드 챗봇으로 수렴** 한다. 문서는 챗봇을 "핵심 · 제품의 심장"이라 표기했다.

> [!question] 확인 필요
> 플로우차트가 참고하라고 지목한 **`AI개발_시작가이드`** 문서가 볼트 어디에도 없다.
