> [!summary] 같은 질문이라도 무료 유저와 패스 유저에게 다른 답이 나간다 — 차이는 RAG 검색 범위에서 갈린다.

### 상세 내용

**어떻게 작동하나**(아키텍처 문서 Flow 2):

| STEP | 주체 | 내용 |
| --- | --- | --- |
| 1 | Frontend | 질문 + 현재 위치·활성 경로 전송 |
| 2 | Backend | **Entitlement 판정** — tier·허용 work/route id를 붙여 AI에 전달 |
| 3 | AI | Agent가 의도 파악 → 도구 호출 결정 |
| 4 | AI | RAG — **권한 필터로 허용 청크만 벡터 검색** |
| 5 | Route API | `get_route` 로 실측 동선 계산 |
| 6 | Frontend | 근거 포함 답변 + 지도 갱신 |

> 같은 질문이라도 **무료 유저** 는 요약형 답변 + 구매 유도, **해당 경로 구매/패스** 유저는 상세 씬·팁까지 — 차이는 STEP 4의 **RAG 검색 범위(권한 필터)** 에서 갈립니다.

**왜 영리한가.** 보통 유료화는 기능을 잠그는 방식(버튼 비활성화)인데, 이 설계는 **AI가 볼 수 있는 데이터 범위를 조절** 한다. 그래서
- 무료 유저도 답을 받긴 받는다(이탈이 덜하다)
- 유료 가치가 "더 정확하고 깊은 답"이라는 형태로 체감된다
- 게이팅 로직이 Backend 한 곳에 모인다(AI는 판단하지 않는다)

**목업에 이미 구현돼 있다** — `무료 AI 가이드 질문: 3 / 5회 남음` + `무제한 →`, 그리고 `3-Day Pass $14.99` 의 혜택이 "AI 가이드 채팅 무제한 해제".

**M1~M6 도식의 정리**:
> 이 **Entitlement가 AI 차등의 기준**. Backend가 판정한 tier·허용 경로를 AI에 넘겨 **RAG 검색범위·답변깊이·도구 권한** 을 결정. (AI 담당: 티어별 정책·프롬프트·필터 구현)
