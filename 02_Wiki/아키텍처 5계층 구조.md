> [!summary] Frontend → Backend → AI Service → Data → External. "Frontend는 보여주고, Backend는 지키고, AI Service는 생각한다."

### 상세 내용

김태환이 만든 `아키텍처_연결도_김태환.html` 의 구조도다. 이미지 없이 CSS 박스와 텍스트로만 그려져 있다.

**계층별 구성**

- **FRONTEND · Flutter 앱** (iOS/Android/Web) — 지도 화면 / 작품검색 / AI 가이드 챗봇 / 경로여정·커뮤니티
- ↓ `REST / HTTPS (JSON)`, `위치 스트림 · 인증 토큰`
- **BACKEND · SpringBoot** (비즈니스 로직 · **신뢰 경계**) — API Gateway·인증 / **Entitlement(권한)** / 결제·패스 관리 / CRUD
- ↓ `내부 API`, `요청 + 권한 컨텍스트(tier, 허용 work/route id)`
- **AI SERVICE · Python / LangChain** — Location-aware Agent / RAG Engine / 추천·경로 엔진 / 수집·추출 파이프라인
- ↓ `SQL · 지리쿼리 · 벡터검색`
- **DATA** — PostgreSQL + PostGIS / pgvector / 원문·출처 저장소
- ↓ `외부 API 호출`
- **EXTERNAL** — Map/Route API / Geocoding API / LLM Providers(Claude·Gemini·QWen) / 콘텐츠 소스(YouTube·블로그·SNS)

**Backend가 "신뢰 경계"인 이유** — Entitlement 판정이 여기서 일어나고, 그 결과(tier·허용 work/route id)를 권한 컨텍스트로 AI Service에 넘긴다. AI는 스스로 권한을 판단하지 않는다. → [[권한 기반 차등 RAG]]

**데이터 흐름 3종이 문서에 명시돼 있다**
1. **촬영지 검색 → 지도 핀** — AI가 관여하지 않는 빠른 조회 경로. "지도는 Frontend가 그리고, 핀 좌표는 PostGIS에서"
2. **실시간 AI 가이드 질문** — RAG + 권한 + 지도가 한 번에 맞물리는 핵심 흐름
3. **성지 데이터 자동 구축(배치)** — 수집 → LLM 추출 → Geocoding → **HITL 사람 검수** → PostGIS 적재 + pgvector 인덱싱. "실시간 흐름과 분리해 앱 응답 지연을 없앰"

**한 줄 정리**(원문):
> Frontend는 **보여주고(지도·챗봇)**, Backend는 **지키고(인증·결제·권한)**, AI Service는 **생각합니다(RAG·Agent·추출)**.
