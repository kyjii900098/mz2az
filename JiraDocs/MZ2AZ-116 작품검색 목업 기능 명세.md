## 1. 전체 구조

```
하단 탭 (4)
├─ 작품검색 (search)   ← 이 문서의 주 대상
│   ├─ 지도 레이어 (핀 · 내 위치 · 포커스 애니메이션)
│   └─ 바텀시트 (3단 스냅: 132 / 430 / 640 px)
│       ├─ view=list  · tab=works   작품 목록
│       ├─ view=list  · tab=places  장소 목록
│       ├─ view=work                작품 상세
│       └─ view=place               촬영지 상세
├─ 경로여정 (route)      타임라인 동선 + 루트 마켓 + AI 가이드 채팅
├─ 커뮤니티 (community)  후기 / 동행 모집 / 제보·검증
└─ 마이페이지 (mypage)   프로필 · 저장한 장소 · 내 루트 · 설정

오버레이 (전역)
├─ 장면 팝업 (sceneKey)
├─ AI 가이드 채팅 (chatOpen)
├─ 장바구니 시트 (cartOpen)
└─ 토스트 (toast)
```

## 2. 작품검색 탭 — 기능 명세

### 2.1 검색바 · 탭 전환

| 요소 | 동작 |
| --- | --- |
| 검색 입력 | 실시간 필터링(디바운스 없음). placeholder가 탭에 따라 바뀜 — 작품 탭 `작품, 배우, 장면 검색` / 장소 탭 `장소, 지역, 골목 검색` |
| 필터 버튼(슬라이더 아이콘) | 현재는 **검색어 + 카테고리 초기화** 로만 동작 |
| 작품 / 장소 토글 | 전환 시 검색어·상세뷰·근처검색 상태를 모두 리셋 |

**작품 탭 검색 대상** — 작품 제목, 그 작품의 촬영지 이름
**장소 탭 검색 대상** — 장소명, 카테고리, 그 장소의 장면 제목, 장면이 속한 작품 제목

> placeholder는 `배우 검색` 을 안내하지만 목업 필터는 배우를 보지 않는다. 실제 구현에서는 `search_term`(`entity_type='person'`) 이 이를 담당한다.

### 2.2 지도 레이어

**핀 표시 규칙** — 상태별로 다르다.

| 상태 | 표시되는 핀 |
| --- | --- |
| 검색 전(검색어 없음) | 없음 |
| 작품 탭 + 검색어 | 검색 결과 작품들의 모든 촬영지 |
| 장소 탭 + 검색어 | 검색 결과 장소들 |
| 근처 검색 ON | 반경 5km 내 장소 |
| 작품 상세 | 해당 작품의 촬영지 — **번호가 촬영 순서** |
| 촬영지 상세 | 작품 경유 진입이면 작품의 전체 촬영지, 아니면 해당 장소 1개 |

- **포커스 애니메이션** — 작품 상세 진입 시 촬영지들의 중심점으로 `scale 1.35`, 촬영지 상세 진입 시 해당 핀으로 `scale 2.1` (0.6s cubic-bezier)
- **선택 핀** 은 30px · `#C4442F` · 외곽 글로우로 구분 (비선택 24px · `#17130F`)
- **내 위치** 는 초록 점 + 펄스 애니메이션 고정

### 2.3 현 지도 내 성지 검색

- 라벨: `현 지도 내 성지 검색` ↔ (활성) `검색 결과 N곳 · 해제`
- 반경 **5km** 이내를 거리순 정렬해 장소 탭 목록으로 전환
- 바텀시트가 올라와 잔여 지도 높이가 `≤ 246px` 이면 버튼이 fade-out + 포인터 차단. 지도 컨트롤(내 위치·북마크)은 `≤ 306px` 기준으로 별도 fade

### 2.4 바텀시트

- **스냅** — `132px`(지도 위주) / `430px`(기본) / `640px`(목록 위주)
- 드래그(pointer, 110~700px) → 놓으면 최근접 스냅으로 흡착
- 핸들 **탭** 은 3단 순환. 4px 이상 이동한 드래그는 탭으로 오인하지 않음
- 힌트가 높이에 따라 바뀜: `위로 끌어올려 목록 보기` / `끌어서 지도 / 목록 조절` / `아래로 내려 지도 보기`

### 2.5 작품 목록 → 작품 상세

작품 카드 — 포스터 · 제목 · `방송사 · 연도 · 장르` · **촬영지 N곳** · **루트 N개** · 대표 지역

작품 상세 —
- 포스터, 제목, 메타, 줄거리
- 지표 3종: **촬영지 수 / 등록 장면 수 / 루트 수**
- **촬영 장소 리스트** — 번호가 지도 핀과 연동. 각 행에 그 작품의 대표 장면명 + 거리 + `+`(장바구니)

### 2.6 장소 목록 → 촬영지 상세

장소 카드 — 썸네일 · 장소명 · **이 장소에 등장한 작품들** · `카테고리 · 거리 · 장면 N개` · `+`
카테고리 칩 — `전체 / 거리·골목 / 랜드마크 / 카페·식당 / 상점·서점 / 자연`

촬영지 상세 구성:

1. 대표 이미지 + **검수 완료** 배지 + **신뢰도 %** 배지
2. 장소명 / `카테고리 · 현재 위치에서 N km`
3. **장바구니에 저장** (저장 시 `저장됨` 토글) + 루트 아이콘 → 경로여정 탭 AI 채팅으로 이동
4. **이 장소의 장면** — 가로 스크롤 카드. `N개 작품이 이곳에서 촬영`. 탭 → 장면 팝업
5. **팩트 블록** — 주소 / 운영 시간 / 가는 방법
6. **촬영 앵글 팁** — 방문자용 촬영 가이드
7. **이어서 걷기 좋은 곳** — 인접 촬영지 3곳

### 2.7 장면 팝업 (핵심 차별 요소)

| 항목 | 예시 |
| --- | --- |
| 작품 배지 | `이태원 클라쓰` |
| 장면 제목 | `단밤 포차가 있던 골목` |
| 회차·타임코드 | `2화 34분` |
| 장면 설명 | 촬영 지점 + 현재 상태 + 방문 시 재현 방법 |
| **이 장면의 대사** | `여기서 다시 시작하는 거야.` |
| 액션 | 공식 클립 보기(YouTube) · 장바구니 저장 |
| 출처 표기 | `출처 제작사 공개 로케이션 · 사용자 제보 24건 검수 반영` |

### 2.8 장바구니 → 루트 생성

- 담기 경로 3개: 장소 카드 `+`, 상세 저장 버튼, 장면 팝업 북마크
- 중복 시 토스트 `이미 저장된 장소입니다`
- 시트에 순번·장소명·**대표 작품**·거리 표시, 예상 소요 = `저장 수 × 1.2시간`
- `담은 장소로 루트 만들기` → 경로여정 탭 전환 + 자동 동선 생성. 비어 있으면 `먼저 장소를 저장해 주세요`

## 3. 나머지 탭 (작품검색과의 연결점 위주)

**경로여정** — 진행 중인 루트(장바구니 기반 자동 생성) · 남은 장소/예상 소요/도보 구간. **오늘의 동선** 타임라인(시각, 장면명, 이동 수단·소요). **루트 마켓** — 팬 제작 동선(`₩4,900` / `무료 공식`, `showPrices` prop 으로 가격 노출 토글). **AI 가이드 채팅** — 키워드 룰 응답 목업(`맛집/밥` · `다음` · `교통/어떻게` 3분기 + 기본), 퀵 버튼 3개, 컨텍스트 헤더 `위치 인식 중 · {저장 1순위 장소} 부근`.

**커뮤니티** — `여행 후기` / `동행 모집` / `제보·검증` 3탭. 제보 탭에 `검수 대기` / `검수 완료` 태그 — §2.6 신뢰도·검수 배지와 같은 파이프라인.

**마이페이지** — 저장한 장소 수 / 방문 기록 / 만든 루트 수, 내 루트(공개·임시저장), 최근 본 장소 · 내 제보 검수 현황 · 여행 패스 · 다국어(한국어/English/日本語).

## 4. 목업 내부 데이터 모델

```
Work   id, title, meta(방송사·연도·장르), region, routes, desc
Place  id, name, cat, dist, top/left(지도 %좌표), trust, addr, hours, move, tip
Scene  place_id, work_id, title, ep, desc, quote, source, reports
```

관계는 **Place 1:N Scene N:1 Work** — 한 장소에 여러 작품의 장면이 공존한다(남산 소월로 육교 = `이태원 클라쓰`·`도깨비`·`케이팝 데몬 헌터스` 3개 장면).

수록량: 작품 4편 / 촬영지 10곳 / 장면 15건.

## 5. DB 스키마 대비 갭 분석 → MZ2AZ-121 리뷰 입력

[[SceneTrip DB 스키마]] (테이블 14 + MV 1) 기준 대조다. 수집 CSV 15컬럼([[MZ2AZ-111 촬영지 데이터 수집용 스키마]])이 아니라 **적재 후 DB 구조** 를 기준으로 본다.

### 5.1 이미 스키마가 커버하는 것

| 목업 요소 | 대응 |
| --- | --- |
| 작품 제목 · 검색 | `content_i18n.title` · `content_alias` · `search_term` |
| 작품 카테고리 | `content.category` |
| 방송사 (`tvN`) | `content.broadcaster` |
| 포스터 | `content.poster_url` |
| 작품 줄거리 | `content_i18n.description` |
| 배우 검색 | `person_i18n` · `content_cast` · `search_term(entity_type='person')` |
| 장소명 · 주소 | `place_i18n.name` / `.address` |
| 지도 핀 좌표 | `place.geom` (GEOGRAPHY 4326) |
| 반경 5km 검색 | `place.geom` GiST 인덱스 |
| 장소 카테고리 칩 | `place.type` |
| 장소 대표 이미지 · 추가 사진 | `place_image` + `sort_order` |
| 장소 자체 설명 | `place_i18n.description` |
| 장면 설명 | `place_content_i18n.relation_description` |
| `지금 뜨는 작품` 정렬 | `content.popularity_score` |
| 줌아웃 시 핀 솎아내기 | `place.popularity_score` |
| 다국어 (한/영/일) | `*_i18n` 4개 언어 |
| 장바구니(찜) | `saved_place` (MVP2) |
| 장바구니 행의 **대표 작품** 표시 | `saved_place.source_content_id` — 저장 이유를 남긴 설계가 이 화면과 정확히 맞물린다 |

### 5.2 스키마에 없는 것 — 신설/결정 필요

| # | 목업 요소 | 화면 | 제안 |
| --- | --- | --- | --- |
| 1 | **연도** (`2024`) | 작품 카드 · 상세 메타 | `content.release_year INT` |
| 2 | **장르** (`로맨스`, `판타지 멜로`) | 작품 카드 · 상세 메타 | `content.genre` — `category`(drama/movie/…)와 별개 |
| 3 | **작품 대표 지역** (`서울·경기`) | 작품 카드 | `place_content` 집계 파생값. 캐시 컬럼 여부 결정 |
| 4 | **장면 제목** (`단밤 포차가 있던 골목`) | 장면 카드 · 팝업 · 촬영 장소 리스트 | `place_content_i18n.relation_title` |
| 5 | **회차·타임코드** (`2화 34분`) | 장면 카드 · 팝업 | `place_content.episode_no INT` + `.timecode` — `"2화"` 는 한국어라 언어중립 분해 필요 |
| 6 | **명대사** | 장면 팝업 **핵심 차별 요소** | `place_content_i18n.quote` — **저작권 논점(§5.3-4)** |
| 7 | **공식 클립 URL** | 장면 팝업 CTA | `place_content.clip_url` |
| 8 | **촬영 앵글 팁** | 촬영지 상세 | `place_i18n.photo_tip` (목업은 장소 단위) |
| 9 | **운영 시간** | 촬영지 상세 팩트 블록 | 공공데이터 `영업시간` 이 소스. 스키마는 **MVP1 범위 밖** 으로 잡았으나 목업은 3칸 중 1칸으로 노출 |
| 10 | **가는 방법** (`6호선 녹사평역 2번 출구 도보 5분`) | 촬영지 상세 팩트 블록 | `place_i18n.transit` — **수집 소스 없음.** 생성 방법부터 결정 필요 |
| 11 | **신뢰도 % · 검수 상태 · 제보 건수** | 상세 배지 · 장면 팝업 · 커뮤니티 제보 탭 | 대응 테이블 없음 |
| 12 | **루트** (`루트 N개`, 루트 마켓, 내 루트, 타임라인) | 작품 카드 지표 · 경로여정 탭 전체 · 마이페이지 | `route` / `route_stop` 테이블 없음 |
| 13 | **장면 스틸** | 장면 카드·팝업 이미지 | 스키마에 `scene_image` **미결정 메모** 로 존재 — 목업이 요구하므로 결정 대상 |
| 14 | **커뮤니티 게시글** | 커뮤니티 탭 전체 | `post` / `review` / `review_image` 테이블 없음 (`review_image` 는 `place_image` 절에 언급만) |
| 15 | **방문 기록** (`12`) | 마이페이지 지표 | `user_event(event_type='view')` 집계로 가능하나 MVP2 |

### 5.3 구조 논점 — 리뷰에서 결정할 것

> [!question] 1. `place_content` 의 `UNIQUE(place_id, content_id)` 와 "등록 장면 수" 지표가 충돌한다
> 작품 상세는 **촬영지 수** 와 **등록 장면 수** 를 별도 지표로 보여준다. 그런데 `place_content` 에 `UNIQUE(place_id, content_id)` 가 걸려 있으면 한 장소에 같은 작품의 장면은 1건뿐이므로 **두 값이 항상 같아진다.** 목업 데이터에서도 실제로 그렇다 — `도깨비` 6곳/6장면, `눈물의 여왕` 4곳/4장면.
> 선택지는 둘이다.
> - **(A)** 지표를 하나로 합친다 (`촬영지 N곳`). 스키마 변경 없음.
> - **(B)** 장면을 분리한다 — `place_content` 아래 `scene` 테이블을 두고 UNIQUE 를 해제. 한 장소에서 같은 작품의 여러 장면(예: 1화 로비 씬 / 12화 재회 씬)을 구분할 수 있게 된다. §5.2 의 4·5·6·7·13 이 전부 이 테이블로 내려간다.
>
> **(B)를 택하면 §5.2 항목 절반의 소속이 바뀌므로 이것을 먼저 결정해야 한다.**

> [!question] 2. 연도·장르를 `content` 에 둘 것인가
> 스키마는 `air_period`·`air_status` 를 "TEXT 범위라 정렬 불가 + 파생값이라 낡는다"는 이유로 뺐다. 타당하지만 **연도 단일 INT는 그 두 문제가 없다** — 정렬 가능하고 낡지 않는다. 장르도 화면 메타의 3분의 1을 차지하는데 현재 대응 컬럼이 없다. 작품마스터 28컬럼에 원본이 있는지 확인 필요.

> [!question] 3. 작품 대표 지역을 매 조회 집계할 것인가
> `top_region` 을 "`place_content` 집계 파생값"으로 뺐는데, 목업은 **작품 목록의 모든 카드** 에 지역을 표시한다. 장소 14,000+ · 작품 476 규모에서 목록 조회마다 집계하면 부담이므로, 적재 시 계산해 `content.top_region` 에 넣는 편이 `popularity_score` 처리 방식과도 일관된다.

> [!question] 4. 명대사·장면 스틸의 저작권 처리
> 스키마 문서는 `scene_image` 를 "실제 관문은 저작권" 이라며 보류했다. **명대사도 같은 성격의 저작물** 이고, 목업에서는 장면 팝업의 시각적 중심이다. 두 항목을 묶어 한 번에 판단하는 편이 낫다 — 짧은 인용의 허용 범위, 출처 명시 방식, 제휴 필요 여부.

> [!question] 5. 검수·신뢰도 파이프라인의 MVP 범위
> 목업은 신뢰도 %, 검수 완료 배지, 제보 N건, 커뮤니티 제보·검증 탭, 마이페이지 "내 제보 검수 현황" 까지 **일관된 하나의 시스템** 으로 그려져 있다. 스키마에는 전혀 없다. MVP1에서 값을 고정 표시할지, 아예 목업에서 뺄지, MVP2 테이블로 설계할지 결정 필요.

## 6. 목업의 알려진 한계

- 지도는 **정적 이미지 + % 좌표 핀** 이다. 네이버 지도 SDK 연동 시 좌표계·줌 레벨 재설계 필요
- 거리 값이 하드코딩 문자열(`1.2km`, `240m`)이고 근처 검색 반경 5km 도 상수. 실제로는 `place.geom` 기반 런타임 계산
- AI 가이드는 키워드 매칭 룰이며 LLM 호출 없음
- 이미지는 시드 기반 플레이스홀더(`picsum.photos`) 또는 파일 내 임베드 리소스
- 검색이 단순 `includes()` — 초성 검색·로마자·오타 보정 미지원. 실제로는 `search_term` 의 `pg_trgm` 이 담당
- dedupe 이전 상태를 전제한 데이터라 동일 장소 중복 케이스가 없음
