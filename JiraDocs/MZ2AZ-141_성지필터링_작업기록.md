> [!summary] v4(5,669행)의 작품 161편을 네이버 블로그에서 '촬영지·성지순례·무대탐방' 키워드로 크롤링(8,623개 글)해, **여러 글에 반복 등장하는 장소일수록 인기 성지** 라는 기준으로 점수를 매기고 **1,091행** 만 남겼다.
> 같은 패스에서 비어 있던 `scene_description` 을 글 본문 문장으로 37건 채웠다.
> 이 문서는 **무엇을 어떻게 모았고, 무슨 기준으로 걸렀으며, 어디까지가 신뢰할 수 있고 어디부터가 한계인지** 를 기록한다.

## 1. 배경 — 왜 이 작업인가

7/31 회의 「앞으로 할 일」의 지시:

> - Description 채우기와 인기성지 필터링을 진행할 필요가 있음
>   - 이에 대해 로컬 LLM을 사용할 수 있을지에 대한 논의가 진행됨
>   - 필터링 된 성지데이터의 파일이름은 v4 로 할 것

v4는 143~147(정승길)이 끝나면서 **5,669행 × 21컬럼** 으로 확정됐지만, 이건 "빈칸을 채운 v3"이지 **필터링이 된 상태가 아니다**. 눈물의여왕 한 편에만 145곳이 붙어 있어 앱에 그대로 노출하면 쓸 수 없다.

**핵심 가설** — 하나의 작품을 두고 블로그를 여러 개 긁으면, 진짜 사람들이 찾아가는 성지는 여러 글에 반복 등장한다. 그 반복 횟수가 곧 인기도다.

> [!note] 로컬 LLM은 쓰지 않았다
> 회의에서 논의된 로컬 LLM 대신 **문자열 매칭 + 규칙 기반 점수** 로 갔다. 5,669행 × 8,623글 조합을 LLM으로 돌리면 비용·시간이 크고, 검증해 보니 매칭만으로도 대표 성지가 정확히 상위에 올라왔기 때문이다(§5 검증). 재현·감사도 쉽다.

## 4. 채점과 필터

### 4.1 장소 매칭

`place_name` 을 소문자화·공백/문장부호 제거로 정규화한 뒤 본문에서 찾는다. 매칭 키는 여러 개를 만든다.

- `마곡중앙로(1)` → `마곡중앙로` (괄호 앞)
- `윤치과(청진3리어민복지회관)` → `윤치과` + `청진3리어민복지회관` (괄호 안 별칭도)
- `스타벅스 성수점` → `스타벅스성수` (지점 접미사 제거)
- 3글자 미만이거나 `서울`·`카페`·`공원` 같은 일반명사는 **버린다** (오탐 방지)

### 4.2 인기도 점수

```
popularity_score = (이 장소를 언급한 글 수 ÷ 그 작품 1위 장소의 글 수) × 100
```

**작품 내 상대빈도로 정규화한 이유** — 원시 언급 수만 쓰면 글이 많은 대형작이 상위를 독식하고, 마이너 작품의 대표 성지가 전부 묻힌다. 작품 인기도(`famous_rank`)와 **장소 인기도를 분리** 해야 앱에서 둘을 따로 쓸 수 있다.
검색 결과 제목에 장소명이 뜨면 대표 성지일 확률이 높아 +1 가중했다.

### 4.3 필터 규칙 (적용 순서)

| 순서 | 규칙 | 결과 |
| --- | --- | ---: |
| 1 | 해외 로케이션 → 제외 | 116행 탈락 |
| 2 | 근접 중복 → 대표 1행으로 통합 | 203행 탈락 |
| 3 | **언급 2글 이상 + 작품 내 상위 15** → 통과 | 986행 통과 |
| 4 | 작품 내 언급 비율 15% 이상 → 통과 | (3에 포함) |
| 5 | 위로 3곳이 안 되는 작품은 데이터 품질 순으로 보존 | 105행 통과 |

- **1 해외 제외** — 7/31 회의 안건 3(국내 여행 앱이므로 제외가 기본). 좌표가 한국 범위(위도 33~38.7 / 경도 124.5~132) 밖이면 해외로 본다. 눈물의여왕은 독일 로케이션(상수시궁전·베를린돔 등)이 언급 상위를 독식했는데 전부 걸러졌다. **`is_overseas` 플래그로 남겨 뒀으니 팀이 방침을 뒤집으면 한 줄로 되살릴 수 있다.**
- **2 근접 중복** — `용연리(1)` · `용연리(2)` · `용연리마을(용두리)` 처럼 같은 곳이 여러 행으로 갈라져 필터 슬롯을 잠식한다. 정규화 키가 같거나 한쪽이 다른 쪽의 **접두** 면 같은 곳으로 보고, 데이터가 가장 충실한 행을 대표로 남긴다.
- **5 최소 보존** — 크롤링 신호가 약한 작품이라고 앱에서 통째로 사라지면 안 되므로, 장면설명·네이버URL·사진·좌표가 있는 순으로 3곳까지 채운다.

## 6. 작업 중 발견한 v4 결함 (정승길 확인 필요)

> [!question] 확인 필요 — 두 건 다 원본 `촬영지_TOP_v4_MVP1.csv` 의 문제다

**① 작품명 표기 중복 — 205개 title 값이 실제로는 161편**
`눈물의여왕`(145행)과 `눈물의 여왕`(7행)이 별개 작품으로 들어가 있다. 이런 그룹이 **43개**. 이대로 두면 앱에서 같은 작품이 두 번 뜨고, 성지도 갈라진다.
→ 이번 산출물에는 `title_key`(공백·문장부호 제거) 컬럼을 넣어 묶어 뒀지만, **v4 원본의 `title` 자체를 통일하는 게 맞다.**

**② 위도·경도가 뒤바뀐 행 18개 — 마더 10 · 지옥 8**
예: 남이섬이 `lat=127.525, lon=37.791` 로 들어가 있다(정상은 반대). 지도에 찍으면 엉뚱한 곳으로 간다.
→ 이번 산출물에서는 자동 교정하고 `coord_issue='위경도뒤바뀜_교정'` 로 표시했다. **v4 원본도 고쳐야 한다.**

## 7. `scene_description` 보완

빈칸이던 행에 대해, 그 장소가 언급된 문장 중 **장면 서술에 가장 가까운 문장** 을 골라 넣었다.

- **필수 조건** — 문장에 `촬영`·`장면`·`씬`·`등장`·`배경` 같은 단서가 하나라도 있어야 한다. 없으면 잡문이라 버린다.
- 가점: 문장이 끊기지 않고 끝남 / 그 장소가 문장 앞쪽(주어) / 30~160자
- 감점: 홍보·협찬 문구 / 해시태그·전화번호 / 장소를 3개 이상 나열한 문장
- 같은 문장을 한 작품 안에서 **두 장소에 돌려쓰지 않는다**

**결과 — 37건 보완.** 예:

> 모범택시3 · 해양힐링로 → "김도기가 마지막에 택시를 몰고 해안선을 따라 달리는 장면은 태종대 조개구이촌에서 동삼중리로 이어지는 해양힐링로라는 도로에서 촬영됐어요."

> [!note] 수확이 37건뿐인 이유는 원천 부재다
> 언급이 있는 2,278행 중 **1,808행은 이미 승길님이 채워 놨고**, 남은 빈칸 대부분은 `올림픽대로`·`노량대교`·`경복궁 정류장(01540)` 같은 도로·정류장이다. 표본 조사에서 후보 문장이 아예 0개인 행이 **105/151** 이었다.
> 이는 MZ2AZ-143에서 승길님이 내린 판정("잔여 42%는 온라인에 장면 서술 자체가 없음")과 **독립적으로 같은 결론** 에 도달한 것이다. 여기서 더 파도 안 나온다.

## 8. 한계 — 그대로 믿으면 안 되는 것

1. **이름으로만 매칭한다.** 블로그가 다른 이름으로 부르는 성지는 놓친다. 예) `구룡포항 언덕(전망 계단)` 은 블로그에서 보통 "동백이 계단"·"일본인 가옥거리"로 불려 0글로 떨어졌다. **실제 인기 성지인데 탈락한 케이스가 있다.**
2. **인기도는 "블로그에 많이 쓰였나"지 "방문자가 많나"가 아니다.** 진짜 인기도는 권호님이 설계 중인 **유저 이벤트 + 반감기** 로 가야 한다(7/31 회의). 이 점수는 **콜드 스타트 초기값** 으로만 써야 한다.
3. **최근 편향.** 네이버 검색은 최신 글을 위로 올린다. 구작(별에서 온 그대 등)은 성지가 살아 있어도 글이 적게 잡힌다.
4. **최소 보존 105행은 인기도 근거가 없다.** `filter_reason='언급부족_데이터품질기준보존'` 이며, 데이터가 충실하다는 이유로만 남았다.
5. **동명이인 오탐.** 짧고 흔한 이름은 다른 뜻으로 걸릴 수 있다. `인기성지_언급근거_2026-08-01.csv` 의 URL로 표본 검수를 권한다.

## 9. 팀에 물어야 할 것

1. **해외 로케이션 116행** — 지금은 전부 제외. 눈물의여왕(독일)·모범택시3(일본)처럼 상위 성지가 통째로 빠진다. "작품 정보 차원에서 노출"할지 결정 필요 (7/31 안건 3).
2. **컷 기준** — 지금은 "언급 2글 이상 + 작품 내 상위 15"로 작품당 평균 6.8곳. 앱 화면 설계에 따라 상향·하향 가능하며, `popularity_score` 가 남아 있어 재계산은 즉시 된다.
3. **파일명** — 회의록은 "필터링 된 파일명은 v4"라 했지만, v4는 이미 승길님 산출물명이다. 덮어쓰지 않고 `촬영지_v4_인기성지_필터링_2026-08-01.csv` 로 뒀다. **v5로 승격할지 팀 결정 필요.**
4. **§6 결함 2건** — 승길님이 v4 원본을 고칠지, 이 산출물의 교정본을 정본으로 삼을지.

## 10. 재현 방법

```bash
pip install requests beautifulsoup4 lxml
python scripts/crawl.py    # 1단계 — 작품별 블로그 코퍼스 수집 (재실행 시 이어받기)
python scripts/score.py    # 2단계 — 채점·필터·설명 보완·CSV 4종 출력
```

`crawl.py` 는 코퍼스를 작품 단위 `jsonl` 로 캐시하므로 중간에 끊겨도 다시 돌리면 남은 작품만 받는다. 코퍼스 원본(69MB)은 세션 스크래치패드에 있고 볼트에는 넣지 않았다 — 필요하면 `crawl.py` 재실행으로 복원된다.
