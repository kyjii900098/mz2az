> [!summary]
> `JiraDocs/` 는 Jira **스토리(작업) 단위 산출물 기록소** 다. 팀원 누구든(또는 Claude를 호출해서) 이 규칙대로 문서를 만들거나 갱신한다.
> 호출법 — Claude에게 **"JiraDocs 갱신해줘"** 또는 **"MZ2AZ-NNN 문서 만들어줘"** 라고 하면 이 파일을 읽고 아래 절차를 그대로 수행한다.

---

## 1. 파일 단위와 이름

| 규칙 | 내용 |
| --- | --- |
| 파일 단위 | **파일 하나 = 스토리(작업) 하나** |
| 파일명 | `MZ2AZ-{스토리번호} {스토리명}.md` |
| 에픽·서브태스크 | 별도 파일을 만들지 않는다 — 서브태스크는 스토리 파일 안의 `##` 섹션 |

---

## 2. 문서 양식

```markdown
---
title: "{스토리명}"
type: jiradoc
status: 완료 | 진행 중
updated: YYYY-MM-DD
---

JIRA:MZ2AZ-124          ← 서브태스크 티켓 전부 나열 (플러그인이 상태 렌더링)
JIRA:MZ2AZ-125

| 티켓 | 제목 | 담당 | 상태 |
| --- | --- | --- | --- |
| [MZ2AZ-124](https://mz2az.atlassian.net/browse/MZ2AZ-124) | … | 김태환 | ✅ 완료 |
| [MZ2AZ-125](https://mz2az.atlassian.net/browse/MZ2AZ-125) | … | 정승길 | 🔄 진행 중 |

> [!summary]
> 스토리 한 줄 요약 — 무엇을 왜 했고, 핵심 결과가 무엇인지. 근거 회의록 링크.

---

## MZ2AZ-124 서브태스크 제목        ← 티켓번호 오름차순

**파일** — [[결과물 파일]] · [[근거 회의록]]

| 산출물 | 규모 | 내용 |
| --- | --- | --- |
| … | … | … |

- 보충 설명 (상세 서술이 필요하면 MZ2AZ-111 SceneTrip DB 스키마처럼 길게 써도 된다)

---

## MZ2AZ-125 서브태스크 제목
…
```

**시각 요소를 적극 사용할 것** — 밋밋한 불릿 나열 금지.

| 요소 | 용도 |
| --- | --- |
| `> [!summary]` | 문서 맨 위 스토리 요약 (필수) |
| `> [!note]` / `> [!tip]` | 배경·경위, 팁 |
| `> [!warning]` | 주의사항 (병합 유실, 데이터 함정 등) |
| `> [!question] 확인 필요` | 미확인·미확보 항목 |
| `---` 구분선 | **서브태스크 섹션 사이마다** (필수) |
| 표 | 산출물 목록·수치·비교는 불릿 대신 표로 |
| **굵게** | 핵심 수치·파일명 강조 |

---

## 3. 작성 규칙

1. **완료·진행 중 티켓만 다룬다.** "해야 할 일" 서브태스크는 상단 `JIRA:` 나열과 티켓 표에는 포함하되(상태 ⬜), 본문 섹션은 만들지 않는다. 진행 중 티켓 섹션에는 현재까지의 진행 상황을 적고 제목에 `(진행 중)` 을 붙인다.
2. **서브태스크 섹션은 티켓번호 오름차순** 으로 정렬한다.
3. **섹션 소유권** — 각 서브태스크 섹션은 그 태스크를 수행해 결과를 낸 사람만 작성·수정한다. 다른 팀원은 같은 스토리 파일에 자기 섹션을 **추가** 만 한다. 남의 섹션은 건드리지 않는다.
4. **이미 있는 문서·섹션은 손대지 않는다.** 새로 완료된 티켓의 섹션만 추가한다.
5. **파일 링크는 원본이 아니라 볼트 안의 파일** 로 건다. 결과물은 주로 `01_Raw/{김태환, 정권호, 정승길}/` 아래에 있다. 동명 파일이 여러 개면 경로 붙인 위키링크를 쓴다 — `[[01_Raw/정승길/data/README|data/README]]`. 원본과 전사본이 둘 다 있으면 `전사/` 쪽을 링크한다.
6. **결과 설명은 검증된 내용만.** 근거는 ① Jira 티켓 설명 ② 회의록(`00_기록/Daily(태환작성)/`, `00_기록/Sprint(권호작성)/`, `01_Raw/정승길/데일리회의/`) ③ 실제 산출물 파일. 수치는 산출물·작업 로그에서 직접 확인한 값만 쓴다.
7. 굵게(`**단어**`) 뒤에 조사가 바로 붙으면 렌더링이 깨진다 — 한 칸 띄운다: `**단어** 다`.

## 4. 생성 절차 (Claude 호출 시)

| 단계 | 작업 |
| --- | --- |
| 1 | Jira 조회 — JQL `project = MZ2AZ AND status in ("완료", "진행 중")` 로 스토리·서브태스크 계층과 담당자 파악 |
| 2 | `JiraDocs/` 기존 파일 확인 — 이미 문서화된 티켓은 건너뜀 |
| 3 | 결과물 탐색 — `01_Raw/{김태환, 정권호, 정승길}/`, `assets/`, `01_Raw/정승길/전사/Project/JiraDocs/` |
| 4 | 근거 수집 — Daily·Sprint Planning·멘토링 회의록에서 해당 작업 언급 확인 |
| 5 | 새 스토리는 파일 생성, 기존 파일에는 새로 완료된 서브태스크 섹션만 추가 |

> [!note] "내가 한 거 올려줘" (스토리 번호만 주어진 경우)
> `mcp__atlassian__atlassianUserInfo` 로 호출자를 식별한 뒤, 그 사람이 담당자인 완료·진행 중 서브태스크 중 아직 섹션이 없는 것만 골라 위 3~5단계를 수행한다. 기록·결과물을 볼트에서 못 찾으면 지어내지 말고 사용자에게 위치를 물어본다.

> [!warning] macOS 한글 파일명 함정
> 한글 파일명은 NFD 정규화라 `grep`/`find` 가 놓칠 수 있다. 탐색이 빗나가면 python `unicodedata.normalize('NFC', …)` 로 비교할 것.
