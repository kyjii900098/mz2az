# 05. 2026-08-08 — 설문 최종 분석 (n=88)

> 설문 마감본 88건을 받아 다시 분석했다. 페르소나를 가르는 축이 통계적으로 하나도 확인되지 않아, 페르소나의 지위를 "근거"에서 "서술 장치"로 내렸다.
> 작업자: 정승길 (Claude Code 보조)
> 관련 문서: [[SceneTrip 설문 최종 분석 (n=88)]], [[설문조사 결과]], [[사용자 페르소나 4종]], [[SceneTrip 사용자 페르소나와 앱 사용 시나리오]]

## 1. 무엇을 받았나

설문 대행(surveyswap) 마감본 CSV를 zip으로 받아 볼트에 넣었다. **88행 × 27열** 이고, 관심 없음 6명을 뺀 유효 응답은 82명이다.

정권호가 8/01에 쓴 [[SceneTrip 사용자 페르소나와 앱 사용 시나리오]] 는 **69행** 으로 만든 것이었다. 두 파일을 대조해 보니 88행은 69행을 **한 줄도 바꾸지 않고 그대로 포함하는 상위집합** 이었고, 7/25 이후 응답 19건이 8/02까지 더 들어와 붙은 것이었다.

```
old ts range 2026/07/08 3:05:46 오후 GMT+9 ~ 2026/07/25 3:36:48 오전 GMT+9
new ts range 2026/07/08 3:05:46 오후 GMT+9 ~ 2026/08/02 3:24:02 오후 GMT+9
old rows present in new: 69 / 69
```

이걸로 [[MZ2AZ-90 설문 조사]] 에 남아 있던 `확인 필요` 가 풀렸다. **"7/27 기준 87개"와 "CSV 69행"의 불일치는 스크리닝 탈락이 아니라 스냅샷 시점 차이** 였다.

## 2. 막혔던 것 — zip 압축 해제 실패

macOS에서 `unzip` 이 파일명 인코딩 때문에 죽었다.

```
error:  cannot create survey_new/K-Content Travel ��� 90-Second Fan Survey (Anonymous).csv
        Illegal byte sequence
```

파일명의 em dash(`—`)가 문제였다. `unzip` 대신 파이썬 `zipfile` 로 읽어서 직접 파일명을 지정해 저장하는 방식으로 우회했다.

```python
import zipfile
z = zipfile.ZipFile(path)
for i, n in enumerate(z.namelist()):
    open(f'survey_{i}.csv', 'wb').write(z.read(n))
```

> [!note] 나중에 알게 된 것
> 사실 같은 CSV가 Dropbox 동기화로 이미 볼트에 들어와 있었다. 처음 `ls` 를 했을 때는 zip만 보였는데 작업 중에 동기화가 끝나면서 나타났다. **Dropbox 폴더에서는 `ls` 결과가 그 시점의 최종 상태가 아닐 수 있다.**

## 3. CSV를 읽을 때 주의할 것

27개 열 중 **5쌍이 같은 질문명으로 중복** 된다. "여행 단계" 문항의 답에 따라 응답자가 서로 다른 경로로 분기하고, 각 분기가 별도 열에 기록되기 때문이다.

`csv.DictReader` 로 읽으면 중복된 열 이름이 하나로 합쳐지면서 **한쪽 분기 응답이 통째로 사라진다.** 인덱스를 직접 다루는 방식으로 읽어야 한다. 다중선택 문항의 구분자는 쉼표가 아니라 **세미콜론(`;`)** 이다 — 선택지 문구 자체에 쉼표가 들어 있어서 쉼표로 자르면 항목이 쪼개진다.

## 4. 판단이 갈렸던 지점

### 4.1 처음엔 v1 대비 비교로 썼다가 갈아엎었다

처음에는 "69건 → 88건에서 무엇이 바뀌었나"를 축으로 문서를 썼다. 사용자가 **"비교가 아니라 최종본의 순수한 분석"** 을 원한다고 해서 전면 재작성했다. 비교 문서(`SceneTrip 설문 재분석 v2 (n=88).md`)는 지웠다.

결과적으로 이게 맞았다. 비교로 쓰면 "P1의 지불 의사가 41%에서 30%로 내려갔다" 같은 문장이 나오는데, **애초에 41%도 30%도 통계적 근거가 없다는 것이 진짜 결론** 이기 때문이다. 비교 프레임이 그 사실을 가렸다.

### 4.2 축을 물려받지 않고 다시 검정했다

정권호의 원본은 "나이·거주·콘텐츠 종류는 안 갈리고, 여행 단계 × 여행 스타일은 깨끗하게 갈렸다"고 적었다. 이걸 그대로 쓰지 않고 축 후보 6개를 전부 다시 검정했다. **결과가 뒤집혔다** — §5 참고.

### 4.3 사전 지정 가설을 따로 뒀다

축 검정 56건에서 p<0.05가 6건 나왔는데, 이건 사후에 눈에 띄는 것만 고른 것이라 낚시로 보일 수 있다. 그래서 **기존 팀 문서가 이미 주장하고 있던 명제 5개를 미리 정해 놓고** 그것만 따로 검정했다(`hypo.py`). 둘 다 같은 결론이 나와서 신뢰할 수 있게 됐다.

## 5. 결과 — 축을 하나도 못 찾았다

축 후보 6개에서 n≥15인 그룹끼리 기능 니즈 6개와 지불 의사를 양측 z검정으로 비교했다. **총 56건.**

| 축 후보 | 기능 니즈 평균 격차 |
| --- | ---: |
| 거주 지역 | 23.0%p |
| 성별 | 15.1%p |
| 여행 스타일 | 14.5%p |
| 콘텐츠 종류 | 14.3%p |
| 나이 | 12.0%p |
| 페인 경험 유무 | 10.9%p |
| **여행 단계** | **8.9%p** |

p<0.05가 6건 나왔지만 **56건을 검정하면 우연히 2.8건이 나오는 것이 정상** 이다. Benjamini-Hochberg로 FDR 10%를 걸면 **6건 전부 탈락한다.**

**여행 단계가 후보 중 가장 못 가르는 축** 이었다는 점이 뼈아프다. 페르소나의 1번 축이다.

사전 지정 가설 5개도 결과가 같았다.

| 가설 | p | |
| --- | ---: | --- |
| 완성형 코스 원하는 사람은 한국에 안 가봤다 | 0.165 | ✗ |
| AI 동선 원하는 사람은 한국에 안 가봤다 | 0.206 | ✗ |
| 돈 낼 의사는 방문 경험자에게 몰린다 | 0.347 | ✗ |
| 언어장벽과 정보 분산은 다른 사람이 겪는다 | — | ✗ 그냥 독립 |
| 페인 안 겪은 사람이 지도를 더 원한다 | **0.027** | △ |

> [!warning] 내가 처음에 잘못 읽을 뻔한 것
> "완성형 11명 중 10명이 미방문(91%)"이라는 숫자를 보고 강한 발견이라고 생각했다. **틀렸다.** 표본 전체의 미방문 비율이 이미 74%라, 11명을 무작위로 뽑아도 8명은 미방문자다. 관측된 10명은 기대치보다 2명 많을 뿐이다.
> 비율이 높아 보여도 **기저율(base rate)을 먼저 봐야 한다.** 이 설문은 방한 경험자가 21명뿐이라 이런 비교에 애초에 검정력이 없다.

기능 선택 벡터로 데이터 주도 군집화(자카드 거리 + 평균연결 계층군집)도 돌려 봤는데, 나온 군집이 "검색을 골랐나 / AI를 골랐나"뿐이었다. 0%와 100%가 대각선으로 늘어서는데, 이건 사람의 차이가 아니라 **"최대 3개만 선택"이라는 문항 제약** 을 알고리즘이 다시 읽어낸 것이다.

## 6. 그래서 무엇을 바꿨나

**페르소나를 버리지는 않았다.** 화면을 설계할 때 "누구의 하루를 그리는가"를 고정하는 용도로는 여전히 쓸모가 있고, 박재범 멘토가 07-21에 요구한 것도 그 서술이었다. 바꾼 것은 **지위** 다.

- ❌ "설문에서 P1이 27%이므로 P1 화면을 먼저 만든다"
- ⭕ "전체 집계에서 확인된 니즈를 P1의 하루라는 형식으로 서술한다"

시나리오도 군집별로 쓰지 않고, 이 설문이 실제로 구분해 주는 축 하나 — **지금 한국에 있는가** — 로 두 개만 썼다. 기능 니즈는 못 가르지만 앱을 여는 상황 자체가 다르기 때문이다.

대신 **전체 집계 수준의 사실 다섯 개** 를 근거로 남겼다. 나눌 필요가 없어서 오히려 튼튼하다.

| # | 사실 | 수치 |
| ---: | --- | --- |
| 1 | 언어장벽이 단일 최대 페인 | 44%, 2위와 16%p 차 |
| 2 | 지도와 검색이 제품의 두 축 | 둘 중 하나 83% |
| 3 | 찾다가 포기하는 비율 | 12% |
| 4 | 유료화 근거 없음 | $11+ 21%, 지불 경험 없음 79% |
| 5 | 못 가는 이유는 우리가 못 푼다 | 자유응답 대부분이 돈 |

## 7. 파일을 어디에 뒀나

처음엔 `01_Raw/정승길/설문결과/` 에 뒀는데, [[01_Raw/README]] 의 두 갈래 규칙(주차 폴더 / `logs/`)에 없는 폴더였다. 게다가 **설문은 내 개인 작업이 아니라 팀 공용 산출물** 이다.

`01_Raw/Project/03_설문결과/` 가 8/01에 만들어져 비어 있는 것을 발견해서 그리로 옮겼다. 원래 이걸 위해 만들어진 자리로 보인다.

```
01_Raw/Project/03_설문결과/
├── K-Content Travel — 90-Second Fan Survey (Anonymous).csv       ← 원본 88행
├── K-Content Travel — 90-Second Fan Survey (Anonymous).csv.zip   ← 받은 그대로
├── SceneTrip 설문 최종 분석 (n=88).md                             ← 분석 본문
├── analyze.py    ← 집계 (분기 열 병합 처리 포함)
├── axes.py       ← 축 후보 6개 비교
├── stats.py      ← 유의성 검정 + 데이터 주도 군집화
└── hypo.py       ← 사전 지정 가설 5개
```

스크립트를 같이 둔 이유는 **재현 가능하게 하려는 것** 이다. `analyze.py` 를 69행 CSV에 돌리면 정권호의 원본 표(여행 단계 44/17/3/5, 페인포인트 27/21/19/15/12/7/4, 탐색 채널 33/31/29/13/12/10/10)가 그대로 재현된다. 이걸 먼저 확인하고 나서 88행 분석에 들어갔다.
