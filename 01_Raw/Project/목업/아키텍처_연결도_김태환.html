실제 데이터 흐름 (핵심 시나리오 3)
1

촬영지 검색 → 지도에 성지 핀 표시

지도 사용

사용자가 작품을 고르면 실제 촬영 성지가 지도 위 핀으로 뜨는 흐름.

STEP 1
Frontend
작품 선택 · 내 위치(GPS)와 함께 요청 전송
STEP 2
Backend
인증 확인 후 성지 조회 요청 중계
STEP 3
PostGIS
지리 쿼리로 해당 작품 성지 + 좌표 반환
STEP 4
Frontend
받은 좌표를 지도 SDK로 핀·내 위치 렌더링
지도는 Frontend가 그리고, 핀 좌표 데이터는 PostGIS의 성지 DB에서 옵니다. AI는 이 단계에 관여하지 않음(빠른 조회).
2

실시간 AI 가이드 질문 — "여기 어떻게 가요?"

RAG + 권한 + 지도

RAG와 지도(Route API), 그리고 구매 권한(Entitlement)이 한 번에 맞물리는 핵심 흐름.

STEP 1
Frontend
질문 + 현재 위치·활성 경로 전송
STEP 2
Backend
Entitlement 판정 — tier·허용 work/route id를 붙여 AI에 전달
STEP 3
AI · Agent
의도 파악 → 필요한 도구 호출 결정
STEP 4
AI · RAG
권한 필터로 허용 청크만 벡터 검색 → 근거 확보
STEP 5
Route API
get_route로 도보/대중교통 실측 동선 계산
STEP 6
Frontend
근거 포함 답변 + 지도 핀/동선 갱신
같은 질문이라도 무료 유저는 요약형 답변+구매 유도, 해당 경로 구매/패스 유저는 상세 씬·팁까지 — 차이는 STEP 4의 RAG 검색 범위(권한 필터)에서 갈립니다.
3

성지 데이터 자동 구축 (배치 · 서비스 이전 준비)

배치 파이프라인

앱 요청과 무관하게 오프라인에서 성지 DB와 RAG 인덱스를 미리 채워두는 흐름.

STEP 1
콘텐츠 소스
YouTube 자막·블로그·기사 수집 (출처 URL 보관)
STEP 2
AI · 추출
LLM로 작품·씬·장소·주소 구조화 추출
STEP 3
Geocoding
주소 → 좌표 변환, 중복 병합
STEP 4
AI · HITL
저신뢰 건 사람 검수 후 승인
STEP 5
Data
PostGIS 적재 + 임베딩 → pgvector 인덱싱
이 배치가 Flow 1의 지도 핀과 Flow 2의 RAG 근거의 원천 데이터를 만듭니다. 실시간 흐름(1·2)과 분리해 앱 응답 지연을 없앰.
지도와 RAG는 정확히 어디에 쓰이나
지도(Map)는 3곳에서 쓰입니다
  • Frontend 렌더링 — 지도 SDK로 성지 핀·내 위치·경로 동선 표시 (Flow 1·2)
  • PostGIS 지리 검색 — "내 반경 N km 성지", 근접 정렬 등 위치 쿼리 (Data 계층)
  • Route API 길안내 — AI Agent가 도보/대중교통 실측 동선 계산에 호출 (Flow 2)
  • Geocoding — 수집 파이프라인에서 주소를 좌표로 변환 (Flow 3)
RAG는 이렇게 쓰입니다
  • 근거 기반 응답 — AI 가이드가 성지 DB·검증 후기를 검색해 환각 없이 답변 (Flow 2)
  • 권한 필터 검색 — Backend가 준 tier로 허용된 work/route 청크만 검색 → 차등 서비스
  • 인용(citation) 반환 — 답변에 출처를 붙여 목업의 "검증 데이터 기반" 카드 구현
  • 작품 요약·추천 근거 — 작품 상세·추천 이유 생성에도 활용
한 줄 정리   Frontend는 보여주고(지도·챗봇), Backend는 지키고(인증·결제·권한), AI Service는 생각합니다(RAG·Agent·추출). 지도는 표현+지리검색+길안내에, RAG는 AI 응답의 근거와 권한별 차등에 쓰입니다.
