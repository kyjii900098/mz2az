## 1. 서비스 포지셔닝

본 서비스는 K-POP, K-드라마, K-영화, 예능, 애니메이션 등 K-콘텐츠와 연결된 실제 장소를 통합 제공하는 팬덤 여행 플랫폼이다. 핵심은 장소 목록 제공이 아니라, 작품 장면의 맥락, 사용자 취향, 현재 위치, 이동 동선, 방문 후 기록을 하나의 여행 경험으로 연결하는 것이다.

기존 서비스가 지도 위 핀과 단편 장소 정보에 머무르는 경향이 있다면, 본 서비스는 다음 네 가지를 차별화 축으로 삼는다.

- 데이터 신뢰도: 공식 자료, 사용자 제보, 방문 인증, 운영 상태를 결합한 검증형 DB이다.
- 여행 실행성: 현재 위치, 남은 시간, 교통수단, 영업시간을 반영해 실제 이동 가능한 루트를 제안한다.
- 팬덤 맥락: 작품명, 회차, 장면 설명, MV 타임스탬프, 방문 포인트를 장소와 연결한다.
- 커뮤니티 기록: 사용자의 성지순례 이동기를 블로그처럼 축적해 다음 방문자의 여행 자료로 전환한다.

## 2. 고려해야 할 핵심 질문

### 데이터를 어떻게 모을 것인가

데이터는 한 번에 완성하는 방식이 아니라, 공식 자료와 사용자 참여를 결합해 단계적으로 구축하는 방식이 적절하다.

1. 초기 데이터는 한국관광공사, 지자체 관광 페이지, 제작사·방송사·OTT 홍보 페이지, 공식 SNS, 지도 API, 공개 보도자료를 기반으로 구축한다.
2. 사용자 제보 기능을 통해 팬이 직접 성지 후보를 등록하게 한다.
3. GPS 체크인, 최근 방문 사진, 후기, 운영 상태 신고를 통해 최신성을 보완한다.
4. 관리자 검수와 신뢰도 라벨을 통해 공식 확인, 사용자 다수 검증, 제보 필요, 폐업/이전 의심 등으로 구분한다.
5. 지역 상점, 여행사, 지자체가 직접 정보를 수정할 수 있는 파트너 콘솔을 제공한다.

데이터의 핵심 단위는 장소가 아니라 `콘텐츠-장면-장소-방문경험`의 연결 관계이다.

초기 구축은 수작업 큐레이션이 불가피하다. 다만 모든 데이터를 사람이 직접 입력하는 방식은 확장성이 낮으므로, 다음과 같은 수집 파이프라인을 두는 것이 적절하다.

- 1차 후보 수집: 공식 관광 페이지, 지자체 보도자료, 제작사 홍보자료, 공개 지도, 팬 블로그, SNS 링크에서 후보 장소를 수집한다.
- 2차 정규화: 장소명, 주소, 좌표, 관련 작품, 회차, 장면 설명, 출처 URL, 영업 상태를 같은 스키마로 정리한다.
- 3차 검수: 관리자가 출처 신뢰도와 좌표 정확도를 확인한다.
- 4차 현장 검증: 사용자의 GPS 체크인, 최근 사진, 방문기, 폐업·이전 제보를 받아 최신성을 보완한다.
- 5차 파트너 검증: 지자체, 상점, 여행사가 자기 장소의 운영 정보와 이벤트 정보를 직접 관리하게 한다.

데이터 수집에서 중요한 것은 “많이 모으는 것”보다 “언제, 누가, 어떤 근거로 확인했는지 남기는 것”이다. 따라서 모든 장소 데이터에는 출처, 검증일, 검증 방식, 신뢰도 등급, 최근 사용자 확인일이 포함되어야 한다.

### 작품 장면 제시에 저작권 문제가 있는가

작품의 실제 장면 이미지, 영상 캡처, 대사 전문, 포스터, 음원, 뮤직비디오 장면은 저작권 또는 초상권 이슈가 발생할 수 있다. 따라서 기본 정책은 다음과 같이 설정하는 것이 안전하다.

- 서비스 초기에는 장면 원본 이미지를 자체 저장하지 않는다.
- 장면은 텍스트 설명, 회차, 타임스탬프, 공식 링크 중심으로 제공한다.
- 이미지가 필요한 경우 공식 홍보 이미지, 권리자가 허락한 이미지, 제휴 이미지, 사용자가 직접 촬영한 현장 사진을 우선 사용한다.
- 유튜브, OTT, 방송사 클립은 가능한 경우 임베드 또는 외부 링크 방식으로 연결한다.
- 사용자가 작품 캡처를 업로드하는 기능은 공개 게시가 아니라 개인 검색 또는 제보 검수용으로 제한한다.
- 상업화 단계에서는 제작사, 방송사, OTT, 엔터사와 제휴를 통해 공식 장면 카드 또는 프로모션 페이지를 확보한다.

즉, 장면 맥락은 제공하되 원저작물을 서비스 내부에 무단 복제하지 않는 방향이어야 한다.

법적으로는 공표된 저작물의 인용이나 공정이용 가능성이 논의될 수 있으나, 상업 서비스에서 드라마·영화·뮤직비디오 장면 캡처를 반복적으로 노출하는 것은 권리자와의 분쟁 가능성이 있다. 특히 이미지 한 장도 작품의 표현을 담고 있고, 배우·아이돌의 초상권 및 홍보 이미지 사용권과도 연결될 수 있다. 따라서 기획서에서는 “가능할 수도 있다”가 아니라 “서비스 정책상 무단 장면 사용을 기본값으로 삼지 않는다”라고 명확히 쓰는 것이 안전하다.

권장되는 장면 카드 정책은 다음과 같다.

- 안전 단계 1: 장면 이미지를 쓰지 않고, 작품명·회차·타임스탬프·텍스트 설명·공식 링크만 제공한다.
- 안전 단계 2: 사용자가 직접 촬영한 현재 장소 사진과 포토 가이드만 제공한다.
- 안전 단계 3: 방송사·OTT·제작사·엔터사 공식 홍보 이미지 또는 임베드 링크를 사용한다.
- 확장 단계 4: 권리자 제휴를 통해 공식 장면 카드, 공식 스틸컷, 프로모션 뱃지를 제공한다.

사용자가 업로드한 작품 캡처는 공개 게시물로 노출하지 않고, 개인 검색 또는 관리자 검수 자료로만 활용해야 한다. 공개 노출이 필요할 경우 자동 블러, 썸네일 비저장, 일정 기간 후 삭제, 권리자 신고 대응 프로세스를 두어야 한다.

### 수작업으로 구축한 데이터를 다른 서비스가 베껴갈 수 있는가

장소명, 주소, 좌표, 작품명 같은 사실 정보 자체는 독점하기 어렵다. 따라서 “우리가 수작업으로 모은 장소 리스트”만을 경쟁력으로 삼으면 다른 서비스가 크롤링하거나 사람이 복사해 따라올 수 있다. 이 리스크는 반드시 인정해야 한다.

다만 방어할 수 있는 영역도 있다. 핵심은 사실 데이터 그 자체가 아니라 다음과 같은 `가공 데이터`, `운영 데이터`, `네트워크 효과`이다.

- 출처와 검증 이력이 붙은 신뢰도 라벨
- 최근 방문 인증과 폐업·이전·촬영 제한 제보
- 사용자 방문기와 실제 이동 루트
- 장소별 혼잡도, 대기시간, 사진 촬영 난이도, 추천 시간대
- 팬덤별 저장/방문/공유 패턴
- 지자체·상점·여행사 파트너가 직접 갱신하는 이벤트와 쿠폰
- AI 챗봇이 사용자의 일정·위치·취향에 맞게 생성한 개인화 루트

따라서 데이터 방어 전략은 법적 차단보다 제품 구조를 통해 만들어야 한다.

1. 원천 목록이 아니라 검증 과정과 갱신 속도를 경쟁력으로 삼는다.
2. 사용자가 방문기를 작성할수록 서비스 안에 독자적 UGC가 쌓이게 한다.
3. 파트너 콘솔을 통해 외부에서 복사하기 어려운 실시간 이벤트·쿠폰·운영 정보를 확보한다.
4. 데이터 변경 이력, 신뢰도 점수, 사용자 반응 지표를 내부 자산으로 축적한다.
5. 서비스 약관으로 무단 크롤링과 대량 복제를 금지하고, API 접근은 인증·쿼터·워터마크 정책으로 관리한다.

결론적으로 본 서비스의 방어력은 “우리가 장소를 더 많이 안다”가 아니라 “우리가 더 빨리 검증하고, 더 잘 추천하고, 더 많은 실제 방문 경험을 축적한다”에 있다.

### 누가 돈을 내는 고객인가

비용을 지불할 고객은 개인 팬만으로 한정하면 약하다. 본 서비스의 유료 고객은 다음 세 계층으로 정의하는 것이 타당하다.

1. B2B/B2G 고객: 지자체, 관광재단, 지역 축제, 한류 관광 사업자이다. 지역 방문객 유입과 체류 시간을 늘리는 데 비용을 지불할 가능성이 가장 높다.
2. B2B 고객: 성지 주변 카페, 식당, 굿즈샵, 팝업스토어, 여행사, 숙박업체이다. 노출, 쿠폰, 예약 연결, 이벤트 홍보에 비용을 지불할 수 있다.
3. B2C 고객: 성지순례를 계획하는 국내외 팬이다. 무료 사용을 기본으로 하되, AI 루트 생성, 오프라인 저장, 다국어 여행 플래너, 프리미엄 방문기 템플릿 등에 과금할 수 있다.

초기 사업성은 B2C 구독보다 지자체·상점·여행사 제휴형 모델이 더 현실적이다.

### 챗봇 기능을 어떻게 넣을 것인가

챗봇은 단순 잡담 기능이 아니라 여행 실행을 돕는 AI 컨시어지여야 한다.

- “홍대 근처에서 BTS 관련 장소 2시간 코스를 짜줘” 같은 자연어 루트 생성
- “지금 열린 곳만 보여줘” 같은 운영 상태 필터
- “이 장소가 어떤 장면에 나온 곳인지 설명해줘” 같은 작품 맥락 Q&A
- “외국인이 가기 쉬운 동선으로 바꿔줘” 같은 현지화 요청
- “비가 오는데 실내 중심으로 바꿔줘” 같은 상황 대응
- 사용자 방문기를 기반으로 “내 여행 기록 요약문을 만들어줘” 같은 콘텐츠 생성
- 제보된 장소의 중복 여부, 신뢰도, 부족한 정보를 확인하는 관리자 보조 기능

챗봇은 장소 DB, 콘텐츠 DB, 지도/교통 API, 사용자 프로필, 운영 상태 데이터를 검색한 뒤 답변하는 RAG 구조로 구현하는 것이 적절하다.

### 성지순례 이동기 기능을 어떻게 넣을 것인가

개개인의 성지순례 이동기는 서비스의 커뮤니티이자 데이터 수집 장치이다. 사용자는 블로그처럼 여행기를 작성하고, 서비스는 이를 장소 최신성·동선 품질·후기 데이터로 전환한다.

필수 기능은 다음과 같다.

- 방문 장소 자동 타임라인
- 지도 위 이동 경로 표시
- 사진, 짧은 후기, 비용, 혼잡도, 대기시간 기록
- 작품/아티스트 태그
- 공개/비공개 설정
- 다른 사용자가 루트 복사하기
- 다국어 자동 요약
- 장소 정보 수정 제보 연결

방문기는 단순 커뮤니티 기능이 아니라, 신규 사용자의 여행 계획과 데이터 검증에 기여하는 핵심 자산이다.

## 4. 핵심 기능 우선순위

### MVP 필수

1. 콘텐츠/장소 통합 검색
2. 지도 기반 성지 핀
3. 현재 위치 기반 주변 추천
4. AI 챗봇 기반 루트 생성
5. 방문기 작성 및 루트 공유
6. 사용자 제보 및 관리자 검수
7. 저작권 안전 장면 카드
8. 한국어/영어 다국어 지원

### 2차 확장

1. 지자체·상점 파트너 콘솔
2. 쿠폰/예약/이벤트 연결
3. 팝업스토어·생일카페 실시간 이벤트 등록
4. 애니메이션·웹툰·게임 배경지 확장
5. 공식 IP 제휴 장면 카드
6. 여행사 패키지 연결

## 5. 결론

본 서비스는 기존 성지순례 서비스가 존재한다는 점을 약점이 아니라 시장 검증 신호로 받아들여야 한다. 다만 기존 서비스와 같은 방식으로 장소 핀만 늘리면 차별화가 어렵다. 따라서 데이터 수집 구조, 저작권 안전 정책, 명확한 유료 고객, AI 챗봇, 사용자 방문기를 초기 기획의 중심에 두어야 한다.

최종 방향은 `성지순례 지도 앱`이 아니라 `K-콘텐츠 팬덤 여행 플랫폼`이다.
