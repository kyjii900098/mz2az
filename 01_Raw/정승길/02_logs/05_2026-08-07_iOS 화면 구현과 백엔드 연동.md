## 1. 맥북에어 인수인계 — `git fetch` 만으로는 안 된다

프로에서 푸시하고 에어에서 `just run //apps/scenetrip-ios:bin` 을 돌렸는데 안 됐다.
원인은 단순했다 — **`git fetch` 는 원격 정보만 가져오고 작업 트리는 안 건드린다.**
로컬이 19 커밋 뒤처져 있었고 `apps/` 밑에 `README.md` 하나뿐이라 그 타깃이 존재하지
않았다.

`just doctor` 가 통과한 건 도구 설치만 보기 때문이고, `just check` 가 초록이었던 건
**빌드할 iOS 코드가 아예 없었기** 때문이다. 둘 다 정상처럼 보이는 게 함정이었다.

> 앞으로 두 기계를 오갈 때는 `git fetch` 대신 `git pull` 을 쓴다.

## 2. 네이버 지도 SDK — MapKit 으로 우회하지 않았다

처음에 "Bazel 에 xcframework 를 물리는 게 오래 걸릴 것" 이라며 MapKit 대체를
제안했는데, **확인 없이 추정으로 말한 것**이었다. 실제로는

- 네이버가 SPM 으로 공식 배포한다 (`navermaps/SPM-NMapsMap`)
- `MODULE.bazel` 에 `rules_swift_package_manager` 가 **이미 선언돼 있었다**

경로가 깔려 있었다. 다만 세 군데서 걸렸고 전부 실측으로 풀었다.

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 타일이 한 장도 안 옴 | `clientId`(deprecated)에 키를 넣음 | `ncpKeyId` 로 — flutter_naver_map 도 그렇게 한다 |
| `target does not exist` | rules_swift_package_manager 0.34.0 이 binaryTarget 을 못 옮김 | 1.23.0 으로 올림 |
| Starlark transition 오류 | 리눅스 설정으로 xcframework 를 지으려 함 | `swift_library` 에 `tags = ["manual"]` |

## 3. 화면 — 목데이터로 먼저 세우고 서버로 갈아끼웠다

§3-1 화면 구조, §3-2 검색 범위, §3-3 자동완성, §3-5 카테고리 칩을 목데이터(164 행)로
구현한 뒤, 생성 클라이언트가 붙자 **SceneData 안쪽만 갈아끼웠다.** 화면 코드는
`SceneRow` 만 보게 짜 뒀기 때문에 그렇게 됐다.

### 걷어낸 것 — 검색 로직

목데이터 시절에는 앱이 직접 랭킹을 계산했는데 서버 연동 시점에 **전부 지웠다.**
`GET /contents` 와 `GET /places` 에 같은 `q` 를 넣으면 두 탭이 채워지고,
자동완성도 `GET /search/suggestions` 가 갈래와 랭킹을 정한다.

> 서버가 하는 일을 앱이 다시 구현하면 iOS 와 Android 가 갈린다. ADR 0002 가 검증
> 항목으로 건 바로 그것이다.

앱에 남은 규칙은 **칩 매핑(§3-5)과 오류 화면이 읽는 값(§3-6)** 둘뿐이고, 테스트도
그 둘만 남겼다. §3-2 표의 대칭은 서버 통합 테스트가 지킨다.

### 186 은 내가 잘못 올렸다가 고쳤다

처음에 "백엔드가 빠뜨렸다" 고 적었는데 **사실이 아니었다.**
`services/scene-api/seed/v6.sql:76-77` 에 이유가 명시돼 있다.

```
-- 넣지 않는 컬럼과 이유:
--   scene_image_url   장면 스틸을 담을 테이블이 없다. 저작권 문제로 미도입 (MZ2AZ-111)
```

`information_schema` 만 조회하고 **적재 SQL 의 주석을 읽지 않아** 생긴 오류다.

그런데 그 전제 자체가 지금 단계에 맞지 않는다 — 그 URL 은 실제 장면 스틸이 아니라
수집 단계에서 넣어 둔 대체 이미지이고, MVP1 실험 단계라 배포도 하지 않았다.
**저작권 문구는 문서 네 곳에서 함께 지우기로** 했고 티켓에 목록을 넣었다.

> 배포 시점에 다시 판단할 문제를 지금 스키마 결정의 근거로 남겨 두지 않는다.

## 6. CI — 사흘에 걸쳐 네 번 깨졌다

| 증상 | 원인 | 우리 탓? |
| --- | --- | --- |
| 15 분 뒤 cancelled (스텝 0 개) | macOS 러너 미배정 | GitHub |
| `shellcheck` 없음 | ubuntu 에는 있고 macos 에는 없다 | 우리 |
| `Service Unavailable` | 액션 다운로드 실패 | GitHub |
| `linux-toolchain` 해석 실패 | 리눅스가 Swift 클라이언트를 지으려 함 | 우리 |

두 번은 GitHub 인프라 문제였고 두 번은 우리 문제였다.

**pull_request 이벤트가 통째로 흘려진 적도 있다** — 커밋 두 개가 CI 를 아예 타지 않아
`head_sha` 로 조회해 run 0 개를 확인했다. 그때 다시 돌릴 방법이 없어서
`workflow_dispatch` 를 워크플로에 더했다. 이제 `gh workflow run ci.yml --ref <브랜치>`
로 손으로 돌릴 수 있다.

### Swift 게이트를 어느 잡이 지는가

`.swift` 파일이 하나라도 생기면 `lint.sh`·`format.sh` 가 자동으로 켜지는데, 우분투
러너에는 `swiftlint`·`swiftformat` 이 없어 **다음 PR 부터 죽을 상태**였다.

Swift 검사를 Apple 플랫폼으로 한정했다. 다만 **조용히 건너뛰지는 않는다** —
`lint.sh` 머리말의 "검사해서 통과한 것과 아예 검사하지 않은 것은 다르다" 가 여기에도
걸리므로, 건너뛴 사실과 누가 대신 검사하는지(`verify-macos`)를 함께 남긴다.

## 7. 도커가 꺼져 있어 우연히 잡은 버그

탭바를 확인하려고 앱을 띄웠는데 서버가 내려가 있었고, **오류 화면이 틀려 있었다.**
"요청을 처리하지 못했습니다" 가 뜨고 **재시도 버튼이 없었다** — 정작 재시도가 제일
필요한 상황인데.

생성 클라이언트는 연결 실패를 **음수 코드**로 알린다 (`-1` 연결 실패, `-2` HTTP 응답
아님). 그것을 HTTP 상태 코드로 그대로 넘긴 게 원인이었다. 회귀 테스트를 넣었다.

> 서버를 켜 놓고만 테스트했으면 계속 몰랐을 버그다.

## 8. 구조를 정리하면

도커에 대해 오해가 있어 정리해 둔다.

```
맥북
├── Docker Desktop              ← 컨테이너 엔진일 뿐
│    └── scenetrip-control-plane (kind 노드)
│         ├── postgres-0
│         ├── scene-api         ← :8081
│         └── signoz-*          ← :8080
├── iOS 시뮬레이터               ← 도커 밖
└── Bazel                       ← 빌드 도구, 컨테이너 아님
```

- 컨테이너로 감싼 건 **scene-api 하나**다. iOS 앱은 시뮬레이터에 설치되고,
  `agents/` 는 아직 모듈이 없다.
- CI 는 GitHub Actions 다. 로컬 도커와 무관하다.
- **이미지는 우리 서버에 없다.** `posterUrl`·`imageUrl` 은 TMDB·구글 주소이고 앱이
  직접 받아온다. 도커가 꺼졌을 때 사진이 없던 건 **URL 목록 자체를 못 받아서**다.
