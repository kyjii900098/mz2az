# 촬영지 데이터 수집 작업 기록 (2026-07-28 ~ 07-29)

이 폴더의 CSV 5개는 SceneTrip 촬영지 데이터 수집 세션(2026-07-28~29)의 결과물이다. 원래 `assets/`에 임시로 뒀다가 이 폴더로 정리했다.

## 파일 목록

### 1. `촬영지_수집_kdramamap_전체.csv` — 메인 드라마 촬영지 데이터
- **20,068행**, 드라마·예능 476편(kdramamap.com 가나다순 전체 20페이지)
- 컬럼(15개, 엠지옵시 공유 규격): `id, title, title_aliases, title_category, title_cast, place_name, place_type, place_address, place_latitude, place_longitude, place_image_url, place_naver_url, scene_description, source_url, last_updated`
- 장소명·주소·위경도는 kdramamap 사이트에 임베드된 카카오맵 JSON에서 직접 수집(지오코딩 아님, 신뢰도 높음). 607행은 사이트 자체에 좌표가 없음(해외 촬영지 포함).
- `title_aliases`(영문 제목)는 확실히 아는 것만 채움(약 280편). `place_type`은 장소명 키워드로 확실한 것만(33%).
- `scene_description`은 **1,398행만 채워짐**(아래 "진행 상황" 참고). 나머지는 빈칸.
- 작품 카테고리: kdramamap 사이트가 방송사 필드를 "영화"로 표기한 6편(기생충, 길복순, 뷰티인사이드(영화), 유열의음악앨범, 청년경찰, 추격자)은 `title_category=movie`로 처리, 나머지는 `drama`.

### 2. `촬영지_수집_kdramamap_p14-20.csv` — 위 파일의 부분집합
- **6,978행**, 드라마 164편(가나다순 14~20페이지, 원래 팀 분담에서 사용자 담당분)
- 컬럼·수집 방식은 위와 동일. **전체 파일과 내용이 겹치므로**, 팀에서 병합할 때는 이 파일 대신 `촬영지_수집_kdramamap_전체.csv` 하나만 쓰면 된다(중복 방지용으로 남겨둔 것).

### 3. `촬영지_수집_영화전수.csv` — 영화 마스터 + 일부 촬영지
- **6,943행**, 영화 6,675편(KOBIS 전수 8,536편 중 에로 장르 1,811편 제외)
- 컬럼: 위 15개 + `audience_acc`(누적 관객수, 1,361편에 값 있음) = 16컬럼
- 대부분 행은 **장소 정보가 비어있는 "작품 목록"**이다 — KOBIS가 애초에 촬영지 데이터를 안 주기 때문. 한국문화정보원 공공데이터(아래 4번)와 매칭된 **47편만 실제 촬영지 266곳**이 채워짐(장소명·주소·위경도·장면설명 포함).
- id는 `mv_0001`부터. `source_url`은 KOBIS 상세페이지 링크.

### 4. `한국문화정보원_미디어콘텐츠 영상 촬영지 데이터_20221125.csv` — 원본 공공데이터
- **15,034행**, 사용자가 data.go.kr에서 직접 받은 원본 파일(인코딩 cp949 주의)
- 드라마 7,339 / 예능 5,460 / 아티스트 1,962 / 영화 273행. 2022-11-25 스냅샷이라 그 이후 작품(더글로리, 눈물의여왕, 폭싹 속았수다, 선재업고튀어 등)은 아예 없음.
- 위 1번·3번 파일에 장소명·주소·위경도·장면설명을 채우는 데 소스로 사용함. 원본이라 그대로 보존.

### 5. `드라마_해외인기_TOP100.csv` — 우선순위 선정 목록
- **103편**(103으로 됐지만 사용자가 "숫자는 안 중요하다"고 해서 그대로 둠), kdramamap 476편 중 해외 인기 기준 선정
- 컬럼: `rank, title, title_en, tier, reason, location_rows`
- 등급: **S(25편)** 글로벌 메가히트, **A(66편)** 넷플릭스·디즈니+ Top10급, **B(12편)** 한류 클래식. 선정은 Claude 지식 기반(2025년까지)이라 팀에서 검토·조정 필요.

## 오늘 한 일 (타임라인)

1. kdramamap.com 14~20페이지(사용자 담당분) 크롤링 → `촬영지_수집_kdramamap_p14-20.csv`
2. 사용자 요청으로 1~13페이지도 추가 크롤링 → 전체 476편 통합 → `촬영지_수집_kdramamap_전체.csv`
3. 영화는 `SceneTrip/11_schema/works.csv`(KOBIS 8,536편) 기반, 에로 제외 6,725편으로 `촬영지_수집_영화전수.csv` 생성, `audience_acc` 컬럼 추가
4. **ys-dl.tistory.com(kdramamap 운영자 블로그)에서 scene_description을 가져오려던 시도는 중단.** 이유: 이 블로그가 2026-07-20에 "데이터 무단 이용 경고" 공지를 올림(사전 협의 없는 이용 금지). 그리고 애초에 이 블로그에는 장면 설명 텍스트가 없고 스크린샷 이미지뿐이라 텍스트 수집 자체가 불가능했음.
5. 사용자가 한국문화정보원 공공데이터(4번 파일)를 직접 받아옴 → 영화 47편(266곳)·드라마 107편(844곳)에 장소·장면설명 병합
6. 해외 인기 TOP100(103편) 선정 → `드라마_해외인기_TOP100.csv`
7. **S등급 25편**에 한해 scene_description 웹 리서치를 서브에이전트 병렬 실행으로 진행 (visitkorea, 뉴스, 나무위키, 촬영지 전문 블로그/사이트 등에서 회차·장면 확인, "N화에서 ~하는 장면" 형식 25~90자로 요약, 못 찾으면 빈칸 유지 — 지어내지 않음)
8. 사용자가 중지 요청 → 진행 중이던 리서치 정리 후 병합

## 어디서부터 다시 하면 되는지

### 우선순위 1 — S등급 미착수 2편
- **눈물의여왕**(145곳)과 **내남편과결혼해줘**(117곳)는 전혀 손대지 못했다. `촬영지_수집_kdramamap_전체.csv`에서 `title == "눈물의여왕"` 또는 `title == "내남편과결혼해줘"` & `scene_description` 빈 행을 뽑아서 웹 리서치(visitkorea, 뉴스 기사, 나무위키, 팬 정리 블로그·사이트 등)로 채우면 된다. 형식: "N화에서 ~하는 장면" 25~90자, 확인 안 되면 빈칸 유지(절대 지어내지 않기).

### 우선순위 2 — S등급 절반 이하 8편 보강
중증외상센터(6/33), 지금우리학교는(2/6), 킹더랜드(30/79), 더글로리(53/108), 태양의후예(8/15), 폭싹 속았수다(40/72), 닥터슬럼프(55/121) — 이미 시도했지만 자료 자체가 부족하거나 검색 예산이 부족해서 못 채운 케이스. 재시도하면 몇 곳은 더 나올 수 있다.

### 우선순위 3 — A등급(66편)·B등급(12편) 착수
지금까지 A·B등급은 **한국문화정보원 공공데이터 병합으로만** 일부 채워졌고(2022년 스냅샷 기준이라 최신작은 커버 안 됨), S등급처럼 능동적으로 웹 리서치를 돌린 적은 없다. `드라마_해외인기_TOP100.csv`에서 tier=A, tier=B인 작품들이 다음 대상.

### 우선순위 4 — 영화 우선순위 491편 촬영지
`SceneTrip/11_schema/priority_works.csv`(2000년 이후 & 관객 100만+ 491편)에 대해 촬영지를 채우는 작업은 **아직 시작 안 함**. 한국문화정보원 공공데이터에 매칭되는 영화는 47편뿐이라, 491편 중 나머지는 별도 리서치가 필요하다.

### 참고 — 리서치 품질 메모
- 서브에이전트마다 세션 WebSearch 한도(200회)를 금방 소진해서 이후엔 우회 검색 도구(insane-search 스킬, Jina Reader 등)로 계속 진행함. 주요 소스: hanlyu-map.com, koreandramalocation.com, secretseoul.com, traveltodrama.com, 네이버 블로그 "촬영지 총정리" 글들.
- 일부 결과는 회차·인물까지 구체적으로 확인됐지만("14회에서 김신은..."), 일부는 "지하철역 촬영지" 식 두루뭉술한 카테고리 태그뿐인 경우도 섞여 있다. 특히 **오징어게임2의 30곳 중 27곳**이 이런 저품질 케이스라 한번 검수하고 넘어가는 게 좋다.
- ys-dl.tistory.com(kdramamap 운영자 블로그)은 2026-07-20 데이터 무단 이용 경고 공지가 있으므로, 이 블로그 내용은 사전 협의 없이 그대로 가져다 쓰지 않는다.

## 다른 컴퓨터에서 이어서 하기

**가능하다.** 이 폴더는 Dropbox로 동기화되는 볼트 안에 있어서, 같은 Dropbox 계정으로 로그인한 맥북에어에서도 이 CSV들과 이 README가 그대로 보인다. 단, **아래 두 가지는 이 맥북프로에만 있고 자동으로 안 넘어간다:**

- 이번 세션에서 Claude가 만든 memory 기록(작업 배경 요약)
- 세션 스크래치패드에 있던 크롤링/병합 스크립트(`crawl_kdramamap.py`, `merge_public.py` 등)와 서브에이전트 리서치 중간 결과물(`desc_results/*.json`)

**따라서 재개할 때는 이 README.md 하나만 있으면 된다** — 여기 적힌 파일 설명과 진행 상황표가 곧 인수인계 문서다. 스크립트가 없어도 웹 리서치는 Claude가 그 자리에서 다시 하면 되므로 문제없다.

### 맥북에어에서 새 세션 열 때 입력할 프롬프트

먼저 Dropbox 앱이 이 볼트 폴더(특히 `01_Raw/정승길/data/`)를 완전히 동기화했는지 확인한 뒤(CSV가 8~15MB로 꽤 커서 동기화가 늦을 수 있음), `~/Library/CloudStorage/Dropbox/mz2az` 안에서 Claude Code 세션을 열고 아래처럼 입력:

```
엠지옵시 볼트의 01_Raw/정승길/data/README.md를 읽어줘. SceneTrip 촬영지 데이터 수집 작업을
다른 컴퓨터(맥북프로)에서 하다가 넘어온 거야. README의 "어디서부터 다시 하면 되는지" 섹션
순서대로 이어서 진행해줘 — 지금은 우선순위 1(눈물의여왕, 내남편과결혼해줘 scene_description
채우기)부터 시작하면 돼.

작업 방식은 README에 적힌 대로: 웹 리서치(visitkorea, 뉴스 기사, 나무위키, 촬영지 정리
블로그/사이트 등)로 각 장소가 몇 화 어떤 장면에 나왔는지 확인해서 25~90자 한국어 한 문장으로
촬영지_수집_kdramamap_전체.csv의 scene_description 컬럼을 채워줘. 확인 안 되는 곳은 절대
지어내지 말고 빈칸으로 둬. 앱 지도 핀에 표시할 짧은 설명이라 너무 길게 쓰지 마.
```

이 프롬프트만으로 새 세션이 맥락 없이도 바로 이어갈 수 있다(README에 파일 위치·컬럼·이미 한 일·안 한 일이 다 적혀 있으므로). 진행 중 궁금한 부분이 있으면 이 README의 "리서치 품질 메모" 절도 같이 참고하라고 하면 된다.
