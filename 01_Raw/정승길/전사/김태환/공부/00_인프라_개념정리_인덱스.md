# 인프라 개념 정리 — 인덱스

설치 가이드는 "어떻게 하는가"만 알려주고 "그게 뭔가"는 설명하지 않아서 따로 정리한다.

## 큰 그림 — 왜 이 도구들이 다 필요한가

한 문장으로: **"내 맥에서 되는데 서버에서 안 돼"를 없애기 위해서** 다.

```
문제                              해결 도구
────────────────────────────────────────────────
환경이 사람마다 달라서 안 돌아감   →  컨테이너 (Docker)
컨테이너가 여러 개라 관리가 안 됨  →  쿠버네티스 (Kubernetes)
쿠버네티스를 내 맥에 띄우고 싶음   →  kind
쿠버네티스 앱 설치가 복잡함        →  Helm
장애가 나도 원인을 모르겠음        →  관측성 (SigNoz + OpenTelemetry)
```

각 도구는 **앞 도구가 만든 새로운 문제** 를 푼다. 그래서 순서대로 이해해야 한다.

## SceneTrip에서의 위치

```
로컬 개발 (지금 배우는 것)
└── kind 클러스터 "scenetrip"  ← Docker Desktop 위에서 돌아감
    ├── 네임스페이스 scenetrip  → 우리가 만든 서비스·앱·에이전트
    └── 네임스페이스 signoz     → 관측성 도구

팀 통합 테스트
└── AWS EKS 개발 클러스터      ← 나중에

실제 서비스
└── AWS EKS 스테이징/운영      ← 나중에
```

로컬에서 kind로 배우는 개념이 **EKS에서 그대로 통한다.** kind와 EKS는 같은
쿠버네티스이고, 다른 건 "누가 노드를 제공하느냐"뿐이다. 로컬은 내 맥의 도커
컨테이너, EKS는 AWS의 EC2 인스턴스.
