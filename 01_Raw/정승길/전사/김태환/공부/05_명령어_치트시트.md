# 5. 명령어 치트시트 & 용어 사전

> 개념은 [[00_인프라_개념정리_인덱스]]의 노트들에. 여기는 찾아 쓰는 용도.

## 안전 습관 — 무엇을 하기 전이든

```bash
kubectl config current-context      # kind-scenetrip 인가?
kubectl get nodes                   # Ready 인가?
```

이 두 줄을 확인하고 변경 명령을 실행한다. 특히 `delete`, `apply`, `scale`,
`helm uninstall` 앞에서는 반드시. 같은 kubectl로 운영 EKS도 만지기 때문이다.

## SceneTrip 레시피 (`just`)

SceneTrip에선 **날것의 `bazel`·`kubectl` 대신 `just` 레시피를 쓰는 게 원칙** 이다.

```bash
just --list              # 전체 명령 목록 (그룹별)

# 환경
just setup               # 최초 1회 워크스테이션 세팅
just doctor              # 필수 도구 확인
just cluster-up          # 클러스터 생성 + SigNoz 설치 (멱등, 3~4분)
just cluster-doctor      # 도구·클러스터·SigNoz·워크로드 한 화면
just cluster-test-drive  # 클러스터가 실제로 도는지 확인
just cluster-down        # 전부 삭제
just signoz              # SigNoz UI 주소와 필터 안내

# 빌드·테스트
just build               # 전체 빌드
just test                # 빠른 단위 테스트
just check               # PR 전 게이트 (커밋 전 반드시 초록)
just ci                  # CI가 하는 전부를 로컬에서 재현

# 배포
just image <모듈>         # build + kind load
just deploy <모듈> local  # 로컬 클러스터에 배포
just update <모듈>        # build + load + 롤링 재시작

# 모듈 생성
just new-service <이름>   # services/
just new-app <이름>       # apps/
just new-agent <이름>     # agents/
just modules             # 현재 모듈 목록

# 문서
just slides              # 35슬라이드 강의 덱 열기
```

## Docker


## kubectl — 조회

```bash
kubectl get pods                    # 현재 네임스페이스
kubectl get pods -n signoz          # 특정 네임스페이스
kubectl get pods -A                 # 전체
kubectl get pods -o wide            # IP·노드까지
kubectl get pods --watch            # 상태 변화 실시간

kubectl get all                     # Pod/Service/Deployment 한꺼번에
kubectl get nodes
kubectl get namespaces
kubectl get svc                     # 서비스
kubectl get pvc                     # 저장소
kubectl get events --sort-by=.lastTimestamp | tail -10
```

## kubectl — 디버깅 3종

문제가 생기면 **항상 이 순서** 다.

```bash
kubectl get pods                    # 1. 상태가 뭔가?
kubectl describe pod <이름>          # 2. 하단 Events에 이유가 있음
kubectl logs <이름>                  # 3. 앱 자체의 오류
```

```bash
kubectl logs -f <Pod>                       # 실시간
kubectl logs <Pod> --previous               # 죽기 전 로그 (CrashLoopBackOff 때)
kubectl logs -f deployment/<이름>            # Deployment 단위
kubectl logs <Pod> -c <컨테이너>             # 컨테이너 여러 개일 때
kubectl exec -it <Pod> -- /bin/sh           # 안으로 들어가기
```

## kubectl — 변경

```bash
kubectl apply -f <파일 또는 디렉터리>
kubectl delete -f <파일>
kubectl delete pod <이름>

kubectl rollout restart deployment/<이름>    # 롤링 재시작
kubectl rollout status  deployment/<이름>    # 진행 상황
kubectl rollout undo    deployment/<이름>    # 되돌리기
kubectl rollout history deployment/<이름>

kubectl scale deployment/<이름> --replicas=3
kubectl scale statefulset,deployment --all --replicas=0 -n signoz   # 재우기
```

## kubectl — 컨텍스트·네임스페이스

```bash
kubectl config current-context
kubectl config get-contexts
kubectl config use-context kind-scenetrip

kubectl config set-context --current --namespace=scenetrip   # 기본 ns 변경
kubectl config view --minify --output 'jsonpath={..namespace}'   # 현재 ns 확인
```

## kubectl — 포트 연결

```bash
kubectl port-forward service/<이름> 8080:80
kubectl port-forward -n signoz svc/signoz-ingester 4317:4317 4318:4318
```

> [!warning] SceneTrip에서 8080·8081은 port-forward 하지 말 것
> kind 포트 매핑이 이미 잡고 있다. 겹치면 리스너가 둘 생긴다.

## k9s — 터미널 UI

`kubectl get/describe/logs` 를 반복 입력하는 대신 한 화면에서 본다.

```bash
k9s                        # 현재 컨텍스트
k9s -n <네임스페이스>
k9s -A                     # 전체 네임스페이스
k9s --readonly             # 읽기 전용 (공용 클러스터 볼 때 권장)
```

| 키 | 동작 |
| --- | --- |
| `:pod` `Enter` | Pod 목록 (`:deploy`, `:svc`, `:ns`, `:ev` 등도 동일) |
| `/` | 현재 목록에서 검색 |
| `d` | describe |
| `l` | 로그 |
| `s` | 컨테이너 셸 |
| `y` | YAML 보기 |
| `Esc` | 뒤로 |
| `?` | 도움말 |
| `:q` | 종료 |

> [!danger] `Ctrl + d` 는 삭제다
> 확인 절차가 짧아 실수하기 쉽다. 로컬 `kind-scenetrip` 이 아닌 곳에선 쓰지 말 것.

## SigNoz 로그 검색

```text
service.name = scenetrip-scene-api AND severity_text = ERROR
service.name IN (scenetrip-scene-api, scenetrip-trip-planner)
body CONTAINS "timeout"
trace_id EXISTS
trace_id = <TRACE_ID>
```

연산자: `=` `!=` `IN` `NOT IN` `CONTAINS` `EXISTS` / 조합: `AND` `OR`

## 용어 사전

### 컨테이너

| 용어 | 뜻 |
| --- | --- |
| **이미지** | 실행에 필요한 파일·설정의 읽기 전용 스냅샷 (설계도) |
| **컨테이너** | 이미지를 실행한 상태 (실체) |
| **Dockerfile** | 이미지 만드는 레시피 |
| **레이어** | Dockerfile 한 줄이 만드는 캐시 단위 |
| **레지스트리** | 이미지 보관소 (Docker Hub, AWS ECR) |
| **태그** | 이미지 버전 이름 (`scene-api:dev`) |

### 쿠버네티스

| 용어 | 뜻 |
| --- | --- |
| **클러스터** | 쿠버네티스 전체 한 덩어리 |
| **노드** | 컨테이너가 실제로 도는 머신 (kind에선 도커 컨테이너) |
| **컨트롤 플레인** | 클러스터의 두뇌 (API Server, Scheduler, Controller, etcd) |
| **Pod** | 배포의 최소 단위. 컨테이너 1개 이상을 감싼 껍데기 |
| **ReplicaSet** | Pod 개수를 유지 |
| **Deployment** | ReplicaSet 관리 + 롤링 업데이트·롤백 |
| **StatefulSet** | 상태 있는 앱용. 이름·저장소가 고정 (DB 등) |
| **Job** | 한 번 실행하고 끝나는 작업. `Completed` 가 정상 |
| **Service** | Pod 앞에 붙는 고정 접근점 + 로드밸런싱 |
| **ClusterIP** | 클러스터 내부 전용 Service (기본값) |
| **NodePort** | 노드 포트로 외부 노출 (30000~32767) |
| **Namespace** | 클러스터 안의 논리적 구획 |
| **ConfigMap** | 일반 설정값 |
| **Secret** | 민감 정보 (base64 인코딩일 뿐, 암호화 아님) |
| **PV / PVC** | 영구 저장소 / 그 요청서 |
| **StorageClass** | 저장소를 자동 생성해주는 방식 |
| **라벨(label)** | 리소스에 붙이는 키·값. Service가 Pod를 찾는 기준 |
| **매니페스트** | 원하는 상태를 적은 YAML 파일 |
| **선언적** | 명령이 아니라 "원하는 상태"를 쓰는 방식 |
| **조정 루프** | 원하는 상태 ↔ 실제 상태를 계속 맞추는 반복 |
| **컨텍스트** | kubectl이 지금 보고 있는 클러스터 |
| **멱등** | 여러 번 실행해도 결과가 같음 |

### 관측성

| 용어 | 뜻 |
| --- | --- |
| **관측성** | 밖에서 나오는 데이터만으로 내부 상태를 알 수 있는 정도 |
| **로그 / 메트릭 / 트레이스** | 세 가지 신호 |
| **트레이스** | 요청 하나의 전체 여정 |
| **스팬** | 트레이스 안의 개별 작업 단위 |
| **trace_id** | 요청 하나를 식별하는 ID. 로그와 트레이스를 잇는 열쇠 |
| **OpenTelemetry(OTel)** | 관측 데이터를 만들고 보내는 표준 |
| **OTLP** | OTel 전송 프로토콜. 4317(gRPC) / 4318(HTTP) |
| **Collector** | 데이터를 받아 처리·전달하는 중계기 |
| **자동 계측** | 코드를 안 고치고 에이전트만 붙여 계측 |
| **`service.name`** | 데이터의 출처 서비스 이름. 검색 1차 키 |
| **ClickHouse** | SigNoz가 쓰는 컬럼형 DB |
| **foundryctl** | SigNoz 설치 CLI |

### Pod 상태

| 상태 | 의미 |
| --- | --- |
| `Running` | 정상 |
| `Pending` | 배치 못 함 — 리소스 부족 / PVC 대기 |
| `ContainerCreating` | 이미지 받고 컨테이너 만드는 중 |
| `Completed` | 정상 종료 (Job은 이게 정상) |
| `CrashLoopBackOff` | 켜자마자 죽기를 반복 — 앱 오류. 로그 확인 |
| `ImagePullBackOff` | 이미지를 못 받음 — 이름 오타 / 인증 |
| `ErrImageNeverPull` | **`kind load` 안 함** |
