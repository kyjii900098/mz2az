## IMG_0844 — 1쪽 「컨텐츠 모델링」

좌상단에 제목 **`컨텐츠 모델링`** 이 쓰여 있다. 페이지는 크게 네 덩어리로 나뉜다.

### ① 상단 — 엔티티 3개

가로로 박스 3개가 놓이고 각각 제목이 대괄호로 묶여 있다.

```
[ 드라마 장면 ]        [ Place ]              [ 코스 ]
 ┌──────────┐        ┌──────────┐         ┌──────────────┐
 │ [영상?]    │ ⋯      │ [ 이미지 ]  │        │ ① 드라마 - Place │
 │ [(판독불가)]│        │ [설명|위치정보]│       │   [ Plan ]      │
 └──────────┘        └──────────┘         │ ② (판독 불가)    │
                                           │ ③ (판독 불가)    │
        └──── 1 : N ────┘                  │ ④ (판독 불가)    │
                                           └──────────────┘
                                                   ↑
                                                (판독 불가)
```

- **`[드라마 장면]`** 박스 안에는 작은 박스 2개가 세로로 있다. 위 칸은 `영상` 으로 읽히고, 아래 칸은 판독 불가
- **`[Place]`** 박스 안에는 위에 **`이미지`**, 아래에 **`설명`** 과 **`위치정보`** 가 세로선으로 나뉘어 있다
- 드라마 장면과 Place 사이 아래쪽에 **`1 : N`** 이 적혀 있다
- **`[코스]`** 박스의 첫 줄은 **`① 드라마 - Place`**, 그 아래 **`[Plan]`** 박스, 이어서 ②③④ 번호가 붙은 빈 줄 3개(내용 판독 불가)
- 각 박스 제목 위에는 체크 표시(✓)가 하나씩 그어져 있다

> [!note] 7/24 화이트보드와의 관계
> 3일 뒤 `47_07.24 화이트보드 (MVP1 데이터 모델).md` 에서 **장면 · 장소 · 코스** 3개 엔티티와 **1:N** 관계가 그대로 다시 나온다. 이 스케치가 그 데이터 모델의 출발점으로 보인다. (해석)

### ② 좌중단 — `Data Source`

```
[ Data Source ]     ← 박스, 밑줄
① (판독 불가) 영상?
② 영화 (판독 불가) 씬 ⋯
③ ⋯ (판독 불가) ⋯
```

번호 3개가 붙은 목록이지만 낱말을 확정할 수 없다. 오른쪽에 중괄호 `}` 로 셋을 묶고 **`→`** 화살표가 우측 블록으로 이어진다.

### ③ 우중단 — 화살표가 향하는 블록

화살표가 도착하는 곳 위에 제목이 있는데 **`컨텐츠 후?`** 로만 읽힌다(판독 불확실).

```
[ 드라마 장면 ]   ← 밑줄
      |
   [ Place ]
                  ┌─────────────────────┐
        (원)      │ ① (판독 불가) 영상?    │
                  │ ② [ (판독 불가) ]      │
                  │ ③ [ 관광 연결 매핑? ]  │
                  │ ④ [ Local 등등? ]     │
                  └─────────────────────┘
                          Num + 1
```

블록 오른쪽 아래에 **`Num + 1`** 이 적혀 있다. ③④의 낱말은 획만 보고 옮긴 것이라 신뢰하기 어렵다.

### ④ 하단 — 「상용화 시나리오」

제목이 **`상용화 시나리오`** 로 읽힌다(판독 불확실). 아래에 ①②③ 세 갈래가 있다.

- **①** — 짧은 낱말 2개(`앱`, `신뢰`로 읽힘) + 아래에 박스 2개
- **②** — `컨텐츠 3사` 로 읽히는 제목 + 박스 3개가 세로로 쌓여 있고, 오른쪽에 `배포` 와 **`12. @`** 로 읽히는 표기
- **③** — `등등 시나리오` 로 읽히는 제목 + `○ [ 드라마에 씬 ]` + 아래 `드라마` 라고 쓴 뒤 박스 3개(`유명`, `연예에`, `⋯`)

페이지 맨 아래에는 박스 안에 **`Place`** 라고 쓴 것과, 오른쪽에 **타원 6개를 가로로 늘어놓고 그 아래 `1 2 3 4 5` 라고 번호를 매긴 그림** 이 있다. 순서가 있는 코스를 표현한 것으로 보인다.

## IMG_0845 — 2쪽 「② My Course, 여행 등록」

좌상단 제목은 **`② My Course, 여행 등록`** 이다(`My Course` 는 영문이라 확실).

### ① 상단 — 화면 와이어프레임

- 왼쪽: 빈 사각형 6개를 **3열 × 2행** 으로 배치. 각 사각형 좌상단에 작은 표시가 있다 (카드 그리드 화면으로 보인다)
- 오른쪽: 세로로 긴 사각형 안에 **가로줄 5개** — 목록(List) 화면. 위에 **`List`** 라고 적혀 있고 그 위 낱말은 판독 불가
- 맨 오른쪽: 세로 박스 안에 위쪽 `(판독 불가)`, 아래쪽 **`Place`**

### ② 중단 — MVP 단계 표 (이 자료의 핵심)

표 위에 가로로 긴 낱말 몇 개가 있으나 판독 불가.

| | **MVP #1** | **MVP #2** | **MVP #3 ?** |
| --- | --- | --- | --- |
| **Data** | 드라마<br>(판독 불가) | 드라마 + POP<br>(판독 불가) | **?** |
| **기능** | (판독 불가)<br>(판독 불가)<br>**My Course** | (판독 불가)<br>**개인화 추천** | (판독 불가) 데이터 체계<br>(판독 불가)<br>(판독 불가) |
| (행 제목 판독 불가) | (판독 불가)<br>장면 코스 (판독 불가) | **개인화 추천** | 여행 계획 (판독 불가) |

확실히 읽히는 것만 추리면 이렇다.

- 열 제목이 **`MVP #1` · `MVP #2` · `MVP #3`**(세 번째는 물음표가 함께 붙어 있어 미확정 표시) 3단계다
- 행 제목은 **`Data`** 와 **`기능`** 이다
- MVP #1의 Data는 **`드라마`**, MVP #2의 Data는 **`드라마 + POP`** 다. 즉 **1단계는 드라마만, 2단계에서 K-POP을 더한다**
- MVP #1 기능에 **`My Course`** 가 들어간다
- MVP #2 기능에 **`개인화 추천`** 이 들어간다
- MVP #3 칸은 Data가 **`?`** 로만 표시돼 있다 — 이 시점에 정하지 않았다

> [!question] 판독 불가 구간
> 각 칸의 나머지 한글 낱말은 흘림체라 확정하지 못했다. 특히 MVP #1 기능 칸의 두 항목과 MVP #3 열 전체가 그렇다.
> **MVP 단계를 나누는 이 논의 자체는 음성 전사본에 그대로 남아 있다** — `박재범 요약.md` 의 "MVP 계획을 수립해서 … 뭘 MVP 1까지 하고 2까지 할 건지 그다음에 데이터는 어떻게 할 건지 이 세 가지로 접근해 가지고 갈래를 쳐야 함", "8월달까지의 개발 범위 설정" 대목과 대응한다. 표의 빈칸은 그쪽에서 채우는 편이 정확하다.

## 이 두 장에서 사실로 읽을 수 있는 것

1. 컨텐츠 모델을 **드라마 장면 · Place · 코스** 3개 엔티티로 잡았고, 장면과 Place는 **1:N** 이다
2. Place는 **이미지 · 설명 · 위치정보** 를 갖는다
3. 코스의 첫 항목이 **`드라마 - Place`** 연결이고 그 아래 **Plan** 이 붙는다
4. MVP를 **#1 / #2 / #3** 세 단계로 쪼갰고, 각 단계를 **Data 축과 기능 축** 으로 나눠 적었다
5. **MVP #1 = 드라마 데이터 + My Course**, **MVP #2 = 드라마 + POP 데이터 + 개인화 추천**, **MVP #3 = 미정(`?`)**
6. 코스는 순서가 있는 장소들의 나열(타원 + 1 2 3 4 5)로 표현했다
