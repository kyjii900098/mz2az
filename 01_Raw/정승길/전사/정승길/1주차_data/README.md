## 다음 작업 계획 — 2026-07-30 확정 (실행 전)

### 확정된 기준

- **드라마**: 전수(20,068행)는 DB에 전부 유지(검색 노출용). 앱 기본 노출은 **유명 TOP100 + 최신 12개월 TOP20** (교집합 허용, 120 미만이어도 무방)
  - TOP100 = ① MyDramaList ② IMDB ③ 위키미디어 PageViews API 각각 100개 → **보르다 합산, 2개+ 소스 등장 우선** 으로 조합. 기존 `드라마_자체선정_TOP100초안.csv`(Claude 지식 기반)는 이 결과로 검증·대체
  - 최신 TOP20 = 오늘 기준 12개월 내 방영작을 같은 3원 소스로 랭킹
- **영화**: 인기작만 DB에 넣는다 — **누적 관객수 100만+** 또는 **수상작**(칸·베니스·베를린·아카데미 + 청룡·대종·부산국제영화제). 최신 개봉작은 KOBIS 재조회로 보강(기존 수집 6월 말 이후분), 채택작은 장소·주소·위경도 채움
- **스키마 추가 4컬럼**: `famous_rank`(유명 TOP100 순위) · `recent_rank`(최신 TOP20 순위) · `audience_acc`(관객수) · `award`(수상 내역). 교집합 작품은 두 rank 모두 채움. ⚠️ 팀 스키마(MZ2AZ-111) 변경이므로 태환·권호 공유 필요 — 승길 담당
- **place URL**: TOP 작품만 대상, **카카오 로컬 API** 로 place 직링크 확보(좌표 출처가 카카오라 매칭 정확도 최고, 프록시 경유 키 불필요). 구글 place_id 병행 여부는 8/1 회의 안건
- **장면 설명**: TOP100·TOP20 확정 후 그 목록 기준으로 우선순위 재정렬해 이어서 진행 (위 "어디서부터 다시 하면 되는지" 절 참고)

### 실행 구조 (병렬·모델 배치)

```
[1단계 — 5개 병렬, 전부 Sonnet]
 A. MDL TOP100      B. IMDB TOP100      C. PageViews 랭킹(스크립트)
 D. 최신 12개월 TOP20  E. 영화 KOBIS 최신 보강
[1.5단계 — 메인 세션 직접] 3원 조합 → TOP100·TOP20 확정
[2단계 — 병렬, Sonnet] F. 장면 설명(작품 단위 분할)  G. place URL 카카오 배치
 → F·G는 같은 CSV를 건드리므로 샤드 파일로 받아 마지막에 병합
```

- **Fable 5 불필요** — 리서치·스크립트는 전부 Sonnet. 상위 모델은 장면 설명 표본 검수(작품당 몇 건)에만
- 리서처 예산 상한을 프롬프트에 명시할 것: "장소당 검색 2회, 소스 2개 확인되면 중단"

## 어디서부터 다시 하면 되는지

### 우선순위 1 — S등급 미착수 2편 → ✅ 완료 (7/30)
- 눈물의여왕 79/145, 내남편과결혼해줘 45/117 채움. 설명 출처(desc_source_url)는 `조합작업/장면설명/장면설명_*.csv` 4개 샤드에 보존. 빈칸은 2회 검색 내 출처 미확인분(독일 로케이션 ~15곳, 브랜드 매장 카메오 등) — 재시도해도 큰 추가 수확은 기대 어려움.

### 우선순위 2 — S등급 절반 이하 8편 보강 → ✅ 완료 (7/30)
+103곳 보강 (킹더랜드 +35, 더글로리 +35, 닥터슬럼프 +19, 폭싹 +11, 중증외상 +2, 지우학 +1, 태양의후예 +0) + 오징어게임2 저품질 42곳 재작성 + 신규수집 빈칸 41곳. 잔여 빈칸은 "촬영 확인만 되고 장면 서술이 어디에도 없는" 케이스가 대부분이라 **추가 리서치 수확 기대 낮음 — 사실상 종결.** 설명 출처는 `조합작업/장면설명/장면설명_B2_*.csv` 6개 샤드에 보존.

### 우선순위 3 — A등급(66편)·B등급(12편) 착수 → 🔄 웨이브 1 완료 (7/30)
지금까지 A·B등급은 **한국문화정보원 공공데이터 병합으로만** 일부 채워졌고(2022년 스냅샷 기준이라 최신작은 커버 안 됨), S등급처럼 능동적으로 웹 리서치를 돌린 적은 없다. `드라마_자체선정_TOP100초안.csv`에서 tier=A, tier=B인 작품들이 다음 대상.

- **웨이브 1 (7/30 완료)**: 상위 유명도 14작품 253곳 리서치 → **56 채움 (22%)**, 본체 2개 CSV에 병합 완료. 설명 출처는 `조합작업/장면설명/장면설명_W1_*.csv` 4개 샤드에 보존.
- ⚠️ **채움률이 S등급(48~54%)의 절반 이하.** 원인은 자료 자체의 부족 — 구작(시그널·피노키오·힐러 등)은 당시 촬영지 포스팅이 네이버 검색 인덱스에서 밀려나 있고, 소상점·골목류 스팟은 장면 단위 서술 자료가 애초에 없음. **2차 웨이브(미지의서울 139곳, 엄마친구아들 104곳 등 대형 잔여 ~2,580곳)는 이 채움률을 전제로 비용 대비 수확을 판단할 것** — 최신작 위주로 선별하면 채움률이 오를 여지 있음.

### 우선순위 4 — 영화 우선순위 491편 촬영지
`SceneTrip/11_schema/priority_works.csv`(2000년 이후 & 관객 100만+ 491편)에 대해 촬영지를 채우는 작업은 **아직 시작 안 함**. 한국문화정보원 공공데이터에 매칭되는 영화는 47편뿐이라, 491편 중 나머지는 별도 리서치가 필요하다.

### 참고 — 리서치 품질 메모
- 서브에이전트마다 세션 WebSearch 한도(200회)를 금방 소진해서 이후엔 우회 검색 도구(insane-search 스킬, Jina Reader 등)로 계속 진행함. 주요 소스: hanlyu-map.com, koreandramalocation.com, secretseoul.com, traveltodrama.com, 네이버 블로그 "촬영지 총정리" 글들.
- 일부 결과는 회차·인물까지 구체적으로 확인됐지만("14회에서 김신은..."), 일부는 "지하철역 촬영지" 식 두루뭉술한 카테고리 태그뿐인 경우도 섞여 있다. 특히 **오징어게임2의 30곳 중 27곳**이 이런 저품질 케이스라 한번 검수하고 넘어가는 게 좋다.
- ys-dl.tistory.com(kdramamap 운영자 블로그)은 2026-07-20 데이터 무단 이용 경고 공지가 있으므로, 이 블로그 내용은 사전 협의 없이 그대로 가져다 쓰지 않는다.

## 다른 컴퓨터에서 이어서 하기

**가능하다.** 이 폴더는 Dropbox로 동기화되는 볼트 안에 있어서, 같은 Dropbox 계정으로 로그인한 맥북에어에서도 이 CSV들과 이 README가 그대로 보인다. 단, **아래 두 가지는 이 맥북프로에만 있고 자동으로 안 넘어간다:**

- 이번 세션에서 Claude가 만든 memory 기록(작업 배경 요약)
- 세션 스크래치패드에 있던 크롤링/병합 스크립트(`crawl_kdramamap.py`, `merge_public.py` 등)와 서브에이전트 리서치 중간 결과물(`desc_results/*.json`)

**따라서 재개할 때는 이 README.md 하나만 있으면 된다** — 여기 적힌 파일 설명과 진행 상황표가 곧 인수인계 문서다. 스크립트가 없어도 웹 리서치는 Claude가 그 자리에서 다시 하면 되므로 문제없다.

### 맥북에어에서 새 세션 열 때 입력할 프롬프트

먼저 Dropbox 앱이 이 볼트 폴더(특히 `01_Raw/정승길/data/`)를 완전히 동기화했는지 확인한 뒤(CSV가 8~15MB로 꽤 커서 동기화가 늦을 수 있음), `~/Library/CloudStorage/Dropbox/mz2az` 안에서 Claude Code 세션을 열고 아래처럼 입력:

```
엠지옵시 볼트의 01_Raw/정승길/data/README.md를 읽어줘. SceneTrip 촬영지 데이터 수집 작업을
다른 컴퓨터(맥북프로)에서 하다가 넘어온 거야. README의 "어디서부터 다시 하면 되는지" 섹션
순서대로 이어서 진행해줘 — 지금은 우선순위 1(눈물의여왕, 내남편과결혼해줘 scene_description
채우기)부터 시작하면 돼.

작업 방식은 README에 적힌 대로: 웹 리서치(visitkorea, 뉴스 기사, 나무위키, 촬영지 정리
블로그/사이트 등)로 각 장소가 몇 화 어떤 장면에 나왔는지 확인해서 25~90자 한국어 한 문장으로

지어내지 말고 빈칸으로 둬. 앱 지도 핀에 표시할 짧은 설명이라 너무 길게 쓰지 마.
```

이 프롬프트만으로 새 세션이 맥락 없이도 바로 이어갈 수 있다(README에 파일 위치·컬럼·이미 한 일·안 한 일이 다 적혀 있으므로). 진행 중 궁금한 부분이 있으면 이 README의 "리서치 품질 메모" 절도 같이 참고하라고 하면 된다.
