## 왜 지금 것이 부족한가 (방향 정리)

1. **스택 불일치**: 기획서 확정 스택은 **Flutter 모바일 앱(iOS/Android)**. 지금까지 만든 건 React 웹 목업. Standalone.html은 화면 레퍼런스로만 쓰고, 실제 개발은 Flutter로 새로 시작해야 함.
2. **IA(정보구조)가 뒤집힘**: 기존 목업은 **지도-first**(첫 화면=지도+핀). 박재범 멘토님 지적은 "지도만 뜨면 사용자가 뭘 해야 할지 모른다" → **콘텐츠-first**로 재설계 필요:
   `카테고리(드라마) → 작품 목록 → 장면 리스트 → 장면 상세(담기) → 마이코스 편집 = 나만의 코스`
   (선호도 조사는 MVP1에서 부차적 → 후순위. 탐색과 플랜은 별개 단계.)
3. **MVP1 범위** (박재범 로드맵 기준): 데이터=드라마만·자동생성 콘텐츠만 / 기능=**앱 메인 + 장면 탐색 + 마이코스**. 커뮤니티·루트마켓·선호도 개인화·경로 최적화는 MVP2~3. LLM 플래너 어시스턴트는 차별화 포인트지만 MVP1 스트레치로.
4. **다국어는 처음부터**: 외국인 타겟이면 필수. 로케일(EN 우선) 코드가 데이터 모델·화면 메시지 처리에 처음부터 들어가야 함 — 나중에 붙이면 대공사.
5. **일하는 방식**: 계획 먼저 완벽히 짜지 말고 **손대서 속도 감부터** → 그 감으로 **3일 블록 × 4주** 계획을 셋이 합의(금요일). 문서(설계서)로 명시화해서 멘토링 때 설명 30분 아끼기. Jira(SCRUM, 프론트 에픽 SCRUM-19)에 반영.
