# 피드백 정리

# 현재 결정된 방향
애니메이션 성지순례 아이디어는 일본 중심으로 흐를 가능성이 커서, 한국 맥락에서는 **K-컬쳐 / 국뽕 / 외국인 관광객 / 국내 드라마·영화·뮤직비디오 촬영지** 로 방향을 트는 것이 더 설득력 있다.

정리하면 현재 아이디어는 다음과 같다.
- 외국인 관광객 또는 K-콘텐츠 팬이 한국 여행 전/중/후에 사용할 수 있는 서비스
- 기존 지도 위에 일반 핀을 찍는 수준이 아니라, 콘텐츠 장면과 결합된 **비주얼 맵** 제공
- 각 촬영지 노드에 작품명, 장면 설명, 이미지/영상 레퍼런스, 방문 정보, 주변 정보 배치
- 여러 노드를 연결해 일정, 이동 시간, 주변 맛집/카페/체험을 포함한 루트 추천
- 장면 검색, 이미지 검색, 자연어 검색, 개인화 추천, 여행 후 콘텐츠 생성까지 확장 가능

핵심 포지셔닝은 **"K-콘텐츠 장면을 실제 여행 동선으로 바꿔주는 AI 비주얼 맵/루트 플래너"** 로 잡는 것이 가장 자연스럽다.

# 한 줄 결론
주제 자체는 통과 가능성이 있고, 참신함과 확장성도 있다. 다만 그냥 "촬영지 지도 앱"으로 보이면 약하다. 반드시 **데이터 확보 방식, 저작권 대응, AI가 실제로 하는 일, 외국인 유저 확보, BM** 을 구체화해야 한다.

특히 심사/기획서에서는 다음 프레임으로 밀고 가는 것이 좋다.
- 단순 지도 서비스가 아니라 **콘텐츠 장면 기반 비주얼 맵** 이다.
- 단순 LLM 챗봇이 아니라 **촬영지 데이터 구조화 + 멀티모달 검색 + 이동 동선 최적화** 를 한다.
- 단순 관광지 추천이 아니라 **K-콘텐츠 소비를 실제 관광 소비로 전환** 한다.
- 전국 전체를 처음부터 다 하지 말고, **부산 또는 서울/부산의 대표 K-콘텐츠 몇 개로 MVP** 를 만든다.

# 긍정적인 피드백
## 1. 방향 전환 자체는 좋다
애니메이션 성지순례는 거의 일본 중심이 되기 쉬운데, 한국에서는 드라마, 영화, 뮤직비디오, K-pop, K-culture로 전환하는 것이 더 자연스럽다는 피드백이 반복됐다.

특히 외국인 관광객을 대상으로 하면 한국어 정보 탐색, 지도 사용, 이동 동선, 장소 검증, 번역, 현지 맛집/카페 선택에서 실제 불편함이 생긴다. 이 불편함은 한국인보다 외국인에게 더 크기 때문에 문제 정의가 성립한다.

## 2. 아이디어가 억지스럽지는 않다
"파편화된 촬영지 정보", "기존 지도 서비스의 한계", "촬영지 정보를 여행 동선으로 연결해야 하는 불편함"이라는 문제 제기는 거부감이 크지 않다는 피드백이 있었다.

즉 문제 자체는 설득 가능하다. 다만 정성적인 주장으로만 두면 약하므로, 방한 외국인 증가, K-콘텐츠 영향, 촬영지 방문 사례, 외국인 여행 검색 행태 같은 근거를 붙여야 한다.

## 3. 콘텐츠와 결합된 지도는 직관적이다
그냥 텍스트 설명보다, 지도 위에 촬영지 노드를 찍고 장면 정보와 루트를 함께 보여주면 데모가 직관적이다.

심사위원에게도 "이 장면이 여기이고, 지도에서는 이렇게 보이고, 클릭하면 이렇게 방문 정보와 루트가 나온다"를 보여주면 설명이 빠르다. 특히 기획서나 발표 자료에 간단한 시각화 예시를 넣으면 이해도가 올라갈 수 있다.

## 4. 명확한 선점 사업자가 없어 보이는 점은 기회다
핀맵, 블로그, 팬 커뮤니티, 기존 지도 서비스, 관광 정보 사이트는 존재하지만, K-콘텐츠 장면 중심으로 지도와 루트 추천까지 결합한 뚜렷한 상업 서비스는 강하게 떠오르지 않는다는 피드백이 있었다.

물론 "왜 아직 없을까?"라는 역질문도 필요하지만, 동시에 신생 서비스로 들어갈 수 있는 빈 공간이 있다는 의미이기도 하다.

## 5. B2C뿐 아니라 B2B 가능성이 있다
외국인 사용자가 직접 쓰는 앱뿐 아니라, 관광사, 지자체, 여행사, 로컬 상권, 촬영지 주변 식당/카페/체험 업체와 연결될 수 있다.

특히 핫한 드라마나 뮤직비디오가 뜰 때 관련 장소를 빠르게 큐레이션하고 여행 상품으로 묶어주는 방식은 B2B 가능성이 있다. 기존에는 수동으로 오래 걸리던 큐레이션을 AI 기반으로 줄이면 여행사나 관광 관련 기관에 제공할 수 있다.

## 6. 부산 특화는 좋은 선택지가 될 수 있다
전국 단위로 시작하면 너무 넓고 산만하다. 반대로 부산은 팀의 지역성, 부산센터의 의미, 실제 외국인 관광객 증가, 바다/야경/맛집/축제/영화제/촬영지 자원이 있어 MVP 범위로 설득력이 있다.

"부산에 온 외국인이 비효율적으로 다니는 문제"를 해결하는 서비스로 잡고, 그 안에 K-콘텐츠 촬영지, 맛집, 축제, 사진 스팟을 녹이는 방향도 가능하다.

## 7. 주제 자체는 포트폴리오로 살릴 여지가 있다
데이터 수집, 검색, 추천, 지도, 경로, 멀티모달, RAG, Agent, 백엔드 운영툴, 모바일 UX까지 엮을 수 있기 때문에 팀원별 포트폴리오 요소를 만들기 좋다.

특히 단순 CRUD가 아니라 "비정형 정보를 구조화하고, 지도/검색/추천/AI 워크플로우로 서비스화했다"는 경험을 만들 수 있다.

# 부정적인 피드백 / 리스크
## 1. 가장 큰 리스크는 저작권이다
드라마, 영화, 뮤직비디오 장면을 이미지나 영상으로 직접 제공하려면 저작권 문제가 생길 수 있다. 특히 서비스 화면에 장면 캡처, 영상 클립, 배우 이미지 등을 직접 올리는 방식은 위험하다.

따라서 처음부터 저작권 회피 설계가 필요하다.
- 공식 유튜브 영상, 공식 예고편, 공식 이미지, 공개 홍보자료 중심 사용
- 원본 업로드 대신 링크/임베드/출처 표시 중심 설계
- 장면 자체를 복제하기보다 장면 설명, 위치 정보, 사용자 사진, 지도 정보 중심 제공
- 사용자가 올리는 이미지/정보는 신고/검수/삭제 플로우 필요
- 자유멘토링이나 법률 멘토에게 "어디까지 가능한지" 짧게 확인 필요

## 2. 촬영지 데이터 확보가 생각보다 어렵다
이 서비스의 핵심은 데이터다. 촬영지 데이터가 부족하거나 틀리면 서비스 신뢰가 바로 무너진다.

문제는 촬영지 정보가 블로그, SNS, 커뮤니티, 기사, 유튜브, 팬덤 글에 흩어져 있고, 작품명/장면/좌표/정확한 장소명/방문 가능 여부가 구조화되어 있지 않다는 점이다.

특히 "사진이나 장면을 넣었는데 우리가 가진 DB에서 결과가 안 나오면" 사용자는 서비스가 별로라고 느끼고 이탈할 수 있다.

## 3. 콘텐츠 풀이 충분한지 검증해야 한다
K-콘텐츠 기반으로 여행할 사람이 얼마나 되는지, 서울/부산 안에서 서비스로 만들 만큼 촬영지 풀이 풍부한지 의문이 제기됐다.

외국인이 한국에 오는 데 K-콘텐츠가 영향을 주는 것은 맞지만, 실제로 "특정 드라마/영화/뮤비 촬영지만 따라다니는 여행"이 충분히 큰 시장인지 검증해야 한다.

이를 보완하려면 촬영지만 고집하지 말고, 다음처럼 확장해야 한다.
- K-콘텐츠 촬영지
- 외국인이 좋아하는 한국 로컬 스팟
- 맛집/카페/축제/야경/사진 스팟
- K-pop, 뮤비, 예능, 쇼핑, 뷰티, 체험
- 부산 또는 특정 도시의 자유여행 코스

즉 "촬영지 앱"보다 "K-콘텐츠 기반 한국 여행 큐레이션"으로 넓히는 것이 안전하다.

## 4. 한 번 쓰고 이탈하는 앱이 될 수 있다
외국인 관광객은 한국에 자주 반복 방문하지 않을 수 있다. 따라서 일반적인 리텐션 지표만 보면 약하다.

이 서비스는 매번 새로운 여행객을 데려와야 하는 구조가 될 수 있고, 유저 획득 비용이 커질 수 있다. 특히 외국인을 대상으로 홍보하는 것은 국내 사용자보다 어렵다.

따라서 리텐션보다 "여행 전환 시점에서 선택받는 서비스"로 봐야 하고, 유입 채널을 별도로 설계해야 한다.
- 외국인 유학생/교환학생 베타테스트
- K-content 팬덤 커뮤니티
- 오픈카톡/디스코드/레딧/인스타/틱톡 콘텐츠
- 여행 인플루언서 제휴
- 숙소/게스트하우스/관광 안내소/학교 국제처
- 지자체/관광공사/B2B 제휴

## 5. AI가 억지로 보일 위험이 있다
지도에 핀을 찍고 여행 코스를 추천하는 것만으로는 AI 프로젝트로 보이지 않을 수 있다.

"LLM에게 여행 일정 짜줘" 수준이면 ChatGPT에 물어보는 것과 차이가 약하다. 심사위원 입장에서는 "이게 왜 너희 서비스여야 하지?"라고 물을 수 있다.

AI 요소는 다음처럼 더 명확해야 한다.
- 비정형 웹/블로그/영상/자막 데이터를 촬영지 DB로 구조화
- 이미지/장면/자연어를 같은 벡터 공간에서 검색하는 멀티모달 검색
- 위경도, 이동시간, 영업시간, 사용자 제약을 도구로 검증하는 루트 플래너
- 추천 근거와 출처를 보여주는 RAG
- 허위 정보/중복 정보/저작권 위험 정보를 검수하는 내부 AI 도구
- Agent별 평가 지표 관리

## 6. 개인화 추천은 콜드스타트 문제가 있다
사용자가 많고 아이템 풀이 많아야 추천이 어려워지고 의미가 생긴다. 초기 서비스는 사용자 데이터도 적고 장소 데이터도 적기 때문에 "개인화 추천"을 강하게 말하면 약해 보일 수 있다.

개인화는 처음부터 고도 추천 시스템처럼 말하기보다 다음 단계로 설명하는 것이 낫다.
- 초기: 간단한 온보딩 설문, 선호 작품/장르/여행 스타일 선택
- 중기: 클릭, 저장, 방문, 검색 로그 기반 선호도 업데이트
- 후기: 장기 메모리와 유사 사용자 패턴 기반 추천

## 7. 수익화가 불명확하면 약하다
앱 유료 결제만으로는 설득력이 약하다. 배너 광고로 AI API 비용을 감당할 수 있을지도 의문이다.

BM은 다음처럼 현실적인 조합으로 잡는 것이 낫다.
- 촬영지 주변 식당/카페/체험 업체 제휴 수수료
- 프리미엄 여행 일정 생성
- 여행사/지자체/B2B 큐레이션 데이터 제공
- K-content 테마 패키지 공동구매
- 팬덤/크리에이터 코스 제작
- 쿠폰/예약/티켓팅 연동

# 구현 / 디벨롭 방향
## 1. 표현을 바꿔야 한다: "자동화"보다 "맥락 기반 생성/추론"
기획서에서 "자동화"라는 표현은 약하다. RPA나 반복업무 자동화처럼 보일 수 있다.

대신 다음 표현을 쓰는 것이 좋다.
- 콘텐츠 장면과 실제 장소를 연결하는 멀티모달 검색
- 비정형 촬영지 정보를 구조화하는 AI 데이터 파이프라인
- 사용자의 취향과 제약을 반영한 맥락 기반 여행 코스 생성
- 지도/교통/영업시간/위경도 도구를 활용하는 Agentic Route Planner
- K-콘텐츠 소비를 실제 관광 경험으로 전환하는 AI 큐레이션

## 2. 지도는 "일반 지도"가 아니라 "비주얼 콘텐츠 맵"으로 정의
기존 지도와 다르다는 점을 강조해야 한다.

추천 워딩은 다음과 같다.
- K-콘텐츠 비주얼 맵
- Scene-to-Place Map
- 콘텐츠 장면 기반 여행 지도
- 장면-장소 연결형 성지순례 맵

노드 하나에는 최소한 다음 정보가 들어가야 한다.
- 작품명 / 장면명 / 등장 회차 또는 영상 구간
- 장소명 / 주소 / 위경도 / 가장 가까운 역
- 장면 설명 / 방문 포인트 / 촬영 구도 팁
- 공식 영상 링크 또는 공식 출처 링크
- 주변 맛집/카페/체험/화장실/교통 정보
- 방문 가능 시간 / 혼잡도 / 추천 시간대
- 저작권 안전 상태 / 출처 / 검수 상태

## 3. MVP 범위는 좁혀야 한다
전국의 모든 드라마/영화/뮤비 촬영지를 하겠다고 하면 데이터 수집과 검수에서 무너질 수 있다.

권장 MVP 범위는 둘 중 하나다.
1. 부산 특화 MVP
	- 부산 배경 K-콘텐츠, 영화제, 바다/야경/맛집/축제/로컬 스팟을 묶는다.
	- 팀의 지역성, 부산센터, 외국인 관광객, 로컬 제휴를 설명하기 쉽다.
	- "부산 자유여행 필수 K-culture 맵"으로 포지셔닝 가능하다.
1. 서울/부산 대표 콘텐츠 MVP
	- 대표 작품 5~10개, 촬영지 50~100개 정도만 먼저 한다.
	- 유명 작품과 실제 방문 가능한 장소 중심으로 데모를 만든다.
	- "확장 가능하지만, 6개월 MVP는 검증된 인기 콘텐츠 중심"이라고 설명한다.

개인적으로는 **부산 특화 + 일부 서울 대표작 비교** 가 가장 설득력 있다. 부산으로 좁히면 구현 범위가 줄고, 팀의 차별성이 생기며, 로컬 제휴/B2B 이야기도 만들기 쉽다.

## 4. 데이터 파이프라인을 서비스의 핵심 기술로 잡아야 한다
단순히 DB를 만든다고 쓰면 약하다. "비정형 K-콘텐츠/관광 데이터를 구조화하는 파이프라인"으로 설명해야 한다.

권장 파이프라인은 다음과 같다.
1. 원천 데이터 수집
	- 공식 관광 데이터, 지자체 자료, 공식 영상/예고편, 기사, 블로그, 커뮤니티, 유튜브 설명/자막, 지도 리뷰 등
2. 1차 정제
	- 광고/중복/무관 문장 제거
	- 작품명, 장소명, 지역명, 장면 설명 후보 추출
3. 구조화
	- 장소명, 주소, 위경도, 작품명, 장면, 출처, 방문 가능성, 주변 정보 컬럼화
	- 원문은 별도 저장하고, 서비스에 노출되는 정보는 요약/가공본으로 관리
4. 교차 검증
	- 여러 출처에서 같은 장소가 언급되는지 확인
	- 지도 API로 장소명과 좌표 검증
	- 신뢰도 점수 부여
5. 운영자 검수
	- 초기에는 상위 인기 작품/상위 장소만 수동 검수
	- 관리자 페이지에서 승인/보류/수정 가능하게 설계
6. 인덱싱
	- 텍스트 검색용 인덱스
	- 이미지/장면/텍스트 검색용 벡터 인덱스
	- 위경도 기반 공간 검색 인덱스

이 파이프라인이 있어야 "우리는 그냥 핀 찍는 앱이 아니다"라고 말할 수 있다.

## 5. 멀티모달 검색은 강하게 잡아볼 만하다
가장 AI 프로젝트답게 보일 수 있는 부분은 멀티모달 검색이다.

가능한 기능은 다음과 같다.
- 사용자가 "도깨비 바닷가 장면"처럼 자연어로 검색하면 관련 촬영지를 찾는다.
- 사용자가 장면 이미지를 올리면 유사 장면/장소 후보를 찾는다.
- 특정 장소를 클릭하면 그 장소가 등장한 작품/장면을 역으로 보여준다.
- 영상/자막/설명/이미지를 일정 단위로 임베딩해 장면과 장소를 연결한다.

기술적으로는 다음 키워드를 기획서에 넣을 수 있다.
- CLIP 계열 이미지-텍스트 임베딩
- Video/Text/Image embedding
- Scene captioning
- Vector Search
- RAG
- LangGraph 또는 LangChain 기반 Agent
- Geo API / Route API tool calling

단, 처음부터 전체 영상을 다 처리하겠다고 하면 과하다. 대표 작품 몇 개만 처리해도 데모로 충분하다.

## 6. 루트 추천은 LLM 단독이 아니라 도구 기반으로 만들어야 한다
"LLM아 여행 코스 짜줘"는 차별화가 약하다.

루트 추천은 다음 데이터를 도구로 넣어야 설득력이 생긴다.
- 촬영지 노드의 위경도
- 대중교통/도보/택시 이동시간
- 영업시간
- 사용자의 출발지/숙소/여행 기간
- 사용자의 선호 콘텐츠/장르/배우/아이돌
- 주변 식당/카페/체험 정보
- 비건/할랄/매운 음식 회피 등 제약
- 날씨/혼잡도/추천 시간대

Agent는 이 데이터를 이용해서 후보 코스를 만들고, 이동시간이 말이 되는지 검증하고, 대안 코스를 2~3개 제시하는 역할로 잡는 것이 좋다.

## 7. AI Agent는 3개로 나누는 것이 적당하다
박재범 멘토님 쪽 피드백과도 맞물려, 처음부터 너무 많은 Agent를 만들기보다 3개 정도로 정의하는 게 좋다.
1. 촬영지 후보 탐색 Agent
	- 작품명/장면/이미지/자연어 입력에서 후보 장소를 찾는다.
	- 출처, 신뢰도, 중복 여부를 검증한다.
2. 루트 설계 Agent
	- 후보 장소를 노드로 보고 이동시간, 선호도, 주변 추천을 반영해 코스를 만든다.
	- 1안/2안/3안 식으로 선택지를 제공한다.
3. 콘텐츠 생성 Agent
	- 방문 장소, 찍은 사진, 사용자의 여행 기록을 바탕으로 SNS 캡션, 블로그 후기, 릴스/쇼츠 스크립트를 생성한다.
	- 자동 업로드는 플랫폼 정책 이슈가 있으므로 "업로드용 콘텐츠 생성 및 예약/연동 지원"으로 표현하는 것이 안전하다.

## 8. 평가 지표를 반드시 넣어야 한다
AI를 쓴다고만 하면 약하다. Agent별 평가 지표를 넣으면 완성도가 올라간다.

예시 지표는 다음과 같다.
- 촬영지 탐색 Agent: 장소 정확도, 누락률, 출처 신뢰도, 중복 제거율
- 루트 설계 Agent: 이동시간 오차, 방문 가능 장소 비율, 사용자 만족도, 대안 코스 품질
- 콘텐츠 생성 Agent: 사용자 수정률, 공유율, 생성 시간, 금칙어/저작권 위험 감지율
- 전체 시스템: 응답시간, 토큰 비용, API 실패율, 검수 통과율

## 9. 개인화는 "초기 설문 + 행동 로그 + 메모리"로 설명
개인화 추천은 데이터가 쌓여야 가능하므로 초기에는 온보딩 설문으로 시작한다.

권장 방식은 다음과 같다.
- 좋아하는 콘텐츠: 드라마 / 영화 / K-pop / 예능 / 배우 / 아이돌
- 여행 스타일: 빡센 일정 / 여유 일정 / 사진 위주 / 맛집 위주 / 쇼핑 위주
- 이동 방식: 대중교통 / 택시 / 도보 선호
- 음식 제약: 할랄 / 비건 / 매운 음식 회피 / 카페 선호
- 예산: 무료 위주 / 가성비 / 프리미엄

이후 사용자의 검색, 저장, 방문 완료, 사진 업로드, 코스 수정 로그를 쌓아 장기 메모리로 발전시키는 구조가 좋다.

## 10. 저작권 회피형 미디어 배치 전략이 필요하다
사용자가 원하는 것은 "이미지나 영상이 같이 있는 지도"지만, 직접 캡처 이미지를 서비스 DB에 저장하면 위험할 수 있다.

현실적인 전략은 다음과 같다.
- 공식 유튜브 영상은 임베드 또는 링크 중심
- 공식 예고편/뮤직비디오 썸네일은 플랫폼 정책 확인 후 사용
- 저작권 있는 장면 대신 장면 설명과 촬영 구도 가이드 제공
- 사용자가 현장에서 찍은 사진은 사용자 소유 콘텐츠로 활용
- "이 위치에서 이런 구도로 찍으면 유사한 느낌"처럼 재현 가이드 제공
- 내부 DB에는 원본 장면 파일보다 출처 URL, 타임스탬프, 설명, 임베딩만 저장
- 법률 멘토에게 캡처/썸네일/임베드/링크/사용자 업로드 범위 확인

## 11. 유저 확보는 커뮤니티부터 시작해야 한다
외국인 대상으로 바로 앱을 런칭하면 유입이 어렵다. 먼저 유저가 모일 수 있는 커뮤니티를 만들어야 한다는 피드백이 있었다.

권장 실행은 다음과 같다.
- "K-drama filming locations in Busan/Korea" 오픈채팅/디스코드/인스타 계정 운영
- 외국인 유학생/교환학생 대상으로 베타테스트
- 부산 외국인 커뮤니티, 게스트하우스, 국제처, 관광 안내소 접점 확보
- 팬덤 커뮤니티에 직접 홍보하기보다 자체 커뮤니티를 먼저 키움
- 인스타/틱톡 숏폼으로 "이 장면 실제 장소는 여기" 콘텐츠 제작
- 초기 DB 구축도 커뮤니티 제보/후기 기반으로 보강

## 12. BM은 오프라인 제휴가 오히려 방어력이 될 수 있다
기술만으로는 카피가 빠르다. 반면 로컬 식당, 카페, 체험 업체, 관광사, 지자체와의 제휴는 쉽게 복제되지 않는다.

권장 BM은 다음과 같다.
- 촬영지 주변 카페/식당 쿠폰 수수료
- 체험 상품/티켓/투어 예약 수수료
- 여행사 대상 촬영지 큐레이션 데이터 판매
- 지자체/관광공사 대상 테마 코스 제작
- 팬덤별 프리미엄 코스
- 브랜드/콘텐츠사와의 프로모션 코스

단, 처음부터 돈을 벌겠다고 하기보다 MVP에서는 "어떤 제휴가 가능한지 검증"하는 수준이 현실적이다.

# 추천 MVP 설계
## MVP 이름
가칭: **SceneKorea**
부제: **K-콘텐츠 장면을 여행 동선으로 바꾸는 AI 비주얼 맵**

## MVP 타겟
1차 타겟은 다음 중 하나로 좁히는 것이 좋다.
- 부산을 방문하는 외국인 K-content 팬
- 서울/부산을 방문하는 외국인 자유여행객
- 한국에 있는 외국인 유학생/교환학생

## MVP 기능
1. 비주얼 콘텐츠 맵
	- 지도 위에 촬영지 노드 표시
	- 각 노드에 작품/장면/장소/출처/방문 정보 표시
2. 장면/작품 기반 검색
	- 작품명, 배우, 아이돌, 장면 설명, 자연어 검색
	- 가능하면 이미지 검색 PoC 추가
3. 루트 추천
	- 사용자가 저장한 노드를 기반으로 반나절/하루 코스 생성
	- 이동시간, 주변 맛집/카페, 추천 시간대 포함
4. 현장 가이드
	- 방문 포인트, 사진 구도, 공식 영상 링크, 주변 정보 제공
5. 여행 후 콘텐츠 생성
	- 방문한 장소와 사진을 바탕으로 SNS 캡션/블로그 초안 생성

## MVP 데이터 범위
처음부터 많이 하지 말고 다음처럼 제한한다.
- 도시: 부산 중심 또는 서울/부산
- 콘텐츠: 대표 작품 5~10개
- 노드: 50~100개
- 수동 검수: 상위 노드 필수
- 자동 수집: 블로그/공식 자료/관광 데이터 기반 후보 생성

## MVP에서 보여줘야 하는 데모
기획심의나 발표에서 가장 좋은 데모 흐름은 다음이다.
1. 사용자가 "부산에서 K-drama 촬영지를 하루 동안 돌고 싶다"고 입력한다.
2. 서비스가 장면 기반 촬영지 노드를 지도에 보여준다.
3. 한 노드를 클릭하면 작품/장면/공식 링크/방문 정보/사진 구도 가이드가 나온다.
4. 사용자가 3~4개 노드를 선택한다.
5. Agent가 이동시간과 주변 맛집/카페를 고려해 1안/2안 코스를 만든다.
6. 사용자가 여행 후 사진을 올리면 SNS 캡션과 블로그 후기를 생성한다.

# 기획서에 바로 반영할 문장
## 문제 정의 문장
K-콘텐츠를 보고 한국을 방문하는 외국인은 늘고 있지만, 실제 촬영지 정보는 블로그, SNS, 팬 커뮤니티, 지도 리뷰 등에 흩어져 있어 작품의 장면을 실제 방문 가능한 장소와 여행 동선으로 연결하기 어렵다.

## 차별화 문장
본 서비스는 일반 관광지 지도나 팬 제작 핀맵과 달리, K-콘텐츠의 장면·이미지·텍스트 정보를 실제 장소 데이터와 결합한 비주얼 맵을 제공하고, 사용자의 취향과 이동 제약을 반영해 촬영지 노드를 여행 코스로 재구성한다.

## AI 활용 문장
멀티모달 임베딩과 RAG를 활용해 작품명, 장면 설명, 이미지 입력을 촬영지 후보와 연결하고, 위경도·이동시간·영업시간·사용자 선호도를 도구로 호출하는 Agentic Route Planner를 통해 실현 가능한 여행 코스를 생성한다.

## 저작권 대응 문장
저작권 리스크를 줄이기 위해 원본 영상·이미지의 직접 저장과 재배포를 지양하고, 공식 링크·임베드·출처 기반 장면 설명·사용자 생성 사진·촬영 구도 가이드를 중심으로 콘텐츠를 구성한다.

## BM 문장
초기에는 외국인 관광객의 정보 탐색 비용을 줄이는 무료 서비스로 진입하고, 이후 촬영지 주변 로컬 상권 쿠폰, 체험/티켓 예약 수수료, 지자체·여행사 대상 K-콘텐츠 코스 큐레이션으로 수익화를 확장한다.

# 앞으로 바로 해야 할 일
1. MVP 범위를 결정한다.
	- 부산 특화로 갈지, 서울/부산 대표 콘텐츠로 갈지 먼저 정해야 한다.
2. 데이터 샘플을 실제로 만든다.
	- 대표 작품 3개, 촬영지 20개 정도를 직접 수집해 ERD와 지도 화면에 넣어본다.
3. 저작권 사용 범위를 확인한다.
	- 공식 영상 임베드, 썸네일, 장면 캡처, 사용자 업로드, 출처 링크 각각 어디까지 가능한지 확인한다.
4. 외국인 유저 인터뷰를 한다.
	- 실제로 외국인이 한국 여행 전 어떤 앱/검색어/커뮤니티를 쓰는지 확인해야 한다.
5. 데모 화면을 먼저 만든다.
	- "지도 위 노드 + 장면 정보 + 루트 추천"이 한눈에 보여야 아이디어가 살아난다.
