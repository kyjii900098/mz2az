## 3. 결정된 것 (Decisions)

### 3-1. 기술 스택

> [!check] **확정**
> - **프론트: Flutter (Dart)** — iOS/Android 양쪽 대응
> - **지도: 네이버 지도 SDK** (Flutter 포팅 패키지)
> - **환경: Docker + Docker Compose**, 프로젝트 전체 단위로 컨테이너화
> - **이미지 저장: 경로는 링크 방식으로 통일** — 최종적으로 Amazon S3, 프론트는 링크로 받아 표시

- Docker를 쓰는 이유: 팀 전원 환경 통일 + 나중에 쿠버네티스로 갈 거면 도커로 시작하는 게 좋음 (47:02)
- 이미지를 링크 방식으로 가는 이유: 결국 S3에 저장할 것이므로 **지금부터 링크 흐름으로 맞춰두면 나중에 흐름이 바뀌지 않음** (50:48)
  - 포스터·씬 이미지·사용자 리뷰 이미지 모두 동일하게 링크로 처리
  - **로컬 개발 단계에서도 링크 방식으로 간다.** S3 전환 시 흐름을 바꾸지 않기 위함
- **Kafka는 쓰지 않는다** — 대용량 실시간 스트림이 필요한 서비스가 아님 (47:42)

### 3-2. 데이터 전략

> [!check] **확정** — 이번 MVP1 데이터는 지금 있는 것을 필터링해서 쓴다
> 추가 수집으로 시간을 더 쓰지 않는다.
> 원문: *"데이터만 모았는데 우리 시간을 너무 낭비하고 있으니까 … 일단 MVP1용으로는 이 데이터를 써 보죠"* (11:24)

- 데이터 수집 자체는 **계속 병행** 하되, 개발을 막지 않는다 (김태환이 별도 방식으로 진행)
- **씬 디스크립션은 그대로 넣지 않는다** — 명사로 끝나는 원문을 **설명하는 문장형** 으로 다듬어서 넣는다.
  - 예: "국밥을 먹는 장면이 촬영된 곳" → 문장형으로 (12:24~12:50)
  - AI로 처리하는 방안 검토 (13:01)
- **TMDB는 현재 개인 계정으로 가입해 사용 중.** 상업적 사용 단계는 아직 아니라고 판단 (10:02)
