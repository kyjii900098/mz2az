# SceneTrip 심사 예상 질문 답변집

창업 기획서 발표 대비용 Q&A

기준 문서: 2026 년도 AI·SW 마에스트로 제 17 기 프로젝트 기획서(SceneTrip)

활용법: 각 문항의 "발표용 답변"을 먼저 말하고, 추가 질문이 들어오면 "보충 설명"을 이어서 말하면 됩니다. 수치가 부족한 부분은 과장하지 말고, 대체 지표와 MVP 검증 계획으로 방어하는 방향이 안전합니다.

### 전체 방어 방향 요약

- SOM 100 만 명은 초기 목표가 아니라 장기 확장 목표로 설명한다.
- 저작권은 "원본 저장·재배포 없음, 공식 영상 임베딩/링크 중심, 삭제 요청 대응"으로 방어한다.
- AI 는 장소를 임의 생성하지 않고, 검증된 DB 와 출처 문서를 검색·조합하는 역할로 제한한다.
- 수익모델은 초기 구독보다 무료 기반 사용자 확보 → 광고/제휴 → B2B/데이터 리포트로 단계화한다.
- 크롤링은 핵심 수단이 아니라 공식 자료, 공개 API, 사용자 제보, 운영자 검수의 보조 수단으로 둔다.
- 성지순례 목적/불편 경험에 대한 직접 통계 부족은 인정하고, MVP 설문으로 검증하겠다고 답한다.

### 1. SOM 이 SAM 의 약 30%, 즉 100 만 명인데 이는 어떻게 계산되었나? 통상적인 SAM 대비 SOM 비율을 알고 있는가?

**발표용 답변**
SOM 100 만 명은 SAM 331 만 명에 30%를 적용한 장기 목표치입니다. 다만 SAM 대비 SOM 의 통상적인 고정 비율이 있는 것은 아니므로, 발표에서는 이를 초기 목표가 아니라 장기 확장 목표로 설명하고 MVP 단계에서는 더 작은 실사용 지표로 검증하겠습니다.

**보충 설명**
- 계산식은 331 만 명 × 30% = 99.3 만 명으로, 반올림해 약 100 만 명입니다.
- SOM 은 시장의 일정 비율을 기계적으로 적용하는 값이 아니라, 초기 진입 가능성, 마케팅 채널, 경쟁 강도, 지역 범위, 팀의 운영 역량을 기준으로 산정해야 합니다.
- 따라서 100 만 명은 "초기 확보 목표"가 아니라 "전국·다국어 확장 이후의 장기 목표"로 수정해 설명하는 것이 안전합니다.
- MVP 단계에서는 서울·부산·경주 등 제한된 지역에서 누적 사용자 수, MAU, 여행 일정 생성 수, 방문 인증 수 같은 실사용 지표를 먼저 검증하겠습니다.

### 2. K-콘텐츠의 특정 장면을 담은 유튜브 영상을 어떻게 탐색 가능한가?

**발표용 답변**
SceneTrip 은 영상 원본을 저장하거나 재배포하지 않고, 공식 채널에서 공개한 유튜브 영상이 있을 때만 임베딩 또는 링크 방식으로 연결합니다. 영상 탐색은 작품명·장면 키워드·장소명·회차 정보 기반 검색, 공식 채널 여부 확인, 임베딩 가능 여부 확인, 운영자 검수 순서로 진행합니다.

**보충 설명**
- 첫째, 작품명, 배우명, 장면 설명, 촬영지명, 회차 정보 등을 조합해 공식 유튜브 클립을 검색합니다.
- 둘째, 검색된 영상이 방송사·제작사·공식 유통 채널인지 확인하고, YouTube Data API 의 영상 메타데이터와 임베딩 가능 여부를 확인합니다.
- 셋째, 운영자 검수 또는 사용자 제보를 통해 "해당 영상의 특정 시점이 특정 촬영지와 연결된다"는 정보를 DB 에 저장합니다.
- 공식 영상이 없거나 임베딩이 차단된 경우에는 영상 임베딩을 제공하지 않고, 텍스트 장면 설명과 공식 출처 링크만 제공합니다.
- 핵심은 SceneTrip 이 영상을 제공하는 서비스가 아니라, 공식 영상·장면 설명·실제 장소를 연결하는 서비스라는 점입니다.

### 3. RAG 는 어디에 어떻게 사용되는가?

**발표용 답변**
RAG 는 LLM 이 임의로 장소를 만들어내지 않도록, 검증된 촬영지 DB 와 출처 문서를 먼저 검색한 뒤 그 결과를 기반으로 답변·추천하게 하는 장치입니다. 촬영지 검색, 장면-장소 매칭, AI 일정 추천, 추천 이유 설명에 사용됩니다.

**보충 설명**
- 사용자가 "눈물의 여왕 촬영지 중 오늘 갈 수 있는 곳 추천해줘"라고 입력하면, RAG 가 작품명, 촬영지 DB, 운영시간, 위치, 신뢰도 점수, 이동거리 정보를 먼저 검색합니다.
- 사용자가 "이 장면 어디야?"처럼 장면 설명을 입력하면, 장면 설명과 유사한 촬영지 데이터를 검색해 후보 장소를 제시합니다.
- 여행 일정 생성 시에는 사용자의 선호 콘텐츠, 현재 위치, 남은 시간, 방문 가능 여부를 검색 결과와 결합해 일정 후보를 만듭니다.
- 즉 LLM 은 장소를 생성하는 역할이 아니라, 검증된 데이터 안에서 검색·요약·조합·설명하는 역할을 수행합니다.

### 4. 해외에서는 무료, 방한 시 유료 제공이 현실적인가? 해외에서 여행계획을 다 짜고 방한하면 되는 것 아닌가?

**발표용 답변**
방한 시 모든 기능을 유료화하는 방식은 현실성이 낮다고 판단합니다. 핵심 검색과 기본 일정 생성은 무료로 유지하고, 수익화는 현장형 고급 기능과 광고·제휴·B2B 모델 중심으로 가져가겠습니다.

**보충 설명**
- 해외에서 여행계획을 세울 수는 있지만, 실제 여행 중에는 날씨, 운영시간 변경, 이동 지연, 임시 휴무, 현재 위치, 체력, 주변 맛집·카페 탐색 등 계획 당시 알기 어려운 변수가 발생합니다.
- SceneTrip 의 차별화 포인트는 여행 전 계획 수립보다, 여행 중 현재 상황을 반영한 대체 코스와 주변 장소 추천입니다.
- 초기 BM 은 구독보다 광고·제휴형이 더 현실적입니다. 예를 들어 촬영지 주변 맛집, 카페, 굿즈샵, 로컬 투어 업체와의 제휴 추천을 통해 수익을 만들 수 있습니다.
- 장기적으로는 지자체 테마 지도 제작, 여행사 대상 콘텐츠 코스 제공, 지역별 인기 촬영지 데이터 리포트 등 B2B 모델로 확장하겠습니다.
- 단기 구독은 핵심 BM 이 아니라 오프라인 저장, 다국어 고급 가이드, 실시간 재추천 같은 부가 기능에 대해 실험적으로 검증할 모델로 두겠습니다.

### 5. 웹 크롤링이 정상적으로 이루어질 것이라 기대할 수 있는가?

**발표용 답변**
웹 크롤링이 항상 안정적으로 가능하다고 전제하지 않습니다. 크롤링은 보조 수단으로만 사용하고, 공식 관광 자료, 지자체 자료, 공공데이터, 공식 유튜브 채널, 언론 기사, 사용자 제보, 운영자 검수를 중심으로 데이터 구축을 진행하겠습니다.

**보충 설명**
- 크롤링은 차단 가능성, 서비스 약관, 저작권, 데이터 품질 문제가 있기 때문에 핵심 데이터 확보 방식으로 두기 어렵습니다.
- 허용된 공개 페이지에 한해서만 robots.txt 와 약관을 준수하고, 과도한 요청이나 우회 수집은 하지 않습니다.
- 초기 데이터는 공식 자료와 공공 API 를 우선 사용하고, 부족한 부분은 사용자 제보와 운영자 검수로 보완합니다.
- 따라서 SceneTrip 의 데이터 전략은 "크롤링 의존형"이 아니라 "공식 자료 + 공개 API + 사용자 제보 + 수동 검수"를 결합하는 방식입니다.

### 6. SceneTrip 의 AI 여행코스 추천과 기존 지도서비스의 경로추천은 무엇이 다른가?

**발표용 답변**
기존 지도서비스는 사용자가 이미 목적지를 정했을 때 A 에서 B 까지 가는 최적 경로를 알려줍니다. SceneTrip 은 사용자가 어디를 가야 할지 정하는 단계부터 콘텐츠 맥락, 선호 작품, 현재 위치, 남은 시간, 운영시간, 신뢰도 점수를 고려해 목적지 후보와 여행 일정을 구성합니다.

**보충 설명**
- 예를 들어 사용자가 "오늘 오후 홍대 근처에서 드라마 촬영지 위주로 3 시간 코스를 짜줘"라고 입력하면, SceneTrip 은 관심 작품, 현재 위치, 남은 시간, 촬영지 신뢰도, 운영시간, 주변 관광지, 이동 효율을 함께 고려합니다.
- 그 후 실제 길찾기와 이동 시간 계산은 지도 API 를 활용합니다.
- 즉 기존 지도 서비스가 "정해진 목적지 간 이동 최적화"라면, SceneTrip 은 "콘텐츠 맥락 기반 목적지 선택 + 일정 구성 + 지도 경로 연결"을 제공합니다.
- 지도 서비스와 경쟁하기보다 지도 API 위에서 K-콘텐츠 특화 여행 의사결정을 돕는 서비스라고 설명하는 것이 적절합니다.

### 7. 데이터 구축 파이프라인에서 성지의 신뢰도를 측정하는 '신뢰도 점수'는 어떻게 매겨지는가?

**발표용 답변**
신뢰도 점수는 AI 가 감으로 판단하는 값이 아니라, 출처 신뢰도, 복수 출처 일치 여부, 위치 정확도, 최신 업데이트 시점, 사용자 방문 인증, 운영자 검수 여부 등을 기준으로 산정합니다.

**보충 설명**
- 공식 방송사·제작사·지자체·관광공사 자료는 높은 점수를 부여합니다.
- 언론 기사나 공식 관광 안내 자료는 중간 이상의 점수를 부여합니다.
- 블로그, SNS, 팬 커뮤니티 정보는 단독으로는 낮은 점수를 부여하고, 여러 출처에서 동일 장소가 반복 확인될 때 점수를 높입니다.
- 사용자 제보는 GPS 인증, 방문 인증 사진, 운영자 검수 여부에 따라 추가 점수를 부여합니다.
- 일정 점수 이상만 추천에 사용하고, 점수가 낮은 장소는 "검증 필요" 또는 "참고 정보"로 분리합니다.

**보충 설명**
- 지도/위치: Kakao Map API 또는 Naver Maps API - 국내 주소 검색, 좌표 변환, 주변 POI 탐색, 길찾기 연동에 사용합니다.
- 글로벌 접근성: Google Maps 또는 Google Places API - 외국어 장소명, 글로벌 사용자 친숙도, 해외 사용자의 지도 접근성을 보완합니다.
- 영상 확인: YouTube Data API - 공식 영상 검색, 채널·영상 메타데이터 확인, 임베딩 가능 여부 확인에 사용합니다.
- 영상 표시: YouTube IFrame API - 공식 영상이 임베딩 가능한 경우 앱/웹에서 플레이어를 표시하는 데 사용합니다.
- 관광 정보: 한국관광공사 TourAPI, 공공데이터포털, 지자체 관광 API - 운영시간, 관광지 설명, 주소, 주변 관광지 정보를 보완합니다.
- AI 기능: 데이터 정제·분류에는 경량 로컬 모델을 우선 검토하고, 고도화된 다국어 응답이나 일정 생성에는 상용 LLM API 를 제한적으로 사용합니다.

### 9. 사용자를 모으기 위해 처음에는 서비스를 무료로 제공한다고 했을 때, 어느 정도 인원이 모일 때까지 무료로 제공할 것인가?

**발표용 답변**
가입자 수만으로 유료화 시점을 정하지 않고, 실제 사용 지표를 기준으로 판단하겠습니다. MVP 출시 후 최소 3 개월은 핵심 기능을 무료로 제공하고, 누적 가입자 1 만 명, MAU 3 천 명, 여행 일정 생성 1 천 건, 방문 인증 300 건 정도를 1 차 검증 기준으로 삼겠습니다.

**보충 설명**
- 이 지표가 충족되더라도 바로 전체 유료화하지 않고, 광고·제휴·추천 영역부터 수익화를 실험하겠습니다.
- 검색, 지도 확인, 기본 일정 생성은 계속 무료로 유지해 사용자의 진입 장벽을 낮추겠습니다.
- 현장형 고급 기능, 제휴 추천, 프리미엄 코스, B2B 데이터 제공 등에서 수익화를 시도하는 것이 더 현실적입니다.
- 따라서 무료 제공의 종료 기준은 단순 다운로드 수가 아니라, 실제 여행 계획과 방문 행동이 충분히 발생했는지입니다.

### 10. SceneTrip 으로 짠 여행 전 계획과 여행 중 실시간 추천 경로가 충돌된다면?

**발표용 답변**
여행 전 계획은 기본 일정으로 유지하고, 여행 중 추천은 대체안 또는 수정 제안으로 제공합니다. AI 가 일정을 자동으로 바꾸지 않고, 사용자가 선택했을 때만 일정이 변경되도록 하겠습니다.

**보충 설명**
- 예를 들어 원래 A 촬영지를 방문하기로 했지만 현장에서 운영시간이 끝났거나 이동 시간이 예상보다 길어진 경우, SceneTrip 은 "기존 일정 유지"와 "근처 대체 코스 추천"을 함께 보여줍니다.
- 사용자가 선택해야만 기존 일정이 변경되므로, AI 가 사용자의 계획을 일방적으로 덮어쓰지 않습니다.

### 11. 어떤 지도 API 서비스 기반으로 서비스를 구축할 것인가?

**발표용 답변**
MVP 단계에서는 국내 장소 데이터와 경로 정확도가 중요하므로 Kakao Map API 또는 Naver Maps API 를 우선 후보로 두겠습니다. 다만 외국인 사용자가 Google Maps 에 익숙하다는 점을 고려해 Google Maps/Places API 를 보조 연동하거나 링크아웃 방식으로 보완하겠습니다.

**보충 설명**
- 국내 지도 API 는 국내 주소, 장소명, 좌표 변환, 주변 POI 탐색, 길찾기 측면에서 장점이 있습니다.
- Google Maps 는 외국어 장소명 검색과 글로벌 사용자 친숙도 측면에서 장점이 있습니다.
- 최종 선택 기준은 국내 POI 정확도, 외국어 검색 지원, Flutter 연동 가능성, API 비용, 경로·대중교통 지원 범위입니다.
- 현실적인 MVP 구현안은 Kakao/Naver 기반 지도와 Google Maps 링크아웃 또는 보조 검색을 함께 사용하는 방식입니다.

### 12. 성지순례를 위해 방한하는 외국인에 대한 구체적인 수치가 있는가?

**발표용 답변**
정확히 "성지순례만을 목적으로 방한한 외국인"을 별도로 집계한 공식 통계는 확인하기 어렵습니다. 따라서 기획서에서는 한류 콘텐츠가 방한 계기가 된 집단, 한류 관광지 방문 고려 집단을 대체 지표로 사용했습니다.

**보충 설명**
- 기획서의 SAM 331 만 명은 2024 년 방한 외국인 관광객 1,637 만 명에 "방한 계기 - 한류 콘텐츠" 비율 약 20.2%를 적용한 값입니다.
- 보다 보수적으로는 "방한 시 고려 활동 - 한류 관광지 방문" 비율 8.0%를 적용해 한류 관광지 방문 의향층을 추정할 수도 있습니다.
- 따라서 발표에서는 "성지순례 목적만을 분리한 공식 수치는 부족하지만, 한류 콘텐츠 기반 방한 계기와 한류 관광지 방문 고려 비율을 대체 지표로 사용했다"고 설명하겠습니다.
- 이 부분은 향후 MVP 검증 단계에서 직접 설문으로 보완하겠습니다.

### 13. 성지순례를 하면서 불편함을 겪는 외국인에 대한 구체적인 수치가 있는가?

**발표용 답변**
정확히 "성지순례 중 불편함을 겪은 외국인"만을 분리한 공식 수치는 부족합니다. 하지만 한국여행을 진행하면서 어려움을 겪는 외국인에 대한 수치는 존재하며, 이 지표는 많은 외국인들이 방한했을 때 많은 어려움을 겪는다는 사실을 보여줍니다.

**보충 설명**
- 현재 기획서에서는 촬영지 정보가 블로그, 유튜브, SNS, 팬 커뮤니티 등에 흩어져 있고, 외국인 관광객이 여행 준비 시 교통 정보 부족을 느낀다는 자료를 근거로 문제를 정의했습니다.
- 다만 "성지순례 불편 경험" 자체를 직접 측정한 공식 수치는 부족하므로, 이 부분은 심사에서 약점이 될 수 있습니다.
- 방어 논리는 "현재는 대체 지표를 사용했고, MVP 이후 방한 외국인 대상 설문으로 촬영지 검색 난이도, 이동 동선 설계 어려움, SceneTrip 사용 의향을 직접 측정하겠다"입니다.
- 발표에서는 과장하기보다 "직접 통계는 부족하지만, 그래서 초기 MVP 의 핵심 목표를 시장 검증과 사용자 설문으로 두었다"고 말하는 편이 안전합니다.

### 발표 중 사용하기 좋은 방어 문장

**수치가 부족하다는 지적을 받을 때**
"해당 수치는 현재 공식 통계에서 직접 분리되어 있지 않기 때문에, 한류 기반 방한 계기와 한류 관광지 방문 고려 비율을 대체 지표로 사용했습니다. 이후 MVP 단계에서 직접 설문으로 보완하겠습니다."

**기능 범위가 크다는 지적을 받을 때**
"전체 기능은 확장 방향이고, MVP 는 촬영지 검색, 지도 기반 정보 제공, AI 코스 추천, 루트 저장·공유로 제한하겠습니다."

**AI 환각 우려를 받을 때**
"AI 가 장소를 만들어내는 것이 아니라, 검증된 촬영지 DB 와 출처 문서를 검색한 뒤 그 범위 안에서 추천하도록 제한하겠습니다."

**저작권 질문을 받을 때**
"영상 원본을 저장하거나 재배포하지 않고, 공식 채널의 공개 임베딩 또는 링크만 연결합니다. 임베딩이 제한된 경우 텍스트 설명과 공식 출처 링크만 제공합니다."

**수익성 질문을 받을 때**
"초기에는 무료로 사용자 행동을 검증하고, 수익화는 구독보다 촬영지 주변 로컬 상권 제휴, 광고, 지자체·여행사 대상 테마 코스 제공으로 단계화하겠습니다."
