#### 레퍼럴이 실제로 어떻게 작동하나

용어 혼선을 막기 위해 한 장면으로 적는다.

프랑스 거주 사용자가 SceneTrip에서 `Queen of Tears` 를 검색 → **더현대 서울**(극중 퀸즈 백화점) 상세 화면 진입. 그 화면 맨 아래에 줄 하나가 붙는다.

```
┌────────────────────────────────────────┐
│  이 촬영지가 포함된 투어                │
│  눈물의 여왕 1일 투어 · Trazy          │
│  ₩89,000 · 왕복 교통 + 영어 가이드     │
│                            [보러 가기] │
└────────────────────────────────────────┘
```

누르면 **Trazy 예약 페이지가 브라우저로 열린다.** SceneTrip 안에서 결제하지 않으므로 자체 결제 모듈이 필요 없다. 링크 주소에 SceneTrip 식별 코드가 붙어 있어 Trazy가 유입 출처를 안다. 30일 안에 예약이 일어나면 **Trazy가 SceneTrip에 약 4%(₩3,500)를 지급** 한다. 사용자 부담은 없다 — 파트너가 원래 마케팅비로 쓰는 예산에서 나간다.

| 용어 | 실제 의미 |
|---|---|
| 상품 | 외국인이 돈 주고 사는 실물. 위 예시의 ₩89,000 Trazy 투어. 그 외 교통패스·입장권·액티비티 |
| 맥락 | 그 줄이 붙는 **화면과 거기 떠 있는 내용** |
| 노출 / 클릭 / 전환 | 줄이 떴다 / 눌렀다 / 실제 예약까지 갔다 |
| 파트너 | 상품을 파는 회사 (Trazy, Klook) |

#### 화면 ↔ 상품 대응표

상품을 하나로 정하지 않는다. **화면마다 자연스러운 것이 다르므로 대응표를 미리 정해두고 그대로 붙인다.** 즉흥으로 붙이면 광고판이 된다.

| 화면 맥락 | 붙일 상품 | 파트너 |
|---|---|---|
| 특정 작품 촬영지 상세 | 그 작품 투어 | **Trazy** |
| 서울 외 촬영지 (부산·강원·수원) | 지역 데이투어 · 교통패스 | Klook |
| 촬영지 여러 개를 담은 코스 화면 | 전일 가이드 투어 | Klook · Trazy |
| 촬영지 근처 카페·식당 | **없음** (네이버 지도 링크만) | — |
| 계획 시작 단계 | 입장권 · 패스 | Klook |

지킬 규칙 셋:

1. **한 화면에 한 줄만.** 여러 개 쌓으면 광고판이 된다
2. **맞는 상품이 없으면 안 띄운다.** 빈 슬롯이 억지 매칭보다 낫다
3. **파트너는 둘까지.** Klook 하나로 투어·패스·입장권·액티비티가 커버되고, Trazy는 작품 단위 투어 때문에 추가한다. 어필리에이트는 회사마다 가입·승인·링크 형식·대시보드가 따로라 늘릴수록 3명에게 부담이다

이 방식은 기획서의 원래 원칙과 일치한다 — *"광고성 무차별 노출이 아니라 해당 작품·동선과 연관된 상품만 큐레이션하여 신뢰도 유지"*.

> [!warning] eSIM 우선 권고는 철회
> 초판은 "첫 상품은 eSIM(수수료 20%, 구매율 거의 전원)"을 최대 발견으로 제시했으나 철회한다.
> - **"구매율 거의 전원"은 설문에 문항이 없는 추정** 이었다. 투어 쪽 22%는 실측치인데 한쪽만 가정을 썼고, 투어에는 전환율 2%를 곱하면서 eSIM에는 아무것도 곱하지 않았다
> - **귀속이 어렵다.** eSIM은 대개 항공권 예약 직후 Klook·Airalo에서 직접, 혹은 공항에서 산다. 30일 쿠키 안에 SceneTrip을 거칠 이유가 없다
> - **이 기획의 방어논리를 무효화한다.** "어디에 어떤 순서로 가는지 안다"는 우위가 eSIM에는 아무 값도 갖지 못한다. 눈물의 여왕 촬영지를 보는 사용자에게 유심칩을 들이미는 것은 여행 블로그도 똑같이 할 수 있다
>
> eSIM을 영영 배제하는 것은 아니다. 위 대응표에 "여행 준비 체크리스트" 같은 화면이 생기면 그때 붙인다. **우선순위가 낮을 뿐이다.**

> [!note] 측정에 대한 초판 수정
> 초판은 "측정을 위해 상품을 하나로 집중하라"고 했으나, 이 논리는 약하다.
> - **클릭 → 예약 전환율** 은 상품을 하나로 몰아도 이 트래픽 규모에서 유의미한 숫자가 나오지 않는다
> - **노출 → 클릭률** 은 훨씬 적은 표본으로 측정 가능하며, **화면 종류별로 배우려면 오히려 여러 상품을 걸어야 한다**
>
> 따라서 대응표 방식이 배움의 양에서 더 낫다. 중간발표에 들고 갈 숫자는 **화면 종류별 클릭률** 로 잡는다.

### 8. 이 단계 목표는 매출이 아니라 전환율

수수료 6.5%, 투어 객단가 $60, 전환 2% 가정 → **사용자 1,000명당 약 $78.** 3개월 안에 의미 있는 매출은 나지 않는다.

> 패스·단품 가격과 **구매 전환율(%) 목표를 숫자로** 제시하고 조기 실측할 것 — 정문창 멘토, 피봇팅 의견서 보완 1번

측정 자체는 어필리에이트 링크만으로 가능하다. 다만 기획서 부록 A는 **"MVP1에서는 상품 노출 영역만 UI에 확보, 실제 제휴 링크 연동은 MVP2"** 로 정해 두었으므로, 이를 MVP1으로 당기려면 **범위 변경으로 명시 기록** 해야 한다.

## 데이터 읽을 때 주의

- CSV는 **27컬럼, 분기 문항 5쌍이 중복 헤더**로 존재한다. `csv.DictReader` 로 읽으면 **중복 키가 합쳐져 한쪽 분기가 통째로 사라진다.** `csv.reader` 로 인덱스를 직접 다룰 것
- 복수응답 구분자는 **`;`** 다 (`,` 아님)
- 문항별 응답 수가 다르다 (n=15 / 20 / 44 / 55 / 56 / 64 / 69). **비율 인용 시 분모를 반드시 함께 밝힐 것**
- **n=15 집단의 모든 비율은 6.67%의 배수** 다. 46.7% = 7명, 26.7% = 4명. 이 규모에서 46.7%와 26.7%는 통계적으로 구분되지 않는다. 발표에는 "15명 중 7명"으로 쓰는 편이 정직하다
- 표본은 **자기선택된 온라인 팬 집단**(surveyswap 대행 + Reddit)이다. n=69에서 60.9%의 95% 신뢰구간은 대략 ±12pp, n=15에서 46.7%는 ±25pp. **소수점 표기가 데이터에 없는 정밀도를 암시한다**
- 응답자 구성: 여성 72%(41/57), 18–24세 24/57, 거주지 유럽 23·북미 14·동남아 14. **동아시아는 3명** — 다국어 계획의 일본어 근거는 이 데이터에 없다
