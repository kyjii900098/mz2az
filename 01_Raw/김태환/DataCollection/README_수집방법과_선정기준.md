## 2. 성지 데이터 수집 방법

### 2.1 대상 확정

kdramamap 드라마 목록은 **25편 × 20페이지 = 476편** 이다.
페이지를 훑는 대신 사이트의 WordPress REST API(`/wp-json/wp/v2/kdm_drama`)로 476편을 한 번에 열거했다.

### 2.2 추출

각 드라마 상세 페이지(476건)를 받아 두 곳에서 뽑았다.

| 항목 | 출처 |
|---|---|
| 장소명 · 주소 · 시도 · 시군구 | `<article class="kdm-location-item">` 마크업 |
| **위도 · 경도** | 페이지에 박혀 있는 `kdm-location-cluster-config` JSON |
| 장면 사진 URL | `data-scene-url` 속성 |
| 네이버지도 링크 | 장소 카드의 링크 |
| 출연진 · 방송사 · 방영기간 · 상태 | 상단 정보 영역 |

### 2.3 누락 검증

- 사이트가 표시한 **"촬영지 N곳"** 값과 파싱 행 수를 476편 전부 대조 → **전건 일치**
- 총 20,080건은 사이트의 `kdm_location` 전체 건수와 **정확히 동일** → 누락 없음

### 2.4 채움률

| 컬럼 | 채움 | 비고 |
|---|---:|---|
| `place_name` · `place_address` · `source_url` | 100% | |
| `place_naver_url` | 100% | 651건은 주소로 링크 생성 |
| `place_latitude/longitude` | 97% (19,473) | 소수점 6자리 |
| `place_image_url` | 14% (2,857) | kdramamap 장면 스틸 |

## 3. `place_type` — 규칙 기반 추정 (검수 필요)

kdramamap은 장소 유형을 제공하지 않는다. **장소명 키워드 규칙** 으로 추정했다.

- 역 / 카페 / 음식점 / 공원 / 다리 / 궁궐 / 해변 / 항구 / 산 등 약 30종
- 애매하면 `기타` (전체의 약 51%)
- 예: `~역` → 역, `~대교`·`~교` → 다리, `~궁` → 궁궐, `~시장`(단 `전시장` 제외) → 시장

> [!question] 확인 필요
> **출처에 근거한 값이 아니라 이름에서 추론한 값** 이다. `기타` 51%이고 나머지도 오분류가 섞여 있다.
> 서비스에 노출하기 전 검수하거나, 타입 기반 필터 기능을 MVP1에서 빼는 편이 안전하다.

## 4. 작품 메타데이터 보강 — 위키데이터 대조

kdramamap 제목은 **띄어쓰기가 없다**(`눈물의여왕`, `선재업고튀어`). 476편 중 463편이 그렇다.
정식 제목·영문 제목을 얻기 위해 위키데이터와 대조했다.

### 4.1 방법

1. 위키데이터 SPARQL로 **한국 영상물 14,842건**(제작국=한국 OR 원어=한국어)의 한/영/일/중 라벨과 별칭을 일괄 수신
2. 문장부호·공백을 제거해 정규화 후 **로컬 대조** (검색 API는 붙여쓴 한국어를 못 찾음)
3. 동명이작은 kdramamap이 아는 **방영연도** 로 판별
4. 그래도 안 갈리면 kdramamap **출연진** 과 위키데이터 출연진(P161)을 대조

### 4.2 결과

| 단계 | 편수 |
|---|---:|
| 제목 정확일치 | 375 |
| 시즌표기 보정 후 일치 | 12 |
| 출연진·연도 대조로 확정 | 44 |
| **매칭 성공** | **431 / 476 (91%)** |
| 미매칭 | 45 |

미매칭 45편은 대부분 웹드라마·2026년 신작으로 **위키 문서 자체가 없다**
(`고물상미란이`, `오버랩나이프나이프`, `화자의스칼렛` 등). 외국인 인지도가 낮다는 방증이기도 하다.

### 4.3 `title_aliases`

정식 한국어 제목 · 영문 · 일문 · 중문 · 위키 별칭을 `;` 로 이어 채웠다 (431편).
예: `눈물의여왕` → `눈물의 여왕;Queen of Tears;涙の女王`

## 5. 외국인 인기도 점수 — 100점 만점

### 5.1 설계 원칙

우리 서비스는 **외국인 대상 촬영지 여행 앱** 이다. 따라서 점수는 두 가지를 동시에 봐야 한다.

1. **외국인이 그 작품을 아는가** — 한국 내 시청률·화제성은 무의미하다
2. **우리가 그 작품으로 실제 서비스를 만들 수 있는가** — 아무리 유명해도 촬영지가 2곳이면 코스가 안 나온다

### 5.2 구성

| 항목 | 배점 | 지표 | 산식 |
|---|---:|---|---|
| **A. 글로벌 인지도** | 40 | 위키백과 언어판 수 | `min(언어판/40, 1) × 40` |
| **B. 영어권 관심도** | 40 | 영문 위키백과 12개월 조회수 | 로그 스케일, 1만회=0점 · 200만회=40점 |
| **C. 성지 데이터 충실도** | 20 | 촬영지 수 15 + 좌표 확보율 5 | `min(촬영지/40,1)×15 + 좌표율×5` |

### 5.3 각 지표를 고른 이유

**A. 왜 언어판 수인가**
문서가 N개 언어로 존재한다는 것은 N개 언어권에서 "이걸 설명할 필요가 있다"고 판단했다는 뜻이다.
특정 국가에 치우치지 않는 **국제적 인지도의 대리지표** 다. 조회수와 달리 유행을 타지 않아
`도깨비`(54개 언어), `사랑의불시착`(57), `태양의후예`(52) 같은 **스테디셀러를 놓치지 않는다.**
만점 기준을 40개로 잡은 이유 — 상위권(오징어게임 104, 사랑의불시착 57)은 이미 메가히트라
그 이상의 차이는 성지 여행 수요를 가르지 못한다.

**B. 왜 영문 위키 조회수인가**
7/28 회의에서 **MVP1 외국어는 영어만** 으로 확정됐다. 영어권 관심이 가장 직접적인 대리지표다.
조회수는 "찾아본 사람 수"라 실제 수요에 가깝다.
**로그 스케일을 쓴 이유** — 조회수는 멱함수 분포라 선형으로 쓰면 1~2위가 40점을 독식하고
나머지가 전부 0점대로 눌린다.

**C. 왜 촬영지 수를 넣었나**
`지금우리학교는`은 42개 언어에 60만 조회수지만 kdramamap 기준 **촬영지가 6곳** 뿐이다.
반면 `눈물의여왕`은 145곳이다. 인기만 보면 전자가 위지만, **우리 앱에서 코스를 만들 수 있는 건 후자** 다.
좌표 확보율을 5점 넣은 것은 좌표 없는 장소는 지도에 핀을 못 찍기 때문이다.

### 5.4 넣지 않은 지표와 이유

| 후보 | 제외 이유 |
|---|---|
| 글로벌 OTT(넷플릭스 등) 방영 여부 | kdramamap의 `방송사` 필드가 국내 최초 방영사만 기록한다. tvN 드라마도 해외에선 넷플릭스로 나가므로 신뢰할 수 없는 신호 |
| 시청률 | 국내 지표. 외국인 인기와 무관 |
| 방영 최신성 | B(조회수)에 이미 반영된다. 별도 가점하면 신작 편중이 심해짐 |

## 6. `scene_description` 수집 — 결과와 한계

### 6.1 결론부터

**5,740곳 중 원문에 근거한 장면 설명을 확보한 것은 60곳(1.0%), 16개 작품뿐이다.**

| 출처 | 건수 |
|---|---:|
| 나무위키 | 53 |
| 영문 위키백과 | 7 |
| **미확보** | **5,680** |

작품별로는 `눈물의여왕` 22건, `이사랑통역되나요` 7건, `뉴토피아` 6건 순이다.
한 작품에 몰려 있는 이유는 §6.2 참조.

> [!note] 정밀도를 위해 재현율을 포기했다
> 초기 매칭은 97건이었으나 검수해 보니 시청률 표, 위키 템플릿 잔해, 제작진 명단이
> 장면 설명으로 잘못 들어와 있었다. 일반명사(`스튜디오`, `백화점` 등) 단독 매칭과
> 행정구역 나열 문장을 배제해 **60건으로 줄이는 대신 오탐을 없앴다.**
> 틀린 설명이 섞이는 것보다 적더라도 맞는 것만 있는 편이 낫다고 판단했다.

### 6.2 시도한 소스와 판정

| 소스 | 판정 |
|---|---|
| **kdramamap 자체** | ❌ 장면 **사진** 만 있고 텍스트 설명이 없다. 장소 상세 페이지도 동일 |
| **나무위키** | 🔶 작품별 `촬영지` 문단이 있으면 회차·장면까지 정확히 나온다. 그런데 **그 문단이 있는 작품이 소수** 다 |
| **한국어/영문 위키백과** | 🔶 촬영지를 문서에 적는 경우가 드물다 |
| **대한민국구석구석(한국관광공사)** | ❌ 여행기사에 좋은 서술이 있으나 **검색이 JS 렌더링** 이라 서버 응답에 결과가 없다. 장소명으로 역인덱싱이 불가 |
| **서울관광재단 visitseoul** | ❌ 동일하게 JS 렌더링, 검색 결과 0건 |
| **TourAPI(한국관광공사)** | ⏸️ 인증키 필요. 미발급이라 시도 못 함 — **가장 유망한 미시도 소스** |

### 6.3 확보한 것의 형태

원문 문장을 **그대로** 옮기고 출처 URL을 `scene_source_url` 에 남겼다. 문장은 가공하지 않았다.

```
눈물의여왕 / 회나무식당
  → "8회에서 백현우와 홍해인이 국밥을 먹었던 장소는 이태원의 회나무식당이다."
     출처: 나무위키

눈물의여왕 / 광통교
  → "10회 에필로그에 등장했던 다리는 청계천 광통교이다."
     출처: 나무위키
```

회차 정보가 문장에 포함돼 있어 7/28 결정(**"에피소드/화 정보는 description 한 열로 대체"**)에 그대로 맞는다.

### 6.2 왜 이렇게 적은가 — 매처 문제가 아니다

매칭 로직을 의심해 상위 작품들을 직접 대조해 봤다. **원문이 언급하는 장소 자체가 적다.**

| 작품 | kdramamap 촬영지 | 나무위키 본문에 이름이 나오는 장소 |
|---|---:|---:|
| 눈물의여왕 | 145곳 | 22곳 |
| 킹더랜드 | 79곳 | 5곳 |
| 일타스캔들 | 90곳 | 2곳 |
| 열혈사제2 | 127곳 | 1곳 |
| 더글로리 · 오징어게임 · 태양의후예 | 108 · 21 · 15곳 | 0곳 |

나무위키 98편 중 "촬영"이 5회 이상 언급된 작품은 40편이지만, 그 서술은 대부분
**제작 비화이지 특정 장소 이야기가 아니다.** kdramamap이 20,080곳을 가지고 있다는 것은
위키류가 아닌 다른 경로로 모았다는 뜻인데, 그 원본에 장면 설명이 없다.

### 6.4 미확보분의 처리 — 판단 근거

미확보 5,680행은 **비워두지 않고**, 우리가 실제로 확인한 사실만 적었다.

```
장면 사진 있음 → "촬영지로 확인됨 — kdramamap에 촬영 장면 사진 3장 등록. 텍스트 장면 설명 미확보."
장면 사진 없음 → "촬영지로 확인됨 — 구체적인 장면 정보 미확인."
```

`scene_source` 컬럼이 `미확보` 이므로 **필터 한 번으로 갈라낼 수 있다.**

> [!important] LLM으로 장면 설명을 생성하지 않았다 — 의도적 판단
> 5,680건을 그럴듯한 문장으로 채우는 것은 기술적으로 가능하다. 하지만
> ① 볼트 운영 규칙(`CLAUDE.md`)이 **01_Raw에 없는 내용을 지어내는 것을 금지** 하고,
> ② 검증 불가능한 데이터 5,643건이 팀 데이터셋에 섞이면 **나중에 어느 것이 사실인지 분간할 수 없어진다.**
> 정권호님도 KDramaMap 일괄 수집분 5,816행에 고정 문구를 넣고 큐레이션분 363행과 구분해 두셨다. 같은 원칙을 따랐다.

## 8. 남은 일

   `detailCommon2` 의 `overview` 에 촬영지 소개문이 있는지 확인할 것.
   (승길님 아키텍처 문서 §9의 검증 항목과 같은 키를 쓴다)

   촬영지 수가 많고 인지도가 높은 작품부터 장면 설명을 직접 붙이는 것이 현실적이다.
3. **`place_type` 검수**
4. **3인 CSV 통합** — 제목 표기 통일(한국어 vs 영어), ID 재부여, 중복 제거 규칙 확정
