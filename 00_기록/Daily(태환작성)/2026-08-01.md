## 개요

  

이번 회의는 드라마·영화 촬영지 기반 여행 앱의 개발 전략을 구체화하는 데 집중했다. 팀은 MVP 단계에서 즐겨찾기·평점 같은 부가 기능을 뒤로 미루고 핵심 기능에 집중하기로 합의했다. 데이터 수집 현황(영화 114편, 드라마 50편, 약 4,900개 촬영지)을 검토하며 일부 출처의 편향성과 누락 문제를 확인했고, 인간 검증을 통한 품질 관리 계획을 세웠다.

  

멘토는 POC 단계에서는 작품 수를 대폭 줄이고 잘 알려진 작품에 집중할 것을 제안했다. 약국·경찰서처럼 일반적인 장소보다 독창성과 인지도가 높은 촬영지를 우선하고, 여러 작품에 중복 등장하는 장소를 상위에 노출하는 정렬 방식을 검토했다.

  

UI/UX 논의에서는 현재의 지도 기반 탐색이 기존 서비스와 차별화되지 않는다는 점이 지적되었다. AI 대화형 계획 기능으로 개인화된 일정을 생성하는 방향이 제안되었으며, 무엇보다 ****앱의 핵심 가치가 'AI 여행 플래너'인지 '지도 기반 위치 브라우저'인지를 명확히 정의****해 기능 과부하를 피해야 한다는 점이 강조되었다. 경로 안내는 기존 지도 앱이 더 잘 처리하는 영역이므로 외부 연동을 우선하기로 했다.

  

이 밖에 멀티미디어 콘텐츠의 저작권 리스크, 제3자 지도 데이터 캐싱의 법적 제약, 백엔드의 AWS 이전과 지리공간 DB 최적화, Jira 기반 작업 관리와 역할 분담·리더십 문제가 다루어졌다. 멘토는 현재 개발이 최종 사용자가 아닌 구현자 관점에 치우쳐 있다고 지적하며, 사용자 페르소나 정의와 설문을 통한 가설 검증으로 관점을 전환할 것을 요구했다.

## 1. MVP 기능 우선순위

  

- 즐겨찾기, 평점, 상세 사용자 리뷰는 ****MVP에서 제외**** — 핵심 기능 우선.

- 제외한 기능은 ****백로그에 등록****해 향후 검토 대상으로 남길 것.

- 초기 데이터 수집과 핵심 기능 구현이 사용자 상호작용 기능보다 우선순위가 높다는 데 팀 합의.

- 복잡한 내비게이션 기능 추가 전에 ****위치 정보 + 경로 추천****이라는 핵심에 집중.

  

## 2. 데이터 수집 현황 및 품질 보증

  

- 현재 수집 현황: ****영화 114편 · 드라마 50편 · 촬영지 약 4,900개****.

- 일부 데이터 출처가 ****편향되거나 불완전****해 중요 촬영지가 누락됨.

- AI 추출 데이터에 대해 ****인간 검증****을 수행해 정확성·완전성 개선.

- AI 추출 샘플을 ****수동 검토****해 결함을 찾고 프롬프트를 개선하는 반복 루프 필요.

- 수집된 DB에 대한 ****초기 품질 검사**** 수행 — 데이터가 제대로 수집되었는지 확인.

- 자막 기반 위치 추출 방식의 ****타당성 검증**** 필요.

- 양보다 질 — 데이터를 ****검증·필터링하는 파이프라인**** 구축이 핵심.

  

> [!note] 원문 불일치

> 전사본 내 데이터 파이프라인 관련 항목 중 "품질보다 양에 집중"이라는 표현과, 본문 전반의 "양보다 질" 기조가 상충한다. 회의 맥락상 후자가 멘토의 일관된 입장으로 보이나, 다음 회의에서 확인 필요.

  

## 3. POC 범위 축소 — 작품 및 촬영지 선별

  

- POC용 ****드라마 수를 10~20개 수준으로 축소****하고 잘 알려진 작품에 집중.

  - (전사본 상세요약에는 "10~40개"로 기재되어 있어 정확한 수치는 재확인 필요)

- ****독창적이고 의미 있는 촬영지 우선**** — 특정 약국·경찰서 같은 일반적 장소는 후순위.

- 촬영지를 ****독창성 + 인지도**** 기준으로 정렬·우선순위화.

- ****여러 작품에 중복 등장하는 장소****를 기준으로 정렬해 유명 촬영지를 부각.

- ****작품당 장면 수와 장르 분포****를 분석해 인기 작품이 충분한 위치 데이터를 갖췄는지 확인.

- 촬영지가 너무 많으면 사용자가 압도될 수 있다는 우려 제기.

- 방문 결정을 돕기 위해 ****"여러 작품에 등장한 유명 장소"라는 보충 정보****를 표시하는 방안 검토.

  

## 4. 앱 핵심 가치 정의

  

- ****핵심 질문: 이 앱은 'AI 여행 플래너'인가, '지도 기반 촬영지 브라우저'인가?****

- 이를 명확히 하지 않으면 기능 과부하와 혼란으로 이어짐 → ****주 기능을 결정할 것****.

- 현재의 지도 기반 탐색만으로는 포괄적 여행 계획 지원이라는 목표에 미달.

- 단순 위치 브라우징 앱과 차별화하려면 ****계획(planning) 기능을 전면에 내세운 마케팅**** 필요.

  

## 5. AI 대화형 여행 계획 인터페이스

  

- 사용자가 ****여행 날짜 · 선호 · 관심사를 입력****해 계획을 세우는 AI 대화형 인터페이스 구현 검토.

- 사용자가 여행 계획과 선호를 자유롭게 서술하는 ****간단한 텍스트 입력**** 방식 고려.

- ****자동 일정 생성 ↔ 사용자 맞춤 수정**** 간 균형 설계.

- 의미 있는 일정 생성을 위해 ****도착 날짜·숙소**** 등 여행 세부 정보를 입력받을 것.

- 마음에 드는 장소를 담아두는 ****'장바구니'/목록 기능****으로 경로 계획과 맞춤화를 지원.

- 사용자가 좋아하는 작품을 고르고 그에 따라 경로를 만드는 흐름을 ****사용자 여정****으로 정의 — 앱 발견 → 광고 노출 → 여행 계획까지.

- AI가 생성한 계획을 사용자가 수정하는 방법을 안내하는 ****튜토리얼/온보딩 가이드**** 개발.

- 세부 계획형부터 즉흥 탐험형까지 다양한 여행자 성향을 수용하도록 UX 단순화.

  

## 6. 지도 표시 및 경로 안내

  

- ****경로 안내는 낮은 우선순위**** — 정확한 길안내는 복잡하고 기존 지도 앱이 더 잘 처리함.

- 초기에는 ****Kakao·Naver Map 등 외부 지도 서비스로 연결****하는 방식 선호.

- 다만 외부 지도 API 연동의 ****타당성과 사용자 가치****는 별도로 조사할 것.

- 지리에 익숙하지 않은 사용자는 ****거리·이동 시간 판단이 어려움**** → 지도상 위치 데이터를 어떻게 표시할지 평가 필요.

- 사용자 선호와 제약에 따라 ****경로 포함/제외를 AI가 판단 지원****하는 방안 검토.

  

## 7. 운영 정보 및 멀티미디어 콘텐츠

  

- 여행지의 ****영업시간·운영 상태****를 최신으로 수집·유지 — 일정 정확도와 사용자 만족도 직결.

- 경로 생성 시 이 데이터를 ****검증하는 메커니즘**** 포함.

- 변경 가능성에 대한 ****면책 고지와 함께 캐싱****해 사용자 기대치와 법적 위험을 관리.

- 위치별 이미지가 없는 경우를 대비해 ****이미지·영상(예: YouTube 링크)**** 을 활용한 콘텐츠 보강 방안 조사.

  

## 8. 법적 · 데이터 사용 고려사항

  

- 제3자 출처 ****이미지·영상 사용 시 저작권 문제**** 우려.

- 대응책으로 ****AI를 통한 이미지 변형**** 또는 ****직접 촬영한 원본 사진**** 사용 검토.

- 자막 타임코드로 촬영 장면을 특정하는 방식은 ****정확성과 법적 문제**** 모두 존재.

- ****평점·영업시간 등 제3자 지도 데이터의 캐싱·저장****에 대한 법적·기술적 제약 조사 → PT 또는 법률 전문가 상담.

- 콘텐츠 표시의 ****법적 준수****를 데이터 파이프라인 단계에서 보장할 것.

  

## 9. 경쟁 환경 및 수익 모델

  

- 기존 앱 대부분은 ****맛집·일반 여행****에 집중 — 엔터테인먼트 콘텐츠 + 여행 계획 결합은 드묾.

- 직접적인 경쟁자가 없어 ****시장 선례 없이 기능을 설계****해야 하는 어려움 존재.

- ****K-드라마 맵을 넘어선 경쟁 앱 분석**** 필요 — 인터페이스 디자인과 기능을 참고해 UI/UX 결정에 활용.

- 기존 AI 기반 여행 계획 앱들을 조사·검토해 인사이트 확보.

- 동료 팀 프로젝트에는 ****커뮤니티 기능·여행 아이디어가 만연****하지만, 커뮤니티 기능은 직접 수익으로 이어지는 경우가 드묾.

- ****주 수익 모델 결정 필요****: 커뮤니티 기능 중심인가, 유료 사용자 서비스 중심인가 — 사용자 행동 기반으로 지속 가능성 평가.

  

## 10. 사용자 페르소나 및 시장 조사

  

- 기능이 많은 프로젝트일수록 ****잘 정의된 사용자 페르소나****가 필수.

- 앱 사용자 여정을 반영한 ****페르소나와 시나리오 설계****.

- ****사용자 설문****을 실시해 페르소나와 가설을 검증.

- 지적: ****현재 개발이 최종 사용자가 아닌 구현자 관점에 의해 주도되고 있음**** → 관점 전환 필요.

- 사용자 관점 이해가 서비스를 실제 고객 니즈에 맞추고 채택률을 높이는 열쇠.

  

## 11. 기술 인프라

  

- 백엔드는 현재 ****로컬 환경에서 개발 중****, 확장성을 위해 ****AWS 이전 계획****.

- 인프라 준비 지연을 막기 위해 ****백엔드 개발자와 협력해 개발 환경을 신속히 구축****.

- ****PostgreSQL / PostGIS 등 지리공간 DB 기능**** 학습 — 위치 기반 검색·추천 성능 향상.

- 검색/추천 시스템에 대한 연구로 데이터 처리 최적화.

- ****AI 기능 개발은 데이터·인프라 구축 이후****에 착수하며, 성능·비용 비교를 통해 모델을 선정.

- 빠른 프로토타입 제작과 인프라 구축 사이의 균형 필요.

  

## 12. 팀 운영 및 프로세스

  

- ****Jira에서 문서화와 작업 추적을 조직·유지**** — 완료/보류 작업의 가시성 확보.

- ****정기 스프린트 리뷰**** 운영.

- ****기획 업무와 비기획 업무 간 역할을 명확히 분리****해 책임 소재를 명확히 할 것.

- ****리더십을 확실히 세우고 명확한 방향을 제시****해 혼란을 줄이고 의사결정 속도를 높일 것.

- ****주말까지 앱의 핵심 기능 세트와 디자인을 최종 확정**** — 개발 착수 시기를 놓치지 않고 팀 동기를 유지하기 위함.

- ****일요일에 짧은 온라인 회의****를 잡아 다른 팀과 진행 상황·다음 단계를 조율.

- 다음 리뷰 세션에서 다른 멘토·이해관계자를 설득할 수 있도록 ****앱 화면의 정제된 보고서 또는 데모**** 준비.

## 결정 사항

  

- ****MVP 범위****: 즐겨찾기·평점·상세 리뷰 제외, 촬영지 데이터 + 핵심 계획 기능에 집중. 제외 기능은 백로그로.

- ****POC 범위 축소****: 드라마 10~20개 수준의 잘 알려진 작품으로 한정 (정확한 수치 재확인 필요).

- ****촬영지 선별 기준****: 독창성 + 인지도 우선, 일반적 장소(약국·경찰서 등) 후순위.

- ****경로 안내****: 자체 구현 대신 Kakao·Naver 등 ****외부 지도 서비스 연동을 우선****, 자체 내비게이션은 후순위.

- ****데이터 품질****: AI 추출 결과에 인간 검증을 필수 단계로 포함, 검증·필터링 파이프라인 구축.

- ****개발 순서****: 데이터·인프라 구축 → AI 기능 개발.

- ****핵심 기능 세트와 디자인은 주말까지 확정****.

- ****일요일 온라인 회의****로 타 팀과 진행 상황 조율.
